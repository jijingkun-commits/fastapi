# 子任务实现工作流 (Implementation per Workstream)

按单个 `WS-*.md` 执行编码，确保不越权、不跨边界。

> **中文主导**: 无论是思考过程（CoT）还是最终输出，**永远使用中文**。

## 何时使用

| 场景 | 推荐命令 |
|------|----------|
| 已有并行拆解，执行某个子任务 | `/imp-ws` ✅ |
| 没有 WS 文档，执行整体实现 | `/imp` |

---

## 1. 输入

必须输入：

1. 一个 `WS-*.md` 文档（单个子任务）
2. `docs/内部参考/任务拆解/<YYYY-MM-DD_主题>/parallel_plan.md`（只读参考）
3. `docs/内部参考/迭代需求/requirements.md`（真理来源）
4. `docs/内部参考/迭代需求/implementation_plan.md`
5. `docs/内部参考/迭代需求/implementation_plan_<主题>.md`（若当前 WS 明确引用专项附录）

## 2. 执行约束

1. 只允许修改 WS 白名单文件。
2. 禁止修改 WS 黑名单文件。
3. 禁止跨 WS 改动与“顺手修”。
4. 如发现必须跨 WS 才能完成：立即停止实现并回报“拆解不满足并行条件”。
5. 若 WS 同时引用主计划和专项附录：
   - 先满足主计划门禁与兼容约束
   - 再按附录推进专项 phase
6. Gate 层 WS 必须串行执行：`WS-G1 -> WS-G2`。
7. `WS-G2` 启动前提：`WS-G1` 已完成且门禁结论已回填。
8. 若 `WS-G1` 未通过且无批准豁免，不得执行 `WS-G2`。

### 2.1 Gate 层执行顺序（固定）

当任务拆解包含 Gate 层工作包时，执行顺序固定如下：

1. 先执行并完成 `WS-G1_集成回归门禁.md`
2. 再执行 `WS-G2_文档终稿门禁.md`

不允许并行执行两个 Gate WS，也不允许跳过 `WS-G1` 直接进入 `WS-G2`。

### 2.2 Gate 追溯矩阵要求（新增）

当执行 Gate 层 WS（尤其 `WS-G1`）时，必须在 WS 文档中维护“TC-ID 映射表”，至少包含以下列：

- `TC-ID`（来源：`docs/开发文档/测试管理/测试用例库.md` 或模块测试案例文档）
- `门禁命令/检查项`
- `自动化脚本或 pytest nodeid`
- `本次结果`（PASS / FAIL / BLOCKED）
- `责任 WS`
- `豁免/缺陷单`

执行要求：

1. 失败项必须映射到责任 WS，不允许只记录“失败 N 个”。
2. 暂无现成 TC-ID 时，先标记 `TC-TBD-*`，并在 `WS-G2` 前补齐。
3. Gate 复测必须更新同一映射表，确保前后轮可对比。

### 2.3 浏览器测试触发规则（新增）

默认不是每个 WS 都执行浏览器测试（Playwright / E2E），按变更影响面触发。

满足任一条件时，必须执行浏览器测试：

1. 改动 `web/src/**` 页面、组件、Hook 或用户交互流程。
2. 改动 SSE / 跨端契约并影响前端渲染、状态同步、交互闭环。
3. WS DoD 或需求文档明确要求 UI 行为验收。

可不执行浏览器测试（需同时满足）：

1. 仅后端/文档/脚本改动，且最小验证命令已覆盖风险。
2. 未改动前端消费链路。
3. 在“协作者自检卡”写明未执行原因。

推荐最小命令（按需选择）：

- `cd web && npx playwright test <spec>`
- `cd web && npm run test:visual -- --grep "<关键场景>"`

## 3. 契约执行（涉及 SSE / 跨端协议时）

1. 契约 owner WS 必须先输出冻结字段清单。
2. 消费方 WS 只能按冻结字段清单实现，不推断私有字段。
3. 若冻结清单与实现冲突，以主计划门禁约束为准并回报拆解维护者。

## 4. 必做产出

1. 代码改动（仅限白名单）
2. 最小测试结果（按 WS 文档定义执行）
3. 回填 WS 文档末尾“协作者自检卡”
4. （如适用）回填“冻结字段自检结果”
5. （Gate WS 必做）回填“TC-ID 映射表”并标注失败归属
6. （触发式）回填浏览器测试命令、结果与证据路径


### 4.1 Gate 自动回填（新增，WS-G1/WS-G2 必做）

执行 Gate WS 时，完成门禁命令后必须执行自动回填脚本，禁止手工改数字：

```bash
venv/bin/python scripts/backfill_gate_status.py   --plan docs/内部参考/任务拆解/<YYYY-MM-DD_主题>/parallel_plan.md
```

规则：
1. 脚本会自动执行 `pytest/tsc/lint/docs_guard` 并回写 `parallel_plan.md` 的 Gate 区块。
2. 若任一命令失败，脚本返回非零退出码，Gate 判定失败。
3. 若需只预览不落盘，使用 `--dry-run`。

## 5. 交接

提交时必须包含：

- 实际修改文件列表
- 测试命令与结果
- TC-ID 映射结果（Gate WS）
- 风险点与回滚建议

## 6. 常用执行示例（Gate 串行）

1. `/imp-ws @docs/内部参考/任务拆解/<YYYY-MM-DD_主题>/workstreams/WS-G1_集成回归门禁.md`
2. `/imp-ws @docs/内部参考/任务拆解/<YYYY-MM-DD_主题>/workstreams/WS-G2_文档终稿门禁.md`
