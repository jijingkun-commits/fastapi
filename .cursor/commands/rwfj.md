# 任务分解工作流 (RWFJ Workflow)

将 `/plan` 产出的需求与技术方案，进一步拆解为可并行执行且互不干涉的工作包。

> **中文主导**: 无论是思考过程（CoT）还是最终输出，**永远使用中文**。

## 0. 默认执行策略（无需额外提示词）

执行 `/rwfj` 时，默认强制启用以下策略（不需要额外补充提示词）：

1. **按互不冲突自动拆分**：基于文件/状态/依赖冲突关系自动生成并行工作包。
2. **G0 先冻结协议**：先完成协议冻结，再进入并行拆解。
3. **WS 动态数量**：按实际冲突图输出 `WS-01 ... WS-N`，不固定核心 WS 数量。
4. **冲突不可解则串行回退**：禁止硬拆并行，必须显式回退为串行执行路线。

## 何时使用

| 场景 | 推荐命令 |
|------|----------|
| 方案已明确，需要多人并行推进 | `/rwfj` ✅ |
| 需求尚不清晰，需要先规划 | `/plan` |
| 已有拆解，执行某个子任务 | `/imp-ws` |

## 1. 输入与前置

**优先输入**:
1. `docs/内部参考/迭代需求/requirements.md`
2. `docs/内部参考/迭代需求/implementation_plan.md`
3. `docs/内部参考/迭代需求/implementation_plan_<主题>.md`（如主计划已声明专项附录）

**前置条件**:
- 需求边界已清晰
- 架构层职责已初步确认（模块边界、状态契约、路由闭环）

### 1.0 G0 协议冻结（必须先执行）

> 目的：在并行前冻结跨端契约，避免 WS 并发开发时产生字段语义漂移。

执行要求：

1. **仅冻结契约，不做业务实现**。
2. 冻结范围至少覆盖：`done`、`result`、`interrupt`。
3. 每个事件必须给出：
   - required 字段
   - optional 字段
   - 兼容说明（向后兼容策略）
4. 必须在 `parallel_plan.md` 写入独立章节：`## 0. G0 协议冻结`。
5. 冻结完成后，消费方 WS 只能只读消费，不得自行扩展私有字段假设。

### 1.1 前置可并行判定清单（必须先过）

> 原则：并行任务必须天然互不影响；有冲突或强依赖时，不强行分解。

逐项判断（是/否）：

1. 子任务是否可在不等待其他子任务结果的情况下独立开始并独立交付？
2. 子任务是否可以做到文件白名单互斥（无共享文件并发写入）？
3. 子任务是否不存在共享状态字段语义冲突（单写入权清晰）？
4. 子任务是否可各自完成局部验证，不依赖全量集成结果？

判定规则：

- **全是**：进入自动拆分流程，生成 `WS-01 ... WS-N`。
- **有任一否**：不强行并行；在 `parallel_plan.md` 显式写“并行不通过，改串行路线”，并切换单任务执行（`/imp`）或先解耦后重试。

### 1.2 主从计划继承（新增）

若主计划声明了专项附录：

1. `parallel_plan.md` 必须显式写明“哪一个 WS 继承该附录”。
2. 对应 WS 文档必须写“主计划 + 专项附录”关联关系。
3. 若主计划与附录冲突，WS 文档必须写“以主计划门禁为准”。

## 2. 产出物（固定目录）

在 `docs/内部参考/任务拆解/<YYYY-MM-DD_主题>/` 下生成：

1. `parallel_plan.md`：并行总计划（必须包含以下章节）
   - `## 0. G0 协议冻结`
   - 并行判定四问结果
   - 自动拆分依据（冲突关系与分组结果）
   - 依赖图与里程碑
   - 串行回退说明（若触发）
2. `workstreams/WS-*.md`：工作包明细（动态数量，每包一文件）
   - 每个 WS 必须包含：可改文件白名单、禁止触碰区、状态字段单写入权、局部验收命令
   - Gate WS（至少 `WS-G1`）必须包含：TC-ID 映射表（门禁项 -> 自动化用例 -> 责任 WS）
   - 涉及前端交互或跨端契约消费的 WS，必须包含浏览器测试触发评估（是否触发、命令、结果或未触发原因）
3. `merge_checklist.md`（可选）：仅共享文件/共享字段冲突场景启用

### 2.1 看板导出规范（新增，供 `/vk` 消费）

为保证拆解结果可直接转看板，`/rwfj` 产出时必须附带以下“可机读导出信息”：

1. `parallel_plan.md` 中新增章节：`## 9. 看板导出索引`
   - 本轮拆解目录 ID（如：`2026-02-12_文档治理`）
   - WS 总数、Gate 总数
   - 默认看板列流转：`Backlog -> Doing -> Review -> Gate -> Done`
2. 每个 `workstreams/WS-*.md` 文末新增 `card_export` 区块（YAML）
   - 必填字段：
     - `id`（WS 编号）
     - `title`
     - `type`（`parallel` / `gate`）
     - `lane`（并行泳道标识）
     - `depends_on`
     - `file_whitelist`
     - `readonly_scope`
     - `owner_fields`
     - `check_cmd`
     - `dod`
3. 若出现并行冲突回退，`card_export` 必须显式加：
   - `parallel_fallback: true`
   - `fallback_reason`
   - `serial_order`

## 3. 拆解步骤

1. **执行 G0 协议冻结**：先冻结跨端契约，再做任务拆解。
2. **抽取任务单元**：从主计划中抽取可交付能力点，形成候选任务单元集。
3. **构建冲突关系**：对候选单元建立冲突图，至少包含：
   - 文件重叠冲突（白名单交叉）
   - 状态字段写入权冲突（语义单写入权冲突）
   - 强依赖阻断（必须等待他人交付才能开始）
4. **自动拆分工作包**：按冲突图聚类输出 `WS-01 ... WS-N`（动态数量）。
5. **声明互斥与 owner**：为每个 WS 明确白名单、禁区、共享资源 owner 与消费方。
6. **声明依赖图**：标注 `可并行` / `先后依赖` / `共享文件单所有者`。
7. **定义验收口**：每个 WS 必须绑定独立验收标准与最小验证命令。
8. **串行回退处理**：若存在不可消解冲突，必须停止并行拆分，在 `parallel_plan.md` 写明回退原因与串行执行路线。

### 并行拆解禁忌（必须遵守）

- 禁止把“集成回归、最终验收、终稿文档同步”伪装成并行 WS。
- 如必须依赖他人输出才能开始，说明当前任务不满足并行判定，必须回退为串行路线或先解耦再拆。
- 禁止在冲突未消解时强行生成并行 WS。

## 4. 互不干涉硬约束（必须显式写入）

1. **文件白名单互斥**：同一文件只能归属一个 WS（共享文件需指定唯一 owner）。
2. **状态字段单写入权**：关键字段只能由一个 WS 改写语义。
3. **接口契约先冻结**：输入/输出结构先定稿，再并行开发（通过 G0 落文）。
4. **路由收敛不退化**：任何 WS 不得引入“重复澄清”循环。
5. **合并顺序固定**：先并行交付层，再串行门禁层。

## 5. 协作模式（默认无总控）

- 默认采用 **无总控** 协作：按 WS 文档一对一分配给协作者执行。
- 每个协作者需在对应 `WS-*.md` 末尾填写“协作者自检卡”。
- `merge_checklist.md` 默认为可选，仅在共享资源冲突时启用。

## 6. 与其他命令关系

推荐链路：`/plan` → `/rwfj` → `/vk` → `/imp-ws` → `/review` → `/test`

- `/plan` 负责“真理来源”（需求/架构）
- `/rwfj` 负责“并行编排”（拆包/边界/依赖/合并）
- `/vk` 负责“看板化落地”（建卡 payload + 导入提示词）
- `/imp-ws` 负责“按单个 WS 实现”

## 7. 简化用法（默认即可）

直接执行：`/rwfj`

无需再补充“互不冲突自动拆分 + G0 冻结协议 + WS 动态数量 + 冲突回退串行”等提示词。

## 8. 30 秒人工验收清单（执行 `/rwfj` 后必看）

对照产出目录中的 `parallel_plan.md` 与 `workstreams/WS-*.md`，逐项检查：

1. `parallel_plan.md` 含独立章节：`## 0. G0 协议冻结`。
2. `done/result/interrupt` 三类事件均给出 `required/optional/兼容说明`。
3. 文档包含并行四问结论（通过或不通过）。
4. 文档包含自动拆分依据（文件冲突/状态冲突/依赖阻断）。
5. 工作包编号为 `WS-01 ... WS-N` 动态数量，而非固定 3 个核心 WS。
6. 每个 `WS-*.md` 都有：白名单、禁区、单写入权、局部验收命令。
7. Gate WS 含 TC-ID 映射表，失败项可追溯到责任 WS。
8. 涉及前端交互/跨端契约消费的 WS 含浏览器测试触发评估。
9. 若并行不通过，必须有“串行回退路线与原因”。
10. Gate 层（如 `WS-G1`、`WS-G2`）保持串行，不伪装成并行 WS。
11. 每个 `WS-*.md` 文末包含 `card_export`，且字段齐全。
12. `parallel_plan.md` 包含“看板导出索引”与本轮拆解目录 ID。
