# 任务澄清 (Clarify Task)

通过结构化问答快速澄清需求，确保理解一致后再行动。

> **中文主导**: 无论是思考过程（CoT）还是最终输出，**永远使用中文**。

## 何时使用

| 场景 | 推荐命令 |
|------|----------|
| 需求模糊，想快速确认理解 | `/clarify` ✅ |
| 需要产出正式需求文档 | `/plan` |
| 一站式完成从需求到交付 | `/feature` |

> **与 `/plan` 的区别**: `/clarify` 是轻量级问答，不产出文档；`/plan` 会产出 `requirements.md`。

---

## 执行步骤

### 1. 提出澄清问题

使用 2-4 个问题澄清：

- **目标**: 用户想要达成什么？
- **范围**: 涉及哪些模块/页面？
- **边界**: 异常情况如何处理？
- **优先级**: 哪些是必须的，哪些是可选的？

### 2. 复述确认

```markdown
## 我的理解

1. 目标: [xxx]
2. 范围: [xxx]
3. 边界条件: [xxx]

请确认是否正确，或补充说明。
```

### 3. 确认后再行动

用户确认后，询问：
- "需要我生成正式需求文档吗？" -> 转 `/plan`
- "现在可以开始实现吗？" -> 转 `/imp` 或 `/feature`

---
*使用 `/clarify` 触发。适合需求不明确时快速对齐。*
