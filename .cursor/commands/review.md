# 代码审查工作流 (Code Review)

对已完成的代码进行深度审查，确保功能正确、质量达标、安全可靠。

> **中文主导**: 无论是思考过程（CoT）还是最终输出，**永远使用中文**。

## 何时使用

| 场景 | 推荐命令 |
|------|----------|
| 代码写完，需要审查 | `/review` ✅ |
| 完整测试（用例生成、E2E、报告） | `/test` |
| 修复 Bug | `/debug` |

---

## 1. 理解变更 (Understand the Change)

- 阅读相关的 `requirements.md` 或 PR 描述
- 识别影响范围：哪些文件、哪些功能
- 记录需要向作者确认的问题

## 2. 功能验证 (Functionality)

**Checklist**:
- [ ] 代码是否实现了 `requirements.md` 中的需求？
- [ ] 边界情况是否处理得当？
- [ ] 错误处理是否恰当且信息明确？

## 3. 代码质量 (Code Quality)

**Checklist**:
- [ ] 代码结构清晰、易维护
- [ ] 无重复代码或死代码
- [ ] 函数职责单一，命名有描述性
- [ ] 符合项目规范 (中文注释, 类型提示, Pydantic v2)
- [ ] 测试/文档已更新

## 4. 安全审查 (Security & Safety)

**Checklist**:
- [ ] 无明显安全漏洞（SQL 注入、XSS 等）
- [ ] 输入已验证，输出已清理
- [ ] 敏感数据处理正确（无硬编码密钥）

## 5. 快速自测 (Smoke Test)

> **目的**: 快速验证代码能运行，不替代完整测试。

```bash
# 运行相关单元测试
python -m pytest tests/path/to/test.py -v

# 验证服务能启动
uvicorn app.main:app --reload
```

- 检查日志无 `ERROR`
- 如发现问题：简单问题直接修复，严重问题停止并报告

## 6. 文档同步 (Doc Sync)

> 代码变更必须同步更新相关文档。

- [ ] API 变更 -> `docs/API文档/接口文档.md`
- [ ] 数据库变更 -> `docs/开发文档/架构设计/数据库设计.md`
- [ ] 配置变更 -> `docs/开发文档/快速入门/配置说明.md`

### 测试脚本同步检查

如果本次变更涉及 `web/e2e/*.spec.cjs` 或 `web/e2e/features/*.feature.cjs`：

- [ ] 脚本开头有 `@test-case TC-XXX-xx` 注释
- [ ] 脚本开头有 `@see docs/开发文档/测试管理/<模块>测试案例.md`
- [ ] 测试案例文档第 0 节"自动化覆盖"列已更新
- [ ] 删除/重命名脚本时，文档中的旧引用已清理

### 测试报告命名与索引同步检查（新增）

如果本次变更新增或重命名了 `docs/开发文档/测试管理/测试报告/*.md`：

- [ ] 报告命名符合规范（主报告：`{模块名}测试报告.md`）
- [ ] 报告命名符合规范（归档：`{模块名}测试报告_YYYYMMDD_{主题}.md` 或 `YYYY-MM-DD` 版本）
- [ ] 未新增兼容旧命名（如 `测试报告_{场景}_{日期}.md` 或仅日期无主题后缀）
- [ ] `docs/SUMMARY.md` 已同步新报告入口
- [ ] `docs/开发文档/测试管理/测试用例库.md` “详细报告”链接已同步
- [ ] `docs/开发文档/测试管理/测试报告/README.md` 主报告/归档表已同步
