# 文档同步检查 (Doc Sync Check)

检查当前 git 变更是否有对应文档更新，并生成同步报告。

> **中文主导**: 无论是思考过程（CoT）还是最终输出，**永远使用中文**。

## 何时使用

| 场景 | 推荐命令 |
|------|----------|
| 提交前检查文档是否同步 | `/doc-check` ✅ |
| 代码审查时验证文档 | `/review` |
| 实现功能时自动同步 | `/imp` |

---

## 执行步骤

### 1. 获取变更文件列表

```bash
# 已暂存的变更
git diff --cached --name-only

# 或与上一次提交比较
git diff --name-only HEAD~1
```

### 2. 分类变更文件

将变更文件按以下类别分组：

| 文件路径匹配 | 类别 |
|-------------|------|
| `app/ai/workflow/` `app/ai/tools/` | AI 模块 |
| `app/api/` | API 接口 |
| `app/models/` | 数据库模型 |
| `web/src/components/` | 前端组件 |
| `.env*` | 环境配置 |
| `docs/` | 文档 |

### 3. 检查文档映射

根据 `.cursor/rules/doc_sync.mdc` 中的映射规则，检查：

| 代码变更 | 应更新文档 |
|---------|-----------|
| `app/ai/workflow/` | `docs/开发文档/架构设计/AI模块设计.md` |
| `app/ai/tools/` | `docs/开发文档/架构设计/AI模块设计.md` |
| `app/api/` | `docs/API文档/接口文档.md` |
| `app/models/` | `docs/开发文档/架构设计/数据库设计.md` |
| `web/src/components/` | `docs/开发文档/架构设计/前端架构.md` |
| 环境变量 | `docs/开发文档/快速入门/配置说明.md` |

功能逻辑变更还需检查：

| 模块 | 需求文档 | 测试文档 |
|------|---------|---------|
| 待办助手 | `docs/产品文档/待办助手需求.md` | `docs/开发文档/测试管理/待办助手测试案例.md` |
| 聊天系统 | `docs/产品文档/聊天系统需求.md` | `docs/开发文档/测试管理/聊天系统测试案例.md` |
| 管理后台 | `docs/产品文档/管理后台需求.md` | `docs/开发文档/测试管理/管理后台测试案例.md` |
| 问数助手 | `docs/产品文档/问数助手需求.md` | `docs/开发文档/测试管理/问数引擎测试案例.md` |

### 4. 生成同步报告

**输出格式**:

```markdown
## 文档同步检查报告

### 代码变更
- `app/api/v1/endpoints/chat_api.py`
- `app/models/chat.py`

### 已同步文档
- `docs/API文档/接口文档.md` ✅

### 疑似遗漏（需人工确认）
- `docs/开发文档/架构设计/数据库设计.md` ⚠️
  - 原因：检测到 `app/models/` 变更但未见文档更新

### 跳过条件检查
- [ ] 是否为纯格式化/重构？
- [ ] 是否为简单 Bug 修复？
- [ ] 用户是否说"直接改代码"？

如满足跳过条件，可忽略遗漏警告。
```

---

## 跳过条件

以下情况可跳过文档同步：

- 用户明确说"直接改代码"
- 纯格式化/重构（不改功能）
- 简单 Bug 修复（不涉及设计）

---

*使用 `/doc-check` 触发。建议在 `git commit` 前执行。*
