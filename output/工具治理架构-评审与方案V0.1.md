## 目的与预期成效

### 要解决的问题

当前项目的 AI 工具编排存在以下痛点：

1. **工具散落，新增成本高**：每新增一个工具都要改 `multi_agent_graph.py` 的 `_get_supervisor_tools()` / `_get_common_tools()`，700+ 行的核心文件频繁变动，回归风险大。
2. **无法按角色/场景控制工具可见性**：Supervisor 和各专家 Agent 共享同一套工具拼装逻辑，无法做到"问数 Agent 看不到待办工具"或"普通用户看不到管理工具"。
3. **工具调用无拦截点**：没有统一的 before/after 钩子，安全审计、参数校验、限流、灰度等横切关注点只能硬编码到每个工具内部，或者根本没做。
4. **前端无法精确追踪工具状态**：`tool_start/tool_end` 事件缺少 `tool_call_id`，多个并发工具调用时前端无法关联"哪个开始对应哪个结束"。
5. **随着 Skills/MCP 工具增多，管理复杂度指数上升**：目前 6 个工具文件还能手动管理，但 Skills 检索、MCP 外部工具接入后，没有 Registry 和 Policy 会失控。

### 预期成效

| 维度 | 改造前 | 改造后（核心层完成） |
|------|-------|-------------------|
| 新增工具 | 改 `multi_agent_graph.py`，触发全链路回归 | 在 Registry 注册一行，策略自动生效，不动核心图 |
| 工具可见性控制 | 无，所有 Agent 看到相同工具集 | 按 Agent/用户角色/场景 4 层策略过滤 |
| 安全拦截 | 无统一拦截点 | before_hook 可阻断危险调用，after_hook 可审计 |
| 工具管理复杂度 | O(N) 手动维护 | O(1) 声明式注册 + 策略配置 |
| 回滚安全性 | 改了就改了，没有开关 | 特性开关一键回退旧链路 |

简单说：**把"每次加工具都要改核心代码"变成"注册一行 + 配个策略"，同时获得安全拦截和可观测能力。**

## 第一部分：原方案评审

### 1. 认同的点

| # | 原方案观点 | 评审意见 |
|---|-----------|---------|
| 1 | "最应该借鉴的不是具体工具实现，而是工具治理架构" | **完全认同**。当前项目的工具散落在 `_get_supervisor_tools()`、`_get_common_tools()` 等函数中，每新增一个工具都要改 `multi_agent_graph.py`，耦合严重。 |
| 2 | 工具策略流水线（Policy Pipeline）是 P0 | **认同**。OpenClaw 的 `tool-policy-pipeline.ts` 实现了 7 层策略叠加（profile → providerProfile → global → globalProvider → agent → agentProvider → group），当前项目完全没有这个概念。 |
| 3 | before/after_tool_call 钩子是 P0 | **认同**。OpenClaw 的 `pi-tools.before-tool-call.ts` 实现了 block/modify 两种能力，当前项目的工具调用完全没有拦截点。 |
| 4 | 增量演进，不推倒重来 | **强烈认同**。当前 `multi_agent_graph.py` 已经 700+ 行且稳定运行，不能冒险重写。 |
| 5 | 特性开关回滚策略 | **认同**。`TOOL_PIPELINE_ENABLED` 等开关是必要的安全网。 |

### 2. 不认同/需修正的点

| # | 原方案观点 | 问题 | 修正建议 |
|---|-----------|------|---------|
| 1 | Phase 0-5 线性推进 | **过于理想化**。5 个 Phase 全部完成需要数月，且 Phase 间依赖关系不清晰。实际上 Phase 1（策略流水线）和 Phase 2（钩子）可以并行，Phase 3（事件升级）可以独立。 | 改为"核心层 + 扩展层"两阶段，核心层包含 Registry + Policy + Hook 三件套，扩展层包含事件升级和并发隔离。 |
| 2 | 工具事件从 `tool_start/tool_end` 升级为 `start/update/result` 是 P0 | **优先级过高**。当前 `events.py` 的 `tool_start/tool_end` 已经能工作，前端也已适配。事件升级是锦上添花，不是救火。 | 降为 P1，先把 Registry 和 Hook 做好。 |
| 3 | 并发隔离与状态治理是 P1 | **方向正确但方案模糊**。原方案提到"session 级互斥锁"，但没有说清楚锁什么、锁多久、死锁怎么办。OpenClaw 的 `session-write-lock.ts` 有僵尸锁恢复机制，原方案没有借鉴到位。 | 暂缓到 P2，先解决工具治理主链路。并发问题目前通过 LangGraph checkpointer 的乐观锁部分缓解。 |
| 4 | `ToolInvocationContext` 设计草案放在 Phase 0 | **过度设计**。Phase 0 应该只冻结最小接口，不需要完整的 Context 对象。 | Phase 0 只定义 `ToolRegistry` 接口和 `ToolPolicy` 配置结构，Context 在实现时自然浮现。 |
| 5 | 协议 schema 中心化是 P1/P2 | **认同优先级但缺少具体方案**。原方案只说"事件与请求统一 schema 注册"，没有说怎么做。 | 当前 `events.py` 的 `AgentEvent` 已经是事实上的 schema 中心，只需要补充 `tool_call_id` 字段即可。 |

### 3. 原方案遗漏的关键点

| # | 遗漏项 | 说明 |
|---|-------|------|
| 1 | **工具分组（Tool Groups）** | OpenClaw 的 `tool-policy.ts` 定义了 `TOOL_GROUPS`（如 `group:fs`、`group:web`），允许策略按组批量控制。原方案完全没提。 |
| 2 | **Glob 模式匹配** | OpenClaw 的策略支持 `web_*`、`group:fs` 等通配符，原方案只提到"白名单"。 |
| 3 | **插件工具与核心工具的区分** | OpenClaw 的 `stripPluginOnlyAllowlist` 确保策略不会误杀核心工具。当前项目没有这个概念，但随着 Skills/MCP 工具增多，这个问题会浮现。 |
| 4 | **Owner-Only 工具策略** | OpenClaw 的 `applyOwnerOnlyToolPolicy` 区分了"所有者"和"普通用户"的工具权限。当前项目有 `permission_service.py` 但没有和工具层打通。 |

### 4. 风险评估

| 风险 | 等级 | 说明 |
|------|------|------|
| Registry 引入导致现有工具加载失败 | 中 | 需要保证 Registry 是可选的包装层，不改变工具本身的行为 |
| Hook 拦截导致正常工具调用被误杀 | 中 | Hook 默认应该是 pass-through，只有显式注册的 hook 才生效 |
| 策略配置错误导致所有工具不可用 | 高 | 需要"空策略 = 全部允许"的安全默认值（OpenClaw 也是这么做的） |
| 改造过程中 `multi_agent_graph.py` 回归 | 中高 | 需要先写好工具链路的集成测试再动手 |

## 第二部分：工具治理架构方案 V0.1

### 1. 设计原则

1. **增量叠加**：新增模块，不改现有工具实现
2. **安全默认**：无配置 = 全部允许，无 Hook = 直接执行
3. **可观测**：每一层策略过滤和 Hook 执行都有日志
4. **可回滚**：特性开关控制，旧链路保留一个版本周期

### 2. 架构总览

```
                    ┌─────────────────────────────────────┐
                    │         ToolRegistry (注册中心)       │
                    │  - 工具注册/发现                      │
                    │  - 工具分组 (groups)                  │
                    │  - 工具元数据 (owner_only, category)  │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │      ToolPolicyPipeline (策略管线)    │
                    │  Layer 1: Global Policy              │
                    │  Layer 2: Agent Policy               │
                    │  Layer 3: User/Role Policy           │
                    │  Layer 4: Scene Policy               │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │      ToolHookRunner (钩子执行器)      │
                    │  before_tool_call → block / modify   │
                    │  after_tool_call  → audit / enrich   │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │         Tool Execution (工具执行)     │
                    │  (现有 LangChain @tool 不变)          │
                    └─────────────────────────────────────┘
```

#### 3.1 ToolRegistry（工具注册中心）

新增文件：`app/ai/tools/registry.py`

```python
"""工具注册中心。"""
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Set
from langchain_core.tools import BaseTool

# 工具分组定义
TOOL_GROUPS: Dict[str, List[str]] = {
    "data": ["sql_inter", "fig_inter", "data_query"],
    "web": ["tavily_search", "web_fetch"],
    "knowledge": ["knowledge_search"],
    "file": ["read_uploaded_file", "analyze_image"],
    "todo": ["create_todo", "query_todo", "update_todo", "delete_todo"],
}


@dataclass
class ToolMeta:
    """工具元数据。"""
    name: str
    category: str = "general"        # 分类：data/web/knowledge/file/todo
    owner_only: bool = False          # 是否仅管理员可用
    requires_auth: bool = False       # 是否需要认证
    groups: Set[str] = field(default_factory=set)  # 所属分组


class ToolRegistry:
    """全局工具注册中心。

    职责：
    1. 统一注册所有工具（替代散落的 _get_xxx_tools 函数）
    2. 维护工具元数据（分组、权限、分类）
    3. 按条件查询可用工具集
    """

    def __init__(self):
        self._tools: Dict[str, BaseTool] = {}
        self._meta: Dict[str, ToolMeta] = {}

    def register(
        self,
        tool: BaseTool,
        category: str = "general",
        owner_only: bool = False,
        groups: Optional[Set[str]] = None,
    ) -> None:
        """注册工具。"""
        name = tool.name
        self._tools[name] = tool
        self._meta[name] = ToolMeta(
            name=name,
            category=category,
            owner_only=owner_only,
            groups=groups or set(),
        )

    def get_tool(self, name: str) -> Optional[BaseTool]:
        """按名称获取工具。"""
        return self._tools.get(name)

    def get_meta(self, name: str) -> Optional[ToolMeta]:
        """获取工具元数据。"""
        return self._meta.get(name)

    def list_tools(
        self,
        category: Optional[str] = None,
        group: Optional[str] = None,
        include_owner_only: bool = True,
    ) -> List[BaseTool]:
        """按条件列出工具。"""
        result = []
        for name, tool in self._tools.items():
            meta = self._meta.get(name)
            if not meta:
                result.append(tool)
                continue
            if category and meta.category != category:
                continue
            if group and group not in meta.groups:
                continue
            if not include_owner_only and meta.owner_only:
                continue
            result.append(tool)
        return result

    def list_all(self) -> List[BaseTool]:
        """列出所有已注册工具。"""
        return list(self._tools.values())

    @property
    def tool_names(self) -> Set[str]:
        """所有已注册工具名称。"""
        return set(self._tools.keys())


# 全局单例
_global_registry: Optional[ToolRegistry] = None


def get_tool_registry() -> ToolRegistry:
    """获取全局工具注册中心。"""
    global _global_registry
    if _global_registry is None:
        _global_registry = ToolRegistry()
    return _global_registry
```

#### 3.2 ToolPolicy（策略定义与管线）

新增文件：`app/ai/tools/policy.py`

```python
"""工具策略管线。"""
import fnmatch
import logging
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Set
from langchain_core.tools import BaseTool

from app.ai.tools.registry import TOOL_GROUPS

logger = logging.getLogger(__name__)


@dataclass
class ToolPolicy:
    """工具策略（allow/deny 模型）。

    规则：
    - allow 为空 = 允许所有（安全默认值，与 OpenClaw 一致）
    - deny 优先于 allow
    - 支持 glob 模式（如 "data_*"、"group:web"）
    """
    allow: List[str] = field(default_factory=list)
    deny: List[str] = field(default_factory=list)
    label: str = ""  # 策略来源标签（用于日志）


def _expand_groups(patterns: List[str]) -> List[str]:
    """展开工具分组引用。如 "group:data" -> ["sql_inter", "fig_inter", ...]"""
    expanded = []
    for pattern in patterns:
        normalized = pattern.strip().lower()
        if normalized.startswith("group:"):
            group_name = normalized[6:]
            group_tools = TOOL_GROUPS.get(group_name, [])
            expanded.extend(group_tools)
        else:
            expanded.append(pattern.strip())
    return expanded


def is_tool_allowed(policy: ToolPolicy, tool_name: str) -> bool:
    """判断工具是否被策略允许。"""
    normalized = tool_name.strip().lower()

    # 展开分组
    deny_patterns = _expand_groups(policy.deny)
    allow_patterns = _expand_groups(policy.allow)

    # deny 优先
    for pattern in deny_patterns:
        if fnmatch.fnmatch(normalized, pattern.lower()):
            return False

    # allow 为空 = 全部允许
    if not allow_patterns:
        return True

    # 检查 allow
    for pattern in allow_patterns:
        if fnmatch.fnmatch(normalized, pattern.lower()):
            return True

    return False


def apply_policy(tools: List[BaseTool], policy: ToolPolicy) -> List[BaseTool]:
    """应用单个策略过滤工具列表。"""
    if not policy.allow and not policy.deny:
        return tools  # 空策略 = 不过滤

    filtered = [t for t in tools if is_tool_allowed(policy, t.name)]

    if len(filtered) != len(tools):
        removed = set(t.name for t in tools) - set(t.name for t in filtered)
        logger.info(
            "策略过滤 [%s]: %d -> %d 工具, 移除: %s",
            policy.label, len(tools), len(filtered), removed,
        )

    return filtered


def apply_policy_pipeline(
    tools: List[BaseTool],
    policies: List[ToolPolicy],
) -> List[BaseTool]:
    """按顺序应用多层策略管线。

    策略按优先级从高到低排列，每层独立过滤。
    """
    result = tools
    for policy in policies:
        result = apply_policy(result, policy)
    return result
```

#### 3.3 ToolHookRunner（钩子执行器）

新增文件：`app/ai/tools/hooks.py`

```python
"""工具调用钩子系统。"""
import logging
import time
from dataclasses import dataclass
from typing import Any, Callable, Dict, List, Optional, Awaitable

logger = logging.getLogger(__name__)


@dataclass
class BeforeToolCallResult:
    """before_tool_call 钩子返回值。"""
    blocked: bool = False
    reason: str = ""
    modified_params: Optional[Dict[str, Any]] = None


@dataclass
class AfterToolCallResult:
    """after_tool_call 钩子返回值。"""
    modified_output: Optional[str] = None
    audit_data: Optional[Dict[str, Any]] = None


# 钩子函数类型
BeforeToolCallHook = Callable[
    [str, Dict[str, Any], Dict[str, Any]],  # tool_name, params, context
    Awaitable[BeforeToolCallResult],
]

AfterToolCallHook = Callable[
    [str, Dict[str, Any], Any, float, Dict[str, Any]],  # tool_name, params, output, duration, context
    Awaitable[AfterToolCallResult],
]


class ToolHookRunner:
    """工具钩子执行器。

    支持注册 before/after 钩子，在工具调用前后执行。
    钩子按注册顺序执行，任一 before 钩子返回 blocked=True 则阻断调用。
    """

    def __init__(self):
        self._before_hooks: List[BeforeToolCallHook] = []
        self._after_hooks: List[AfterToolCallHook] = []

    def register_before(self, hook: BeforeToolCallHook) -> None:
        """注册 before_tool_call 钩子。"""
        self._before_hooks.append(hook)

    def register_after(self, hook: AfterToolCallHook) -> None:
        """注册 after_tool_call 钩子。"""
        self._after_hooks.append(hook)

    @property
    def has_before_hooks(self) -> bool:
        return len(self._before_hooks) > 0

    @property
    def has_after_hooks(self) -> bool:
        return len(self._after_hooks) > 0

    async def run_before(
        self,
        tool_name: str,
        params: Dict[str, Any],
        context: Optional[Dict[str, Any]] = None,
    ) -> BeforeToolCallResult:
        """执行所有 before_tool_call 钩子。"""
        ctx = context or {}
        current_params = dict(params)

        for hook in self._before_hooks:
            try:
                result = await hook(tool_name, current_params, ctx)
                if result.blocked:
                    logger.warning(
                        "工具调用被钩子阻断: tool=%s, reason=%s",
                        tool_name, result.reason,
                    )
                    return result
                if result.modified_params:
                    current_params.update(result.modified_params)
            except Exception as e:
                logger.error("before_tool_call 钩子异常: tool=%s, error=%s", tool_name, e)
                # 钩子异常不阻断工具调用（安全默认）

        return BeforeToolCallResult(blocked=False, modified_params=current_params)

    async def run_after(
        self,
        tool_name: str,
        params: Dict[str, Any],
        output: Any,
        duration: float,
        context: Optional[Dict[str, Any]] = None,
    ) -> AfterToolCallResult:
        """执行所有 after_tool_call 钩子。"""
        ctx = context or {}
        audit_data: Dict[str, Any] = {}

        for hook in self._after_hooks:
            try:
                result = await hook(tool_name, params, output, duration, ctx)
                if result.audit_data:
                    audit_data.update(result.audit_data)
            except Exception as e:
                logger.error("after_tool_call 钩子异常: tool=%s, error=%s", tool_name, e)

        return AfterToolCallResult(audit_data=audit_data if audit_data else None)


# 全局单例
_global_hook_runner: Optional[ToolHookRunner] = None


def get_hook_runner() -> ToolHookRunner:
    """获取全局钩子执行器。"""
    global _global_hook_runner
    if _global_hook_runner is None:
        _global_hook_runner = ToolHookRunner()
    return _global_hook_runner
```

### 8. 回滚方案

| 场景 | 操作 |
|------|------|
| Registry 加载失败 | `TOOL_PIPELINE_ENABLED=false`，自动回退旧链路 |
| 策略误杀核心工具 | 清空策略配置（空策略=全部允许） |
| Hook 导致工具超时 | 移除对应 Hook 注册，或设置 `TOOL_HOOKS_ENABLED=false` |
| 线上异常需紧急回滚 | 修改环境变量重启，无需改代码 |
