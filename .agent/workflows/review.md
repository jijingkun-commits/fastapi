# 👓 代码审查工作流 (Review Workflow)

此工作流专注于 **审查 (Review)** 和 **自测 (Self-Test)** 改动，确保代码质量并符合 Vibe Coding 规范。

> **中文主导**: 无论是思考过程（CoT）还是最终输出，**永远使用中文**。

## 1. 代码审查 (Code Review)

**目标**: 确保 Opuse 产出的代码逻辑最简、可读性高，且文档已同步。

**检查清单 (Checklist)**:
- [ ] **意图一致性**: 代码是否实现了 `requirements.md` 中的需求？
- [ ] **最简原则**: 有没有过度设计？逻辑是否可以更直白？
- [ ] **文档同步**:
    - [ ] API 变更 -> `docs/API文档/接口文档.md`
    - [ ] 数据库变更 -> `docs/开发文档/架构设计/数据库设计.md`
    - [ ] 配置/依赖变更 -> `docs/开发文档/快速入门/配置说明.md`
- [ ] **规范遵循**: 是否符合 `rules.md` (中文注释, 类型提示, Pydantic v2)?

## 2. 自测验证 (Self-Test)

**目标**: 在提交给用户前，拦截低级错误。

**动作**:
1.  **运行相关测试**:
    ```bash
    # 示例
    python -m pytest tests/path/to/test.py
    ```
2.  **验证服务启动**:
    - 如果修改了应用代码，尝试重启服务确保无启动报错。
3.  **日志检查**:
    - 检查是否有明显 `ERROR`。

## 3. 修复与反馈 (Fix & Feedback)

- **简单问题** (如 Typos, 类型错误, 简单逻辑 Bug):
    - ⚡️ **直接修复** (由 Sonnet 动手)。
- **严重设计缺陷**:
    - 🛑 **停止流程**，反馈给用户，建议切回 Planning 模式 (使用 Opus)。
