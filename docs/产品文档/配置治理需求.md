# 配置治理需求（C 方案：运行参数单源化到 DB）

> 模块定位：在不新增配置表的前提下，统一配置来源、读取路径与后台可观测性。

> 关联代码：`app/core/config.py`、`app/services/system_config_service.py`、`app/api/v1/endpoints/system_admin_api.py`、`app/api/v1/endpoints/access_admin_api.py`、`app/ai/llm_util.py`

## 1. 目标与边界

### 1.1 目标

1. 动态运行参数以 `t_system_config` 为唯一主来源（密钥除外）。
2. 所有业务模块通过统一配置读取入口消费配置，消除隐式散读。
3. 后台展示与运行时生效保持一致，减少排障歧义。
4. 配置键命名统一，避免同义键并存（如 `askdata.*` / `data_access.*`）。

### 1.2 非目标

1. 不新增配置表与字段。
2. 不替代 Secret 管理体系（密钥仍保持 env-only）。
3. 不改动数据分析库 `data_db` 读写边界。

---

## 2. 典型用户故事

1. **平台管理员**：我希望在“系统配置”页面修改模型路由和技能参数后，问答链路立即生效。
2. **运维工程师**：我希望每个配置都能明确看到来源与当前生效值，避免多套配置互相覆盖。
3. **数据安全管理员**：我希望问数访问控制配置键统一，避免命名不一致导致策略失效。
4. **研发工程师**：我希望新增配置时有明确准入规则，避免再次增加无主配置。

## 3. 功能需求

### 3.1 配置分层与来源策略

1. 配置必须分层管理：
   - `db-dynamic`：运行参数（可后台动态修改）
   - `env-only`：基础设施/密钥参数（不可写入 DB）
2. 每个配置键必须声明：`source`、`value_type`、`default`、`editable`、`is_secret`。

### 3.2 统一读取链路

1. 新增统一配置解析入口（Resolver）。
2. 业务模块不得直接散读 `os.getenv`（密钥读取除外）。
3. 读取优先级固定为：`DB 配置 -> 安全默认值`（`env-only` 仍为 `env -> 默认值`）。

### 3.3 配置键治理

1. 统一问数配置命名主键为 `askdata.*`。
2. 历史键 `data_access.*` 仅保留兼容读与迁移，不允许新写。
3. 所有写接口必须写入统一主键。

### 3.4 后台治理能力

1. 系统配置页仅对 `db-dynamic` 配置提供编辑。
2. 提供“来源标记”和“运行时生效标记”。
3. 支持配置缓存刷新，并返回刷新后缓存项数量。

### 3.5 初始化与对账

1. 初始化脚本保证关键动态配置存在。
2. 提供配置对账脚本，输出以下问题：
   - DB 中存在但未被读取的配置
   - 运行时读取但 DB 缺失的配置
   - 命名冲突/历史兼容键并存

## 4. 共享能力引用（单一真理来源）

1. **动态配置主存储**：`chat_db.t_system_config`
2. **动态配置读取入口**：统一 Resolver（替代散落读取）
3. **管理写入口**：`system_admin_api` / 受控管理接口
4. **问数配置主键规范**：`askdata.*`

---

## 5. 验收标准

### 5.1 Happy Path

1. 修改 `model_routing.*` 后，聊天/问数链路命中新路由。
2. 修改 `skill.*` 后，技能检索评分与候选裁决按新参数生效。
3. 修改 `askdata.*` 后，表/Schema 访问控制策略按新值生效。

### 5.2 异常/边界

1. 非法配置值（如 `number` 写入非数字）被拒绝或降级并告警。
2. DB 缺失时系统按默认值运行且可观测。
3. 历史键存在时，不影响主键读取稳定性。

### 5.3 稳定性

1. 配置读取层改造后，关键接口吞吐无明显下降。
2. 缓存刷新无全局阻塞与竞态异常。

---

## 6. 非功能需求

1. **性能**：配置读取应具备缓存机制，避免每次请求直连 DB。
2. **安全**：密钥类配置不进 DB；后台写接口保持管理员权限。
3. **一致性**：接口文档、后台文案、代码常量命名一致。
4. **可维护性**：新增配置必须经过契约注册与文档同步。

## 8. 风险与优先级

1. `P0`：键名收敛期可能出现“旧键残留 + 新键写入”双值冲突。
2. `P0`：读取链路统一改造影响面广，需分阶段灰度与回归。
3. `P1`：后台展示调整后，需同步培训运维“动态配置 vs env-only”的治理口径。
