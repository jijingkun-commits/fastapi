# 技能系统需求（Skill）

> 更新时间：2026-03-13
> 模块定位：面向 Agent 的技能检索、触发与注入能力  
> 关联代码：`app/models/agent_skill.py`、`app/services/skill_service.py`、`app/ai/workflow/multi_agent_graph.py`、`app/api/v1/endpoints/skill_admin_api.py`

---

## 1. 目标与边界

### 1.1 目标

1. 让技能从“可手工调用”升级为“可自动触发且可治理”。
2. 在复杂提示词场景下保持稳定命中与可解释排序。
3. 将技能注入控制在预算内并支持降级回退。
4. 支持 Skill 定义层、版本层、用户绑定层解耦，满足多用户隔离治理。

### 1.2 非目标

1. 不追求复刻外部闭源平台的全部打分细节。
2. 不承载前端组件渲染逻辑。
3. 不替代问数/待办等业务工作流的业务决策。

---

## 2. 业务用户故事

1. **业务运营**：希望输入“客户触达策略”后自动命中营销类技能。
2. **产品经理**：希望技能命中过程可解释，能看到候选与淘汰原因。
3. **管理员**：希望在后台控制技能自动触发开关、优先级与作用域。
4. **架构治理**：希望技能导入、检索、注入链路具备统一元数据语义。
5. **分行信贷经理**：希望在“贷款余额分析”场景绑定分行定制版本，不影响其他分行用户。
6. **合规管理员**：希望用户绑定可回滚，且回滚后立即恢复到平台发布版本。

---

## 3. 功能需求

### 3.1 技能元数据

1. 支持字段：`auto_enabled`、`priority`、`scope`、`trigger_phrases`、`conflicts_with`。
2. 允许在导入时从 frontmatter 自动填充。
3. 支持对旧技能数据无损兼容。

### 3.2 导入与同步

1. 启动同步支持增量更新和幂等。
2. frontmatter 异常不阻断整体同步，但必须落 warning。
3. skill_id 作为唯一键，避免重复记录。

### 3.3 检索与排序

1. 支持关键词+向量混合召回。
2. 支持融合排序与阈值过滤。
3. 支持作用域过滤与冲突裁决。

### 3.4 注入策略

1. 支持章节/段落级内容提取。
2. 支持 token budget 限制。
3. 注入结果需附带来源 skill_id 列表。

### 3.5 可观测

1. 记录检索候选、分数、裁决、最终注入。
2. 支持按 thread_id/trace_id 检索链路。
3. 支持离线评测集回放。

### 3.6 多用户版本治理（P3-01）

1. Skill 数据层拆分为 `definition/version/user_binding` 三层，`skill_id` 保持全局稳定。
2. 支持发布版本、回滚版本；同一 skill 仅允许一个 `published` 生效版本。
3. 支持用户级绑定：可配置 `enabled/version/priority_override`，按 `user_id + skill_id` 唯一约束隔离。
4. 运行时解析顺序：先加载平台发布版本，再叠加用户绑定覆盖。
5. 回滚开关：`ENABLE_SKILL_VERSIONING` 与 `ENABLE_USER_SKILL_BINDING` 任一关闭时，自动降级到兼容路径。

---

## 4. 验收标准

### 4.1 Happy Path

1. 输入运营类任务时可自动触发预期技能。
2. 相近问题改写时，命中集合稳定。
3. 注入上下文在预算内且可解释。
4. 同一 skill 在用户 A/B 上可绑定不同版本，且检索结果互不污染。

### 4.2 异常与边界

1. embedding 服务异常时检索可降级。
2. 冲突技能场景下不出现双技能互斥污染。
3. 不合法 frontmatter 有清晰告警和回退。
4. 用户绑定 rollback 后，恢复平台发布版本且保留审计状态。

### 4.3 非功能

1. 检索延迟可控。
2. 日志可追溯。
3. 开关可回滚。
