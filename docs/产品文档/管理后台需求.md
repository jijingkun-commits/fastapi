## 1. 目标与边界

### 1.1 目标

1. 提供问数管理、模型配置、权限管理、开发工具等统一入口。
2. 所有后台接口默认管理员权限。
3. 管理变更具备审计与回归验证路径。

### 1.2 非目标

1. 不承载终端用户对话 UI 功能。
2. 不替代数据库迁移工具链。

---

## 2. 典型用户故事

1. **数据管理员**：我需要处理 query logs、纠正 SQL、批量训练、维护指标、维护结果增强规则。
2. **模型管理员**：我需要维护 provider/model、设置默认模型、调整模型路由。
3. **研发管理员**：我需要在开发环境触发 codex 执行调试，但生产必须禁止。

---

## 3. 功能需求

### 3.1 问数管理（data_admin）

1. 提供 query logs 查询、忽略、纠正、反馈。
2. 提供 train、全量待训练、schema 同步、指标 CRUD。
3. 提供结果增强规则管理（CRUD + enable + priority + test + refresh-cache）。

### 3.2 模型管理（llm_admin）

1. provider/model 的增删改查、默认切换、启停切换。
2. 模型路由总览与可编辑配置更新。

### 3.3 开发工具（dev-tools）

1. 提供 `POST /api/v1/dev-tools/codex/exec` 执行入口。
2. 强制管理员权限。
3. 强制环境约束：`ENV == prod` 时拒绝调用。

### 3.4 技能治理（skill_admin）

1. 提供 Skill 元数据治理：`is_enabled/auto_enabled/priority/scope/trigger_phrases/conflicts_with`。
2. 提供 Hybrid 检索调试能力：可查看候选集、融合排序、过滤原因、最终注入上下文预览。
3. 提供向量重建能力：支持单个与批量重建向量（后台任务）。
4. 配置变更需可审计，至少记录操作者与变更摘要。

#### 3.4.1 技能列表交互一致性（2026-02-14）

1. 搜索框输入不得触发整页刷新式闪烁；查询触发需采用显式提交或防抖策略。
2. 技能列表计数必须与当前查询条件命中数一致；无筛选条件下应与总览技能总数一致。
3. 禁止在前端硬编码固定展示上限导致统计失真（例如固定 `100` 条）。
4. 总览统计与列表统计口径需在 UI 文案中显式区分，避免管理决策误读。

### 3.5 总览驾驶舱（admin_overview）

1. 将 `/admin` 首页从“入口卡片”升级为“运行态驾驶舱”，优先回答系统健康状态。
2. 首屏固定 8 块信息：健康总分、请求质量、稳定性、容量与成本、实时告警、数据新鲜度、模块健康矩阵、关键变更流。
3. 数据刷新默认实时（SSE 优先，轮询降级），并显示数据时效状态。
4. 总览统一面向后台用户，不做按角色分版。
5. 总览只展示聚合态指标，禁止暴露客户明细字段，满足银行合规最小披露要求。

### 3.6 访问控制配置治理（access_admin）

1. 访问控制配置键主写统一为 `askdata.*`。
2. 历史 `data_access.*` 仅保留兼容读取，禁止新写入。
3. 配置更新后需触发访问控制缓存失效，确保策略快速生效。

---

## 4. 共享能力引用（单一真理来源）

1. **模型路由**：管理后台仅修改配置键，不定义业务模型策略。
2. **问数结果增强**：规则模型与服务为唯一真理来源，后台只做管理入口。
3. **聊天协议**：后台不定义 SSE 协议，必要时只读取协议文档。

---

## 5. 验收标准

### 5.1 Happy Path

1. 管理员可完成问数日志治理、规则管理、模型路由更新。
2. 更新后业务链路可观察到新配置生效。
3. 开发环境可调用 dev-tools，生产环境被拒绝。
4. 管理员可配置 Skill 自动触发策略，并通过调试接口验证命中效果。
5. 管理员进入 `/admin` 可在首屏看到实时健康态势并定位异常模块。

### 5.2 边界与异常

1. 非管理员访问后台接口返回 401/403。
2. 不合法规则字段返回明确验证错误。
3. dev-tools 命令不存在或超时时返回可解释错误结构。
4. Skill 冲突配置非法（自冲突/循环冲突）时返回可解释校验错误。
5. 总览实时链路中断时自动降级到轮询，页面保持可用且有状态提示。

### 5.3 稳定性

1. 后台操作失败不影响主对话链路可用性。
2. 规则刷新和缓存更新不会阻塞核心业务请求。

---

## 6. 非功能需求

1. **安全性**：管理接口需最小权限原则，开发工具限制非生产。
2. **可观测性**：关键管理操作记录审计日志。
3. **一致性**：前后端字段命名与错误语义统一。
4. **实时性**：总览关键健康指标端到端刷新延迟目标 ≤ 5 秒。

---

### 6.4 管理后台 UI 一致性（2026-02-13 补充）

1. 左侧导航配色需与聊天历史侧栏保持同一语义色体系。
2. 管理后台内容区必须使用统一容器宽度与留白规范，避免页面内容横向铺满。
3. 新增管理页面应默认复用后台壳层样式类，不得新增独立硬编码主题。

## 8. 当前风险与改造优先级

1. `P1`：`data_admin_api.py` 文件体量大（1200 行），建议按日志治理/指标治理/规则治理拆分。
2. `P1`：部分 endpoint 仍有跨层直连，需要收敛到 service 层。
3. `P2`：后台页面 lint 警告较多，影响长期可维护性。
4. `P1`：总览缺少统一观测快照，需补齐分钟级指标快照表避免实时计算抖动。
