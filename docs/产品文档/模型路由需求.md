## 1. 目标与边界

### 1.1 目标

1. 模型表 `t_llm_model` 仅管理模型信息，不再承载调用点治理语义。
2. 场景治理表单独维护调用点场景与默认模型绑定。
3. 每处 LLM 调用均使用场景键，场景键格式固定为 `模块.函数名`。
4. 每个场景仅允许绑定一个默认模型，避免多分支选择导致不可控。
5. 启动阶段强校验场景完整性：若存在未配置调用点，服务启动失败。
6. 场景类型本轮扩展为：`text/image/video/audio/embedding/vision/rerank/asr/tts`。

### 1.2 非目标

1. 不在本轮引入多模型回退链或流量灰度分配。
2. 不在本轮实现自动成本优化调度（如按 token 价格实时切模）。
3. 不改变模型提供商管理（provider/model CRUD）职责边界。

---

## 2. 核心概念

1. **模型管理**：维护模型元数据、能力参数、启用状态。
2. **场景治理**：维护调用点场景键、场景类型、默认模型、启用状态。
3. **调用点（scene_key）**：代码唯一键，格式 `模块.函数名`，例如 `app.ai.workflow.data_graph.generate_sql`。
4. **场景类型（scene_type）**：用于约束场景只能绑定兼容模型类型。

---

## 3. 典型用户故事（含银行场景）

1. **平台管理员**：我希望按调用点查看默认模型，快速定位高成本链路并调整模型。
2. **后端开发**：我希望新增调用点必须先配置场景，否则启动失败，避免遗漏治理。
3. **银行业务分析师**：我希望“按分行统计贷款余额”场景始终走指定文本模型，保证口径稳定。
4. **合规审核人员**：我希望语音/视频相关调用点不能误绑文本模型，避免跨类型误用带来风险。

## 4. 功能需求

### 4.1 场景治理数据模型

1. 新增场景治理表（1 张），用于保存：
   - `scene_key`（唯一）
   - `scene_type`
   - `default_model_id`
   - `is_active`
   - 描述与审计字段
2. `scene_key` 必须满足 `模块.函数名` 格式。
3. 场景停用后不得参与运行时模型解析。

### 4.2 调用入口约束

1. 业务侧统一使用 `get_scene_llm(scene_key=...)`。
2. 禁止使用裸 `get_llm()` 作为业务入口。
3. `get_scene_llm` 未命中有效场景时立即报错，不允许环境变量兜底。
4. 显式 `model_id` 仅作为受控覆盖能力，默认走场景绑定模型。

### 4.3 启动门禁

1. 启动时校验所有已注册调用点是否有数据库配置。
2. 任一调用点缺失配置时，服务启动失败。
3. 若场景绑定模型不存在/禁用/类型不兼容，启动失败并输出原因。

### 4.4 场景类型治理

1. 本轮必须支持：`text/image/video/audio/embedding/vision/rerank/asr/tts`。
2. 场景类型与模型类型兼容性由服务层统一维护。
3. 类型不兼容的更新请求应被拒绝（HTTP 400）。

### 4.5 管理能力

1. 提供场景列表接口，展示调用点、类型、默认模型、状态、更新时间。
2. 提供场景默认模型更新接口，仅管理员可操作。
3. 场景变更后需刷新缓存，无需重启。
4. 记录审计日志（操作者、旧值、新值、时间）。

### 4.6 可观测性

1. 运行日志需包含 `scene_key` 与 `model_code`。
2. 支持按场景维度进行调用量/成本/失败率统计。

## 5. 验收标准

### 5.1 Happy Path

1. 全量 LLM 调用点均已绑定场景键并可在后台查询。
2. 运行时可稳定根据 `scene_key` 命中默认模型。
3. 更新场景默认模型后新请求即时生效。

### 5.2 边界与异常

1. 未配置调用点时，服务启动失败。
2. 场景键格式非法时，接口拒绝写入。
3. 类型不兼容时，接口拒绝写入。
4. 非管理员用户修改场景绑定时返回 403。

### 5.3 稳定性

1. 场景解析使用内存缓存，不显著增加调用延迟。
2. 配置刷新失败时保持旧缓存可用，不产生空缓存窗口。

---

## 6. 非功能需求

1. **一致性**：调用点命名、场景类型、管理接口字段保持统一。
2. **可追溯性**：任一调用可追溯到调用点、场景类型、默认模型。
3. **安全性**：场景配置修改操作受管理员权限与审计约束。
4. **可维护性**：新增调用点流程固定为“登记场景 -> 配置默认模型 -> 提交代码”。

## 8. 迁移与发布约束

1. 发布前必须先执行场景数据初始化脚本，覆盖全部已注册调用点。
2. 迁移期允许旧接口透传到新场景服务，但不允许新增旧式路由键。
3. 回滚时需同步回滚应用版本与场景配置快照，避免“代码与配置版本错位”。
