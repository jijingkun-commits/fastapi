# 问数助手需求（重生版）

> 模块定位：银行场景下的多轮问数与结果解释能力
> 
> 关联代码：`app/ai/workflow/data_graph.py`、`app/ai/semantic/*`、`app/api/v1/endpoints/data_admin_api.py`

---

## 1. 目标与边界

### 1.1 目标

1. 支持贷款/存款/分行维度等银行核心分析场景。
2. 支持多轮补充（时间、维度、筛选）而不丢失上下文。
3. 支持结果增强规则（lookup）与后台可配置治理。
4. 严格执行数据权限与双数据库隔离策略。

### 1.2 非目标

1. 不在本模块内处理通用聊天 UI 交互。
2. 不在本模块内实现前端渲染组件细节。
3. 不在本模块内承载待办业务语义。

---

## 2. 典型用户故事

1. **分行经营分析师**：我想查“本月贷款余额按分行 Top10”，然后补充“只看对公客户”。
2. **管理层秘书**：我想把“贷款余额”切换成“存款余额”，沿用上一轮维度和时间。
3. **合规审核员**：我希望系统自动拒绝敏感表与系统 schema 访问。
4. **数据管理员**：我希望通过后台配置结果增强规则，让结果自动补齐客户名称。

---

## 3. 功能需求

### 3.1 会话意图与上下文

1. 必须支持回合行为分类（`NEW_QUERY/SUPPLEMENT/CORRECTION/CONFIRM`）。
2. 必须支持会话帧归并（`current > handoff > state > default`）与来源映射。
3. 补充轮应优先复用上轮已确认的指标、时间、维度。

### 3.2 SQL 生成与执行

1. 支持总量、维度、TopN 三类查询形态。
2. 支持 schema 路由与 SQL 安全校验。
3. 结果为空时支持空结果恢复重写策略。

### 3.3 结果增强（Result Enrichment）

1. 规则模型需支持：`rule_code`、优先级、启停、来源表与字段映射。
2. 后台提供规则列表、新增、更新、启停、优先级调整、规则测试、缓存刷新。
3. 规则执行顺序由优先级决定，需具备审计记录。

### 3.4 权限与合规

1. 分析查询默认走 `ANALYTICS_DATABASE_URL` 对应链路。
2. 系统表、敏感表、系统 schema 必须拦截。
3. 允许有限元数据视图（`information_schema.tables/columns/...`）只读访问。

---

## 4. 共享能力引用（单一真理来源）

1. **会话意图内核**：以 `session_intent_kernel.py` 为统一语义来源。
2. **SSE 协议**：事件名和 payload 以聊天系统协议为准，不在问数模块发明新事件规范。
3. **模型路由**：SQL 生成与轻量任务模型走统一路由配置键。

---

## 5. 验收标准

### 5.1 Happy Path

1. “贷款余额 → 分行维度 → Top10 → 图表切换”多轮链路可收敛。
2. 用户补充条件后，系统不丢失已有上下文。
3. 结果增强规则生效后，可见补齐字段。

### 5.2 边界与异常

1. 非法 SQL/越权表访问时返回明确错误。
2. schema 路由失败时可回退默认 schema，并保留日志。
3. 空结果场景可触发重写或给出可解释提示。

### 5.3 稳定性

1. 同一会话连续追问不应出现意图震荡。
2. 结果增强规则异常时应降级而非阻断主链路。

---

## 6. 非功能需求

1. **性能**：关键查询链路支持超时保护与重试策略。
2. **可观测**：保留 thread_id、turn_act、schema 选择、规则命中日志。
3. **一致性**：指标语义、字段命名、返回结构在多轮中稳定。
