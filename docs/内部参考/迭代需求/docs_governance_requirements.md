## 1. 背景与目标

当前 `docs/**` 已具备完整目录与导航，但存在以下核心问题：

1. 个别关键文档仍引用失效代码路径，影响内容准确性。
2. 命令/流程说明在多个文档并行维护，存在口径漂移风险。
3. 迭代需求目录命名策略不一致，影响检索与维护效率。

本轮目标：在不改变目录大结构的前提下，完成“结构清晰、内容准确、去重合并”的可执行收敛。

---

## 2. 需求范围

## 2.1 本轮纳入

1. 批次 A：修复 `P0` 准确性问题（按《文档梳理与重构方案》清单执行）。
2. 批次 B：按已拍板决策收敛结构与职责边界。
3. 更新 `SUMMARY` 与核心入口，保证新增/调整文档可检索。

## 2.2 本轮不纳入

1. 不引入 `内部参考/迭代需求` 的双层归档目录重构。
2. 不删除 `vibe-coding开发技巧.md` 的全量百科定位。
3. 不改变 `开发工作流.md` 模板代码策略，仅补“示例占位”标注。

## 3. 用户故事（含银行场景）

1. 作为新加入开发者，我希望在 2 跳内找到权威文档，避免在“架构设计/代码解读/速查”之间反复试错。
2. 作为银行业务分析师，我希望能快速从“需求 -> 架构 -> API”追踪“按分行统计贷款余额”的实现口径，确保业务解释一致。
3. 作为合规审核人员，我希望文档中涉及敏感字段（如客户信息、权限边界）时有统一入口与正确引用，避免误读导致越权查询风险。
4. 作为 AI 协作者，我希望命令工作流说明稳定且可追溯，不因多处重复描述而产生冲突指令。

---

## 4. 验收标准

## 4.1 功能性（Happy Path）

1. `P0` 问题全部修复，失效路径/命令归零。
2. `代码解读/` 与 `架构设计/` 的职责边界在文档中显式可见。
3. `vibe-coding开发技巧.md` 保留全量百科，同时标注权威来源。
4. `开发工作流.md` 模板代码明确标注“示例占位”。

## 4.2 边界与异常

1. 新增文档未加入 `SUMMARY` 时，应被门禁发现并阻断。
2. 文档包含通配符示例路径时，不应被误判为真实失效路径。
3. 命令文档与速查文档冲突时，以 `.cursor/commands/*.md` 为权威源。

## 4.3 性能与稳定性

1. `python3 scripts/docs_guard.py --strict` 全程通过。
2. 文档改动不引入新断链、不降低 `SUMMARY` 覆盖率。
3. 核心入口文档（README/SUMMARY/速查）在本轮不出现互相矛盾描述。

---

## 5. 非功能需求

1. **一致性**：同一术语（如 WS、Gate、权威源）在核心文档中定义一致。
2. **可追溯**：每条关键策略均可追踪到权威来源与执行清单。
3. **安全与合规**：涉及银行业务示例时，不暴露敏感数据，不破坏权限与脱敏边界说明。
4. **可维护性**：后续新增文档可按现有命名规则快速纳入索引。
