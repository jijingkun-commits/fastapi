# 自动化大型任务开发（主机方案）— 需求基线

> 日期：2026-02-28
> 主题：在单主机环境下落地 hooks-first + 本地状态驱动的自动化研发链路
> 关联设计：`docs/内部参考/迭代需求/自动化大型任务开发设计方案.md`
> 关联打钩板：`docs/内部参考/迭代需求/自动化大型任务开发_全量打钩板清单.md`

---

## 1. 背景与问题陈述

当前自动化研发链路存在以下高频问题：

1. `cron */3` 轮询存在天然等待，卡片完成后无法立即推进；
2. 执行状态分散在本地文件与外部看板，故障时一致性修复成本高；
3. 本项目代码、Codex 执行环境与依赖服务均在主机，若设计不贴合主机场景，容易出现“编排可用、执行不可用”的断层；
4. 任务规模大且跨会话，缺少可持续推进的统一门禁与交接规范。

本需求要求在**不迁移代码主阵地**的前提下，完成自动化链路改造，并确保可追溯、可回滚、可审计。

## 3. 目标与范围

### 3.1 目标

1. 建立 hooks-first 主触发链路（`/hooks/wake` 为主，`/hooks/agent` 为特例）；
2. 将执行状态统一收敛到本地三层真理源；
3. 完成主机部署安全基线与上线门禁；
4. 形成可跨会话推进的打钩板与任务拆分机制。

### 3.2 范围内

1. `scripts/coder4/coder4_bootstrap_kernel.py` 本地模式强化；
2. `scripts/coder4/wt-flow.sh` 扩展与串行门禁强化；
3. `task-runner-state.json` / attempts / ledger 本地化收敛；
4. `WORKFLOW_AUTO.md`、`VK_AGENT_PROMPTS.md` 等仓外规则清理；
5. VK 降级为只读展示层（fire-and-forget）。

### 3.3 范围外

1. 将代码仓库、Codex 运行环境整体迁移至 VPS；
2. 引入新的外部工作流引擎（Temporal/Prefect 等）；
3. 重构业务功能本身（本次以执行链路治理为主）。

## 4. 验收标准

### 4.1 功能性（Happy Path）

| AC 编号 | 验收标准 |
|---------|---------|
| AC-F-01 | 卡片 `done` 后可通过 `/hooks/wake` 在 10 秒内触发下一轮推进 |
| AC-F-02 | `bootstrap_kernel` 在本地模式下可完成 `seed -> activate -> dispatch -> done_gate -> done` 闭环 |
| AC-F-03 | `task-runner-state.json` 成为执行时状态真理源，执行路径不依赖 VK 读取 |
| AC-F-04 | `wt-flow.sh` 支持 `next/verify/list`，且主仓 dirty 时默认 fail-fast |
| AC-F-05 | `attempts` 与 `task-ledger.jsonl` 能完整记录每轮执行证据 |

### 4.2 异常/边界

| AC 编号 | 验收标准 |
|---------|---------|
| AC-E-01 | hooks token 缺失/过期时，系统返回 401 并触发告警，不发生静默成功 |
| AC-E-02 | 并发触发（wake+agent+cron）场景下，同一窗口仅允许一个执行轮次 |
| AC-E-03 | `task-runner-state.json` 写入中断后可通过 `.bak` 或备份恢复，无 JSON 损坏 |
| AC-E-04 | VK 同步失败时主链路持续可用，仅记录告警与待同步状态 |
| AC-E-05 | `BLOCKED` 状态可通过 Ch 16 SOP 完成恢复或回滚，不出现无限空转 |

### 4.3 性能与稳定性

| AC 编号 | 验收标准 |
|---------|---------|
| AC-N-01 | hooks 调用成功率 >= 99%（72 小时观察窗口） |
| AC-N-02 | 重复事件跳过率 < 5% |
| AC-N-03 | watchdog 触发频率 <= 3 次/天 |
| AC-N-04 | P0~P3 Exit Gate 全部可审计，证据链可追溯 |

## 5. 非功能需求

| 维度 | 需求 |
|------|------|
| 安全 | hooks 默认仅本地监听；Bearer Token 必填；OpenClaw 非 root 运行；敏感文件最小权限 |
| 可靠性 | 原子写入 + 文件锁 + 幂等键 + watchdog 兜底链路必须同时存在 |
| 可恢复性 | 备份/恢复脚本可在 30 分钟内完成闭环演练 |
| 可观测性 | 关键日志字段齐全（触发源、幂等键、卡片ID、结果、耗时）并可追踪 |
| 一致性 | `_active_task.json`、`vk_cards.json`、`task-runner-state.json` 需保持层级契约一致 |

## 7. 场景约束（运行场景与系统约束）

1. 本轮为**单主机执行模式**，OpenClaw、Codex、代码与本地依赖服务均在同一主机；
2. 不引入额外外部编排引擎，保留 OpenClaw 作为触发与编排核心；
3. 涉及仓外文件（`~/.openclaw*`）变更时，必须先备份再改动；
4. 大任务执行采用“Phase Exit Gate + 会话工作包”双门禁推进，禁止跨 Phase 跳步实施。
