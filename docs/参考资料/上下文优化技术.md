AI Agent 的上下文优化技术在 2025–2026 年已进入**系统化工程阶段**，核心目标是：**在长对话中保持高精度、低延迟、低成本的推理能力**，避免因上下文膨胀导致的“注意力稀释”（Context Rot）[ty-reference](https://www.qianwen.com/chat/1)。

以下是当前最前沿的 **五大上下文优化技术**，以及它们在 **LangChain / LangGraph** 中的具体实现方式：

---

## 🔑 一、主流上下文优化技术（2025–2026）

### 1. **上下文摘要压缩（Context Summarization）**

- **目的**：将历史对话压缩为关键信息摘要，保留任务目标、已完成步骤、待办事项。
- **原理**：当 token 使用 >80% 时，触发 LLM 对历史消息进行摘要，替换原始内容。
- **优势**：减少 60–90% token 消耗，避免无关细节干扰。

### 2. **工作流记忆（Workflow Memory）**

- **目的**：将“经验”固化为可复用策略（如“某 API 在 UTC+8 易超时”），用于未来相似任务。
- **原理**：任务结束后，自动生成“经验卡片”，存入向量库或结构化知识库。
- **优势**：Agent 越用越聪明，避免重复踩坑 [ty-reference](https://www.qianwen.com/chat/1)。

### 3. **工具输出缓存 + 引用（Tool Output Caching with ID Reference）**

- **目的**：避免重复调用相同工具，且不在上下文中存储冗余结果。
- **原理**：
    - 工具执行后，结果存入外部存储（如 Redis/DB）
    - 上下文仅保留 `tool_call_id: "tc_123"`
    - 后续需要时通过 ID 动态加载
- **优势**：上下文极简，支持跨会话工具结果复用 [ty-reference](https://www.qianwen.com/chat/1)。

### 4. **按需加载（Just-in-Time Retrieval）**

- **目的**：只在需要时加载相关信息，而非预加载全部数据。
- **原理**：上下文仅保留“指针”（如文件路径、URL、数据库查询语句），通过工具动态获取内容。
- **优势**：模拟人类“知道去哪查”，而非“记住所有” [ty-reference](https://www.qianwen.com/chat/2)。

### 5. **KV-Cache 优化（底层推理加速）**

- **目的**：降低模型推理延迟与成本。
- **原理**：
    - 固定提示前缀（避免时间戳破坏缓存）
    - 追加式上下文（保持 JSON 键顺序一致）
    - 显式缓存断点（手动标记可复用位置）
- **优势**：单 token 成本可降 10 倍（如 Claude Sonnet）[ty-reference](https://www.qianwen.com/chat/3)。

## 🛠 二、在 LangChain / LangGraph 中的实现

### ✅ 方案 1：使用 LangChain 1.0 的 `create_agent` + Middleware（推荐）

```python
from langchain.agents import create_agent
from langchain.agents.middleware import (
    SummarizationMiddleware,
    ToolOutputCachingMiddleware
)
from langgraph.checkpoint.postgres import PostgresSaver

# 1. 配置中间件
middleware = [
    SummarizationMiddleware(
        max_tokens_before_summary=3000,  # 触发摘要阈值
        summary_prompt="保留用户目标、已完成步骤、待办事项"
    ),
    ToolOutputCachingMiddleware(
        cache_backend=RedisCache()  # 缓存工具结果
    )
]

# 2. 创建带 checkpoint 的 agent
agent = create_agent(
    model="qwen3-max",
    tools=[search_tool, db_tool],
    middleware=middleware,
    checkpointer=PostgresSaver.from_conn_string("postgresql://...")
)

# 自动处理：摘要、缓存、状态持久化
result = agent.invoke({"messages": user_messages})
```

> ✅ **优势**：一行代码集成多种优化，官方维护，生产就绪。

### ✅ 方案 2：在 LangGraph 自定义图中手动实现（高灵活性）

#### 示例：实现“按需加载 + 摘要”

```python
from langgraph.graph import StateGraph, MessagesState
from langchain_core.messages import ToolMessage, AIMessage

def agent_node(state: MessagesState):
    messages = state["messages"]
    
    # 手动触发摘要（当 token > 5000）
    if get_token_count(messages) > 5000:
        summary = llm.invoke([
            {"role": "system", "content": "总结以下对话，保留目标和待办"},
            *messages
        ])
        # 替换历史为摘要 + 最近 2 条消息
        messages = [summary, messages[-2], messages[-1]]
    
    response = llm.invoke(messages)
    return {"messages": [response]}

def tool_node(state: MessagesState):
    last_msg = state["messages"][-1]
    if hasattr(last_msg, "tool_calls"):
        results = []
        for tc in last_msg.tool_calls:
            # 3. 工具结果不直接返回全文，而是存 DB + 返回 ID
            result = execute_tool(tc)
            tool_result_id = save_to_db(result)  # 存入 PostgreSQL
            
            # 上下文只放 ID
            results.append(ToolMessage(
                content=f"Result stored as ID: {tool_result_id}",
                tool_call_id=tc["id"]
            ))
        return {"messages": results}
    return {"messages": []}

# 构建图
builder = StateGraph(MessagesState)
builder.add_node("agent", agent_node)
builder.add_node("tools", tool_node)
builder.set_entry_point("agent")
builder.add_conditional_edges("agent", should_continue)
builder.add_edge("tools", "agent")

graph = builder.compile(checkpointer=PostgresSaver.from_conn_string(...))
```

> ✅ **优势**：完全控制优化逻辑，适合复杂业务场景。

### ✅ 方案 3：结合 RAG 实现“外部记忆”

```python
from langchain_community.vectorstores import Chroma
from langchain_core.runnables import RunnableLambda

# 将对话摘要存入向量库（作为长期记忆）
def save_memory(messages):
    summary = summarize_conversation(messages)
    vectorstore.add_texts([summary], metadatas={"session_id": "sess_123"})

# 检索相关记忆
def retrieve_memory(query):
    return vectorstore.similarity_search(query, k=1)

# 在 agent 节点中注入
def agent_with_memory(state):
    query = state["messages"][-1].content
    memory = retrieve_memory(query)
    
    enhanced_messages = [
        {"role": "system", "content": f"相关记忆：{memory}"},
        *state["messages"]
    ]
    return llm.invoke(enhanced_messages)
```

> ✅ 实现 **短期上下文 + 长期记忆** 的平衡 [ty-reference](https://www.qianwen.com/chat/3)。

## 一、AI Agent 最新主流「上下文优化」技术体系

> 目标：**对话轮次不断增加，但模型始终“记得该记得的、忘掉该忘掉的”**

可以归纳为 **5 大类 + 1 个趋势性方向**。

---

### 1️⃣ 分层记忆（Hierarchical Memory）【当前主流】

**核心思想**
把上下文分为不同“记忆层”，而不是一股脑塞进 prompt。

| 层级                | 内容           | 生命周期 |
| ----------------- | ------------ | ---- |
| Working Memory    | 最近几轮对话       | 短    |
| Episodic Memory   | 一次任务/会话的关键事实 | 中    |
| Semantic Memory   | 用户偏好、稳定事实    | 长    |
| Procedural Memory | 行为规则、工作流程    | 长    |

**效果**

* Prompt 更短
* 关键事实不丢
* 可控性强

**代表实践**

* LangChain Memory V2
* LangGraph + 自定义 State
* AutoGPT / CrewAI 的 memory 模型

---

### 2️⃣ 结构化记忆（Structured Memory）【精度最高】

**核心思想**
不是“存对话文本”，而是**提取结构化事实**。

❌ 低效：

```
用户说：我在杭州，有房贷
```

✅ 高效：

```json
{
  "city": "杭州",
  "has_mortgage": true
}
```

**技术关键**

* LLM → 信息抽取
* JSON / Pydantic / Schema 约束
* 与业务字段强绑定

**优势**

* 精准
* 可查询
* 可用于决策

---

### 3️⃣ 语义压缩（Context Compression）【大模型时代必备】

**核心思想**
“对话越长，信息密度越高，而不是 token 越多”。

常见方式：

#### ① Conversation Summarization

* 定期总结历史对话
* 保留意图、结论、约束条件

#### ② Progressive Summarization（递进摘要）

* 多次压缩，不是一次性

#### ③ Task-Oriented Summary

* 按“任务目标”总结，而非自然语言

**最新趋势**

* 用 **小模型** 专职做摘要
* 主模型只做推理

---

### 4️⃣ 语义检索式上下文（RAG Memory）【长会话标配】

**核心思想**

> 不把记忆放进 prompt，而是 **“需要时再取”**

流程：

1. 历史对话 → embedding
2. 存入向量库
3. 当前问题 → 检索最相关 K 条
4. 拼接到上下文

**关键优化点**

* 时间衰减权重
* 角色区分（user / system / tool）
* 主题标签

---

### 5️⃣ 意图感知上下文选择（Intent-Aware Context Selection）【Agent 专属】

**核心思想**

> 并非所有上下文都服务于当前问题

步骤：

1. 先识别 **当前用户意图**
2. 再选择相关上下文子集
3. 最后构建 Prompt

这在 **多 Agent / 多任务系统** 中尤为重要。

---

### 6️⃣ 🔥 最新趋势：State-based Context（状态驱动上下文）

**这是 LangGraph 兴起的根本原因**

上下文 ≠ 对话
上下文 = **系统状态**

例如：

```python
State = {
  "goal": "生成周报",
  "current_step": "收集数据",
  "facts": {...},
  "history_summary": "...",
}
```

模型每一步只看 **当前 State**，而不是全部历史。

## 二、LangChain 中如何实现上下文优化

### 1️⃣ 经典方式（不推荐长期使用）

```python
ConversationBufferMemory()
```

问题：

* Token 线性增长
* 易污染上下文

---

### 2️⃣ 推荐方式 1：ConversationSummaryMemory

```python
from langchain.memory import ConversationSummaryMemory

memory = ConversationSummaryMemory(
    llm=llm,
    return_messages=True
)
```

适用：

* 问答类
* 咨询类

---

### 3️⃣ 推荐方式 2：VectorStoreRetrieverMemory（RAG Memory）

```python
from langchain.memory import VectorStoreRetrieverMemory

memory = VectorStoreRetrieverMemory(
    retriever=vectorstore.as_retriever(search_kwargs={"k": 4})
)
```

适用：

* 长期多轮
* 历史事实回溯

```python
    city: str | None
```

