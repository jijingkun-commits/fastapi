# 全局代码优化计划 (Optimization Plan)

基于全量代码审查（排除 `ragflow` 目录），我制定了以下优化计划。本计划旨在提升系统的鲁棒性、可维护性和用户体验，而非盲目重构。

## 🛡️ Phase 1: 后端核心鲁棒性增强 (High Priority)

### 1.1 `ImageInsertionStreamProcessor` 边界情况防护
- **现状**: `ChatService` 中的流式处理器使用正则表达式匹配 `##N$$`。虽然实现了基本的缓冲逻辑，但在极端切分情况下（例如 `##` 在一个 chunk 末尾，`N$$` 在下一个 chunk 开头）可能存在脆弱性。
- **优化**: 
  - 引入更严格的状态机机制来处理跨 Chunk 的 Token 拼接。
  - 增加单元测试覆盖各种 Token 切分边界情况。

### 1.2 LangGraph 状态管理与数据一致性
- **现状**: `postprocess` 节点负责保存对话历史。
- **优化**: 
  - 确保 `postprocess` 在异常情况下也能执行（例如使用 `try-finally` 语义的图结构或错误处理节点），防止对话丢失。
  - 检查 `checkpointer` 与 MySQL 历史记录的一致性机制。

### 1.3 工具输出截断与提取优化
- **现状**: `chat_service.py` 中日志使用了 `TOOL_OUTPUT_STORAGE_LEN` 截断，但流式事件中传递了完整 output。
- **优化**: 
  - 明确分离 "日志/存储用摘要" 和 "逻辑用完整数据"。
  - 确保 `ImageInsertionStreamProcessor` 获取到的永远是未截断的完整 JSON，以免正则提取失效。

## ⚡ Phase 2: 前端状态管理与交互优化 (Medium Priority)

### 2.1 `useSSEStream` 逻辑解耦
- **现状**: `useSSEStream.ts` 文件过大（400+行），混合了 SSE 解析、消息状态更新、工具调用拼接、Thinking 标签解析等多种逻辑。
- **优化**: 
  - 抽离 `SSEParser` 为独立工具类。
  - 将 `handleThinking`（处理 `<think>` 标签拼接）逻辑提取为纯函数，并增加单元测试，确保后端流式返回格式变化时易于适配。

### 2.2 组件 Props 透传优化
- **现状**: `index.tsx` 向 `ChatInput` 传递了大量 Props（15+个），通过 Props Drilling 传递状态。
- **优化**: 
  - 使用 React Context (`ChatContext`) 或 Zustand 存储 UI 状态（如 `input`, `isLoading`, `useMultiAgent` 等），减少组件间耦合。

## 🏗️ Phase 3: 架构规范与配置管理 (Low Priority)

### 3.1 配置验证标准化
- **现状**: `config.py` 使用 `os.getenv` 直接获取并转换类型，缺乏统一校验。
- **优化**: 
  - 引入 Pydantic `BaseSettings` 来管理环境变量，自动处理类型转换和必填项校验，在启动时快速失败（Fail Fast）。

### 3.2 统一错误码与异常处理
- **现状**: API 层异常处理分散在各个 endpoint。
- **优化**: 
  - 建立全局异常处理器（Exception Handler），统一 API 错误响应格式 `{ "code": 400, "message": "...", "data": null }`。
