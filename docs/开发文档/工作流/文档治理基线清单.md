# 文档治理基线清单

> 更新时间：2026-03-10
> 目标：把文档治理从“哪里乱了修哪里”，收敛成一套固定执行顺序。

## 1. 当前治理目标

这一轮治理只做四件事，而且顺序固定：

1. **目录结构**：先把稳定文档、过程文档、运行态产物分家。
2. **内容格式**：再统一每一层该怎么写，不允许继续靠 `v2/v3/日期补丁` 叠内容。
3. **内容同步**：再让导航、守卫、文档同步规则跟新结构对齐。
4. **迁移收口**：最后才搬旧文件、清旧入口、补过渡说明。

一句人话：

- 先定“东西放哪儿”，
- 再定“东西怎么写”，
- 再定“怎么检查同步”，
- 最后才做“把旧东西搬过去”。

## 2. 分层基线

### 2.1 目录结构

| 层级 | canonical 位置 | 作用 |
|---|---|---|
| 稳定文档 | `docs/` | 当前有效、给人读的真理源 |
| 过程文档 | `workdocs/` | 需求、方案、任务拆解、评审、验收材料 |
| 运行态产物 | `.artifacts/` | `.state`、锁文件、生成结果、自动执行产物 |

### 2.2 迁移期旧路径

下面这些路径当前仍保留，但只算迁移期兼容入口：

- `docs/plans/`
- `docs/内部参考/迭代需求/`
- `docs/内部参考/任务拆解/`
- `docs/内部参考/任务拆解/<task_split_dir>/.state/`（当前已改为兼容 symlink）

### 2.3 内容格式

- 稳定文档默认原位修改，不追加 `增量需求 / 实现进展 / 补充说明`。
- 过程文档统一写在 `workdocs/` 或迁移期旧路径，不得反向替代稳定真理源。
- 运行态产物不进入 `docs/README.md` 与 `docs/SUMMARY.md` 主导航。

### 2.4 内容同步

- `docs/README.md` 与 `docs/SUMMARY.md` 只面向稳定文档。
- `scripts/docs_guard.py` 负责角色识别、稳定区污染扫描与 current_state 守卫。
- `scripts/check_doc_sync.sh` 负责“代码变更必须同步稳定真理源”，并明确过程文档不能替代主文档。

## 3. 当前基线问题清单

| 优先级 | 问题 | 影响 | 当前处理策略 |
|---|---|---|---|
| P0 | 稳定文档、过程文档、运行态产物混住 | 读者无法快速判断当前口径 | 先完成目录结构分层 |
| P0 | 旧过程路径仍在 `docs/` 主区 | 导航和真实职责容易打架 | 保留旧路径，但明确降级为迁移期入口 |
| P1 | 主文档历史增量段尚未清理干净 | `docs_guard` 会持续报存量债务 | 用 allowlist 托底，但 warning 持续可见 |
| P1 | 过程层与运行态根刚建立，团队习惯还没切换 | 后续新增文档仍可能落错层 | 在 README / SUMMARY / 工作流清单里同步强调 |
| P2 | 部分旧需求文档 TC / NFR 仍不完整 | 月度巡检噪音偏大 | 后续分轮收口，不阻断本轮分层改造 |

## 4. 执行顺序（固定）

### 第一步：目录结构

- 冻结 `docs/`、`workdocs/`、`.artifacts/` 三层边界。
- 收口 `docs/内部参考/` 只保留长期有效内部知识。
- 把旧过程目录明确降级为迁移期入口。

### 第二步：内容格式

- 稳定文档原位修改，不再靠补丁章节表达当前态。
- 过程文档按目录职责写，不再混进稳定主导航。
- 运行态产物从文档阅读路径中移走。

### 第三步：内容同步

- README / SUMMARY 只主推稳定区。
- docs_guard / check_doc_sync / doc_sync 规则跟新结构对齐。
- 过程文档变更只能算过程证据，不能充当稳定真理源同步。

### 第四步：迁移收口

- 迁移 `.state/.jsonl/.lock` 到 `.artifacts/`。
- 逐步把新需求 / 新方案 / 新任务拆解写入 `workdocs/`。
- 对旧入口保留最小过渡说明，后续再删旧路径。

## 5. 验收基线

每轮治理至少验证下面 4 项：

1. `python3 scripts/docs_guard.py --strict`
2. `bash scripts/check_doc_sync.sh --diff-range <base...head>`
3. `find docs -type f | rg '\\.(jsonl|lock)$|/\\.state/'` 结果为空
4. `test -d workdocs/需求 && test -d workdocs/方案 && test -d workdocs/任务拆解`

## 6. 回填要求

每完成一轮治理，必须回填：

- 完成了哪一步：目录结构 / 内容格式 / 内容同步 / 迁移收口
- 改动影响了哪些入口文档
- 还有哪些旧路径只是迁移期兼容
- 哪些 warning 是存量债务，何时收口
