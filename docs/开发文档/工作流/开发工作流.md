## 命令速查表

> 变更 `.cursor/commands/` 时必须同步更新此表。
> 触发方式差异：Claude Code / Cursor 使用 `/jjk-xxx`；Codex 使用 `/prompts:jjk-xxx`（由 `~/.codex/prompts/*.md` 提供）。
> Hook / 门禁分层、Git hooks、`pre-commit` 与 Codex / OMX hooks 的边界说明，统一见 `docs/开发文档/工作流/指令用法_实现方式_工程流全景手册.md` 第 `1.4` 节。

### 核心链路

| 命令 | 用途 | 典型上游 | 典型下游 |
|------|------|---------|---------|
| `/ask` | 兼容入口（已降级）；收到后立即并入 `/jjk-clarify` | 用户显式输入 `/ask` / 历史习惯 | `/jjk-clarify` |
| `/jjk-clarify` | 设计冻结（含 PRD-Lite `product_contract`，支持命令内探索+收敛） | 用户提问（可直接进入） | `/jjk-plan` |
| `/jjk-plan` | 正式规划（`requirements + implementation_plan`） | `/jjk-clarify`（已审批） | `/jjk-imp`、`/jjk-vkplan` |
| `/jjk-vkplan` | 并行拆解与看板落卡准备 | `/jjk-plan parallel` | `/jjk-vktodo` |
| `/jjk-vktodo` | create-only 幂等建卡到看板 | `/jjk-vkplan` | `/jjk-cardrun` |
| `/jjk-cardrun` | 串行卡片调度（主控 + 子代理 + verify/merge 收口） | `/jjk-vktodo` | `/jjk-verify`、`/jjk-create-pr` |
| `/jjk-imp` | 按计划编码（单任务） | `/jjk-plan` | `/jjk-review`、`/jjk-test` |
| `/jjk-imp-ws` | 按 WS 子任务编码（通常由 cardrun 调度） | `/jjk-cardrun` | `/jjk-review` |
| `/jjk-wtimp` | Worktree 隔离实现（大任务） | `/jjk-plan` | `/jjk-review`、`/jjk-verify` |

澄清分流速记：
1. 默认只用 `/jjk-clarify` 完成探索+冻结（不要求先跑 `brainstorming`）。
2. `/ask` 仅保留兼容别名语义，触发后立即并入当前 `/jjk-clarify` 会话。
3. 若需额外探索轮，仍在当前 `/jjk-clarify` 会话内完成。


### 工程流 DB 证据门禁主链（2026-03-08）

> 目标：DB 风险任务的证据契约必须从规划左移到验收，缺证据不能 `done`、不能 `merge`、不能 `PASS`。

| 阶段 | 强制输入/输出 | 失败码（示例） |
|------|------|------|
| `/jjk-plan` | `implementation_tasks[*].risk_tags`、`mandatory_evidence`、`acceptance_cmds[*].kind` | `PLAN_DB_EVIDENCE_MISSING` |
| `/jjk-vkplan` | `vk_cards.json.cards[*]` 继承 `risk_tags/mandatory_evidence`，拆链需 `cross_card_closure` | `VKPLAN_EVIDENCE_MAPPING_BROKEN`、`VKPLAN_DB_CHAIN_SPLIT_UNCLOSED` |
| `/jjk-cardrun` | done gate 消费 `acceptance_results + evidence_satisfied`，不再只看 `commit_sha` | `CARDRUN_DB_EVIDENCE_UNSATISFIED` |
| `/jjk-wtimp` | `cardrun_dispatch` 回执必须返回 typed `acceptance_results[*]` 与 `evidence_satisfied` | `WTIMP_DB_ASSERTION_MISSING`、`WTIMP_ANALYTICS_ROUTE_UNVERIFIED` |
| `/jjk-test` | 报告必须输出 `Required Evidence / Actual Evidence / Scripted Flow Status / Historical Gap vs Current Gap` | `TEST_DB_CHAIN_INCOMPLETE` |
| `/jjk-verify` | `PASS` 仅在 `mandatory_evidence` 全满足时成立 | `VERIFY_CHAT_DB_UNPROVEN`、`VERIFY_DATA_DB_UNPROVEN` |

主链顺序固定：`/jjk-plan -> /jjk-vkplan -> /jjk-cardrun -> /jjk-wtimp -> /jjk-test -> /jjk-verify`。

## 🔀 Worktree 隔离开发模式

### 概述

通过 git worktree 实现每次代码修改的分支隔离，完成后自动合并回主分支。保证每次改动可追溯、可原子回滚。

### 工具

- 脚本: `scripts/coder4/wt-flow.sh`
- 命令: `/jjk-wtimp`

### 生命周期

```
master (干净) -> 创建 feature/<slug> 分支 + worktree
                    -> 在 worktree 中编码、测试、提交
                        -> rebase master (处理前进)
                            -> merge --no-ff 回 master
                                -> 清理 worktree + 分支
```

### 脚本用法

```bash
# 创建隔离环境
bash scripts/coder4/wt-flow.sh create <slug> [base-branch]
# 例: bash scripts/coder4/wt-flow.sh create 20260226-add-export-api

# 查看当前会话
bash scripts/coder4/wt-flow.sh status

# 合并回主分支并清理
bash scripts/coder4/wt-flow.sh merge

# 合并但保留 worktree
bash scripts/coder4/wt-flow.sh merge --no-cleanup

# 仅清理（不合并）
bash scripts/coder4/wt-flow.sh cleanup

# 检查是否在主分支上（用于 hook 安全网）
bash scripts/coder4/wt-flow.sh guard
```

### 分支命名规范

- 格式: `feature/<YYYYMMDD>-<关键词>`
- 例: `feature/20260226-add-export-api`

### 状态文件

会话与运行态统一保存在 `docs/内部参考/任务拆解/<task_split_dir>/.state/<task_key>/`（如 `active-session-<session_id>.json`、`task-runner-state.json`）。

### 与现有流程的关系

| 命令 | 说明 |
|------|------|
| `/jjk-wtimp` | worktree 隔离 + 编码（自动检测是否需要 team 并行） + 自动合并 |
| `/jjk-imp` | 直接在当前分支编码（不隔离） |
| `/jjk-imp-ws` | vibe-kanban worktree 子任务（独立机制） |
| `/jjk-plan -> /jjk-imp -> /jjk-review(/jjk-verify)` | 标准全流程（不隔离） |

### MCP 配置治理

| 项 | 约定 |
|----|------|
| 权威配置源 | 当前 Codex 会话统一以 `/Users/jijingkun/.codex/config.toml` 为准 |
| 项目镜像 | 仓库内 `.mcp.json` 仅作为项目协作镜像，需与权威配置保持一致 |
| 敏感信息 | GitHub PAT 等敏感值只允许放在用户本地配置或本机环境变量，禁止提交到仓库 |
| 版本策略 | `vibe_kanban` 等本地 MCP 优先固定本机二进制或固定版本，禁止依赖 `@latest` 漂移 |
| 体检入口 | 修改 MCP 配置后必须执行 `bash scripts/check_mcp_health.sh`，先看 `OK / FAIL / BLOCKED` 再进入业务流程 |

补充说明：

- `github-mcp-server` 启动依赖 `GITHUB_PERSONAL_ACCESS_TOKEN`，缺失时应在体检阶段直接阻断。
- `vibe_kanban` 依赖本地安装的 MCP 二进制与对应运行态，当前默认通过 `BACKEND_PORT=3000` 连接本地宿主；若端口或运行态缺失，体检结果应标记为 `BLOCKED`，不得伪装为可用。

### Team 并行模式

当 `/jjk-wtimp` 检测到任务涉及多文件（>5）或多模块（>=2）时，自动建议切换到 team 并行模式：

- worktree 作为外层隔离，team 在 worktree 内并行编码
- teammates 不使用 `isolation: "worktree"`，避免嵌套
- teammates 按文件/模块划分职责，避免同文件冲突

### 异常处理

| 场景 | 行为 |
|------|------|
| master 有未提交变更 | 拒绝创建，提示先 commit 或 stash |
| 编码期间 master 前进 | merge 前自动 rebase，冲突时暂停并提示 |
| merge 冲突 | 自动 abort，保留 worktree，提示手动解决 |
| worktree 内有未提交变更 | 拒绝合并，提示先 commit |
