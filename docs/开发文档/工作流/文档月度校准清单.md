# 文档月度校准清单

> 用途：把文档治理从“想起来再修”变成固定巡检动作，防止目录结构、内容格式、内容同步再次漂移。  
> 执行频率：每月 1 次（建议每月第一个工作周）。  
> 更新时间：2026-03-10。

---

## 1. 每月固定检查什么

月度校准固定按下面四步做，不跳步骤：

1. **目录结构**
2. **内容格式**
3. **内容同步**
4. **迁移收口**

### 1.1 目录结构

检查 3 个 canonical 根目录是否仍然成立：

- `docs/`：稳定文档
- `workdocs/`：过程文档
- `.artifacts/`：运行态产物

### 1.2 内容格式

抽查稳定文档是否还在追加：

- `增量需求`
- `实现进展`
- `补充说明`
- `已执行 / 已实现`

### 1.3 内容同步

检查：

- README / SUMMARY 是否仍只服务稳定文档
- 过程文档是否被误当作稳定真理源
- `docs_guard` 与 `check_doc_sync.sh` 是否仍和当前目录结构一致

### 1.4 迁移收口

检查：

- 新增过程文档有没有优先写进 `workdocs/`
- 新增运行态文件有没有写进 `.artifacts/`
- 旧 `docs/**` 迁移期路径有没有继续失控膨胀

---

## 2. 标准流程

### 2.1 目录结构校验

```bash
python3 scripts/docs_guard.py --strict
```

通过标准：

1. `summary_coverage=100%`
2. `runtime_artifact_pollution=0`
3. `errors=0`

### 2.2 路径存在性快检

```bash
python3 scripts/docs_guard.py --check-paths
```

通过标准：

1. 不出现关键路径缺失告警（`app/`、`web/`、`scripts/`）
2. 占位示例不计为失败

### 2.3 内容同步校验

```bash
bash scripts/check_doc_sync.sh --diff-range origin/master...HEAD
```

通过标准：

1. 代码变更能映射到稳定真理源
2. 输出里不出现“缺少必须同步文档”
3. 过程文档不会被当成稳定真理源替代品

### 2.4 迁移收口快检

```bash
test -d workdocs/需求 && test -d workdocs/方案 && test -d workdocs/任务拆解
find docs -type f | rg '\.(jsonl|lock)$|/\.state/'
```

通过标准：

1. `workdocs/` 三个过程层目录存在
2. `docs/` 下不再出现真实 `.state/.jsonl/.lock` 运行态文件

---

## 3. 月度抽检（至少 4 条）

1. **目录结构**：新文档有没有继续写进旧过程路径，而不是 `workdocs/`。
2. **内容格式**：稳定文档有没有重新出现 `增量需求 / 实现进展` 标题。
3. **内容同步**：README / SUMMARY 是否还只导航稳定区。
4. **迁移收口**：`.artifacts/` 是否继续承接运行态，旧 `docs/**/.state` 是否仍只是兼容软链接。

## 4. 回填模板

每次执行后，在对应任务文档原位回填：

```text
### 月度校准回填（YYYY-MM-DD）
1. 目录结构：通过/失败（附摘要）
2. 内容格式：通过/失败（附摘要）
3. 内容同步：通过/失败（附摘要）
4. 迁移收口：通过/失败（附摘要）
5. 存量债务 warning：
6. 下月继续治理项：
```

---

## 5. 责任分工

1. 主责：当月文档 owner
2. 复核：至少 1 名非 owner 协作者
3. 收口标准：四步都完成回填后，再进入 `Done`
