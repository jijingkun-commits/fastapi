# 贡献指南

参与项目开发的规范和流程。

## 开发流程

1. 创建功能分支
2. 编写代码和测试
3. 提交 PR
4. 代码评审
5. 合并主分支

---

## 分支规范

| 分支类型 | 命名 | 示例 |
|----------|------|------|
| 功能 | feature/xxx | feature/todo-recurring |
| 修复 | fix/xxx | fix/chat-stream-error |
| 优化 | refactor/xxx | refactor/ai-module |

---

## 提交规范

使用约定式提交：

```
<type>(<scope>): <description>
```

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 |
| docs | 文档 |
| refactor | 重构 |
| test | 测试 |

示例：
```
feat(todo): 添加重复任务功能
fix(chat): 修复流式响应中断问题
docs(api): 更新待办 API 文档
```

---

## PR 要求

- 标题清晰描述变更
- 更新相关文档
- 添加/更新测试
- 通过 CI 检查

---

## 代码评审

重点关注：
- 代码风格一致性
- 类型安全
- 错误处理
- 文档完整性
