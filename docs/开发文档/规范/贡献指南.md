# 贡献指南

> 适用范围：本仓库代码与文档协作

---

## 1. 提交前检查

1. 先阅读 `AGENTS.md` 与 `.cursor/rules/*` 约束。
2. 变更代码时，同步更新对应文档。
3. 提交前执行最小验证命令：
   - 后端：`venv/bin/python -m pytest -q --maxfail=20`
   - 前端：`cd web && npx tsc --noEmit && npm run -s lint`
   - 文档：`venv/bin/python scripts/docs_guard.py --strict`

---

## 2. 分层协作原则

1. Endpoint 不直接写复杂业务逻辑，优先走 service。
2. Service 负责业务编排，Repository 负责数据访问。
3. Workflow 决策逻辑与 API 协议逻辑保持边界清晰。

---

## 3. 文档协作原则

1. 需求类文档统一落在 `docs/内部参考/迭代需求/` 与 `docs/产品文档/`。
2. 并行任务拆解统一落在 `docs/内部参考/任务拆解/`。
3. 新增文档需同步收录到 `docs/SUMMARY.md`。

---

## 4. 安全与合规

1. 严格遵守双数据库约束（`chat_db` vs `data_db`）。
2. 管理接口必须权限校验；开发工具接口仅开发/测试环境可用。
3. 禁止在日志或文档中泄露敏感凭据。

---

## 5. 提交流程建议

1. 小步提交、单一主题。
2. PR 说明必须包含：变更范围、风险、验证命令、回滚方式。
3. 若存在已知豁免项，需在 PR 明确记录有效期与责任人。
