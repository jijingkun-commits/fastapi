# 多智能体开发规范

> 更新时间：2026-03-13
> 定位：这份文档只回答“以后怎么写 agent”。如果你想看系统现在怎么跑、状态归谁、节点如何协作，请去看 [AI模块设计.md](../架构设计/AI模块设计.md)。

## 结论先行

写 agent 时，默认先让模型负责理解，让编排层负责执行，让 contract 负责约束，让 guardrail 负责拦截。不要再把关键词主路由、多层重复判定、双轨状态源和 speculative fallback 当成“更稳”的默认做法。

## 默认原则

1. **simple-first**：默认先单 agent、单 supervisor 或简单 workflow；只有简单方案被证据证明不够，才允许新增决策层。
2. **contract-first**：节点之间优先传结构化 contract，不靠自由文本 handoff 让下游自己猜语义。
3. **single semantic decider**：一次请求默认只允许一个主语义 owner；下游 executor 消费结果，不再重复做第二次主判定。
4. **guardrail only**：关键词、正则和 substring 只用于 guardrail、格式抽取和安全校验，不承担主语义路由。
5. **single source of truth**：运行态主语义状态默认只有一份真相，不允许 `intent_plan`、`task_description`、`frame`、fallback 并行主导。
6. **evidence before complexity**：想加 agent、加 planner、加 router、加 fallback，先拿出当前真实需求和真实任务样本证据。

## 常见坏味道

| smell_id | 说人话 | 为什么糟 | 默认处理 |
|---|---|---|---|
| `multi_decider_stack` | 同一语义问题被 planner/router/supervisor/expert 连续判两次以上 | 决策层重复，行为不可解释 | 阻断 |
| `keyword_primary_routing` | 关键词、正则、substring 负责主路由 | 同义表达一换就漂，系统越补越脆 | 阻断 |
| `dual_truth_design` | 新旧状态源同时决定运行态语义 | 最终到底信谁说不清 | 阻断 |
| `speculative_fallback` | 为“以后可能会用到”先埋 wrapper、兼容壳、双轨 fallback | 复杂度先涨，收益后补票 | 阻断 |
| `missing_eval_evidence` | 方案说自己更稳，但没有真实任务样本 | 没证据就只是感觉 | 阻断 |

## 允许的例外

只有同时满足下面条件，才允许从默认规则里做例外：

1. 简单方案已经评估过，而且确实满足不了当前目标。
2. 例外是当前真实需求，不是想象中的未来扩展。
3. 新增复杂度的 owner、依赖方向、状态归属和退役旧路径都说得清。
4. 有真实任务样本、shadow case 或回归集能证明收益。

如果做不到这四点，就不要升级复杂度。

## Review / Verify 怎么看

命中 agent 相关任务时，`jjk-review` 和 `jjk-verify` 不应该只看“功能能不能跑”，还要额外看三件事：

1. 有没有命中 `multi_decider_stack`、`keyword_primary_routing`、`dual_truth_design`、`speculative_fallback`、`missing_eval_evidence`。
2. 复杂度升级有没有证据，而不是一句“为了以后扩展”。
3. 真实任务样本有没有补上，而不是只跑一个 happy path。
