## 分层设计

### 分层职责速查

| 层级 | 目录 | 职责 |
|------|------|------|
| **API** | `app/api/v1/endpoints/` | HTTP 入口、参数校验、路由 |
| **Service** | `app/services/` | 业务编排、SSE 流处理 |
| **AI** | `app/ai/` | LangGraph 图、Agent、Tools |
| **Repository** | `app/repositories/` | 数据访问、CRUD 操作 |
| **Model** | `app/models/` | ORM 定义、表结构 |

### 1. API 层 (`app/api/`)

**职责**：HTTP 入口、参数校验、路由定义

```python
# 典型端点结构
@router.post("/chat/stream")
async def chat_stream(
    request: ChatRequest,
    user: User = Depends(get_current_user)
):
    return EventSourceResponse(
        chat_service.sse_stream(request, user.id)
    )
```

**关键点**：
- 使用 `Depends` 注入认证、数据库会话
- 返回 Pydantic Schema 自动序列化
- SSE 流使用 `EventSourceResponse`

### 2. Service 层 (`app/services/`)

**职责**：业务编排、跨模块协调

| 服务 | 文件 | 职责 |
|------|------|------|
| `ChatService` | `chat_service.py` | 管理聊天流程、SSE 事件生成 |
| `TodoService` | `todo_service.py` | 待办业务逻辑 |
| `SkillService` | `skill_service.py` | AI 技能库管理 |
| `LLMConfigService` | `llm_config_service.py` | LLM 提供商/模型配置（含缓存） |
| `SystemConfigService` | `system_config_service.py` | 系统配置管理（含缓存） |
| `PermissionService` | `permission_service.py` | 数据访问权限控制 |

**设计原则**：
- Service 调用 Repository，不直接操作 ORM Session
- Service 可调用其他 Service，但避免循环依赖

### 3. Repository 层 (`app/repositories/`)

**职责**：数据访问、CRUD 操作

```python
class TodoRepository:
    def __init__(self, db: Session):
        self.db = db
    
    def create(self, user_id: int, data: dict) -> Todo:
        todo = Todo(user_id=user_id, **data)
        self.db.add(todo)
        self.db.commit()
        return todo
    
    def find_by_id(self, todo_id: int) -> Optional[Todo]:
        return self.db.query(Todo).filter(Todo.id == todo_id).first()
```

**设计原则**：
- 每个 Repository 对应一个聚合根
- 返回 ORM 模型对象，不返回字典

### 4. Model 层 (`app/models/`)

**职责**：ORM 定义、表结构

使用 SQLAlchemy 2.0 `Mapped` 语法：

```python
class Todo(Base):
    __tablename__ = "t_todo"
    
    id: Mapped[int] = mapped_column(primary_key=True)
    user_id: Mapped[int] = mapped_column(Integer, nullable=False)
    title: Mapped[str] = mapped_column(String(500), nullable=False)
    status: Mapped[str] = mapped_column(String(50), default="pending")
```

## 依赖注入

使用 FastAPI 的 `Depends` 实现依赖注入：

```python
# 获取数据库会话
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

# 获取当前用户
async def get_current_user(
    token: str = Depends(oauth2_scheme),
    db: Session = Depends(get_db)
) -> User:
    return verify_token(token, db)
```

## 异常处理

集中在 `app/core/handlers.py` 和 `app/core/exceptions.py`：

### 业务异常

```python
# app/core/exceptions.py
class BusinessException(Exception):
    """统一业务异常基类。"""
    def __init__(
        self,
        code: str,
        message: str,
        status_code: int = 400,
        details: Optional[dict] = None
    ):
        self.code = code
        self.message = message
        self.status_code = status_code
        self.details = details
```

### 异常处理器

| 异常类型 | 处理方式 |
|----------|----------|
| `BusinessException` | 返回 `{code, message, details}` + 对应状态码 |
| `HTTPException` | 返回对应状态码和消息 |
| `RequestValidationError` | 422 + 详细字段错误 |
| 未知异常 | 500 + 日志记录 |

## 系统级幂等中间件

### 设计目标

将幂等逻辑从具体业务代码迁出，由系统层统一处理，所有写请求共享同一机制。

### 关键设计

| 配置项 | 说明 |
|--------|------|
| **幂等键来源** | HTTP Header `Idempotency-Key` |
| **作用范围** | 默认对 `POST/PUT/PATCH/DELETE` 生效；未提供 header 则跳过 |
| **判定维度** | `key + endpoint + user_id` |
| **重复策略** | 重复请求直接返回 `409 Conflict`，不进入业务逻辑 |
| **状态管理** | 中间件在响应结束后标记 `completed`；异常标记 `failed` |

### 代码位置

```
app/core/middlewares/idempotency.py   # 中间件实现
app/core/middleware.py                # 中间件注册
app/repositories/idempotency_repo.py  # 数据访问层
app/models/idempotency_key.py         # ORM 模型
```

### 使用方式

前端在请求头中添加：

```
Idempotency-Key: <uuid>
```

后端自动处理：
1. 解析请求头，提取用户身份
2. 调用 `idempotency_repo.try_start` 检查是否重复
3. 重复请求返回 409；首次请求放行
4. 响应完成后自动标记状态

### StreamingResponse 支持

对于流式响应（如 SSE），中间件包装 `body_iterator`：
- 流正常结束 → 标记 `completed`
- 流异常中断 → 标记 `failed`

## 消息同步与去重机制

### 数据流

对话消息在三个环节流转：

```
流式输出 (SSE) → 数据库保存 (postprocess) → 历史加载 (API)
```

### 同步保障机制

| 机制 | 实现位置 | 作用 |
|------|----------|------|
| 同步追踪日志 | `chat_service.py`, `chat_repo.py`, `chat_api.py` | 通过 `[SYNC-TRACE]` 日志和 content hash 快速定位不一致 |
| 结构化数据收集 | `chat_service.py` | 流式过程中收集 result 事件，确保 done 事件包含完整数据 |
| Hash 去重 | `chat_repo.py` | 使用 MD5 短 hash 避免微小差异导致重复保存 |
| extra_data 更新 | `chat_repo.py` | 内容相同但 extra_data 不同时更新已存在消息 |

### 关键代码

**去重检查**（`chat_repo.py`）：

```python
def _content_hash(content: str) -> str:
    """计算内容的短 hash。"""
    return hashlib.md5(content.strip().encode()).hexdigest()[:8]

# 检查最近的消息是否有相同 hash
for msg in recent_messages:
    if _content_hash(msg.content or "") == content_hash:
        # 跳过重复保存
        break
```

**Thinking 内容处理**（`chat_repo.py`）：

```python
# 将 thinking 内容包装在 <think> 标签内保存
if thinking and "<think>" not in ai_content:
    ai_content = f"<think>\n{thinking}\n</think>\n\n{ai_content}"
```
