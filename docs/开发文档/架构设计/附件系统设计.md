## 1. 概述

统一智能附件系统允许用户在聊天中上传图片、表格、文档等多种文件。系统负责文件的安全存储、访问代理以及上下文注入，使 AI Agent 能够感知并处理这些文件。

## 2. 系统流程

### 2.1 文件上传

1.  **上传接口**: `POST /api/v1/upload`
2.  **存储**: 文件被上传至 MinIO 对象存储的 `assets` 桶中。
    *   路径规则: `{user_id}/{thread_id}/images/{unique_name}`
3.  **返回**: 返回一个内部代理 URL，例如 `/api/v1/assets/proxy/...`。此 URL 用于前端展示和后续 Agent 引用。

### 2.2 限制与规范

*   **文件大小**: 单个文件最大支持 **50MB** (代码验证: `MAX_FILE_SIZE = 50 * 1024 * 1024`)。
*   **支持格式**:
    *   **图片**: JPG, PNG, GIF, WEBP
    *   **文档**: Excel, CSV, PDF, Word, TXT, JSON

### 2.3 上下文注入 (Context Injection)

当用户发送带附件的消息时，`ChatService` 会自动处理：

1.  **图片处理**: 转换为 Markdown 图片格式 `![name](url)` 并插入 Prompt，同时提示 `(请使用 analyze_image 工具分析此图片...)`。
2.  **文件处理**: 将文件元数据（名称、类型、URL）追加到 Prompt，并根据 MIME 类型给出提示。
    *   例如 Excel/CSV 会提示: `(Hint: Use the read_uploaded_file tool to read this file)`。

## 3. 关键组件

### 3.1 Upload API (`upload_api.py`)

*   负责校验文件类型和大小。
*   生成 UUID 文件名防止冲突。
*   对接 MinIO SDK 进行流式上传。

### 3.2 Chat Service (`chat_service.py`)

*   `stream` 方法接收 `attachments` 参数。
*   解析 Attachment 对象，根据 MIME 类型分类处理。
*   **Prompt Engineering**: 动态构建 Prompt，确保 Agent 知道它拥有哪些文件资源以及如何使用。

### 3.3 Agent Tools

Agent 通过以下工具与附件交互：
*   **Vision Tool**: 通过 URL 下载图片并调用多模态模型分析。
*   **File Tools**: 如 `read_uploaded_file` 或 Python 代码解释器，通过 URL 读取文件内容进行分析。
