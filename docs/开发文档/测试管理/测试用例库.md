## 1.1 工程流 DB 证据矩阵（2026-03-08）

> 本节是 `/jjk-test` 输出模板的文档真理源，所有 DB 风险任务必须在测试报告中显式对账，不允许“只跑命令、不交证据”。

| 风险标签（risk_tags） | Required Evidence（必需证据） | Actual Evidence（本轮实得证据） | Scripted Flow Status | Historical Gap vs Current Gap | 缺口失败码 |
|:--|:--|:--|:--|:--|:--|
| `chat_db` | `chat_db_write_read`、`chat_db_roundtrip_assertion` | `acceptance_results.kind=chat_db` 且 `exit_code=0` | 若 `mandatory_evidence` 含 `scripted_flow`，必须给出脚本执行证据 | 需区分“历史待修”与“本轮新增/未修” | `TEST_DB_CHAIN_INCOMPLETE` |
| `data_db` | `data_db_route_sql_result`、`data_db_permission_assertion` | `acceptance_results.kind=data_db` 且 `exit_code=0` | 同上，脚本链路不可缺席 | 同上 | `TEST_DB_CHAIN_INCOMPLETE` |
| `chat_db + scripted_flow` | `chat_db_*` + `scripted_flow` | `chat_db` 证据 + `scripted_flow` 证据 | `PASS` 仅在脚本链路命中时成立 | 缺脚本证据归类为“本轮缺口” | `TEST_DB_CHAIN_INCOMPLETE` |
| `data_db + scripted_flow` | `data_db_*` + `scripted_flow` | `data_db` 证据 + `scripted_flow` 证据 | 同上 | 同上 | `TEST_DB_CHAIN_INCOMPLETE` |

### 1.2 Scripted Flow 注册来源

1. 脚本链路注册表：`docs/开发文档/测试管理/脚本链路证据注册表.md`
2. 报告必须逐项回填：`Required Evidence` / `Actual Evidence` / `Scripted Flow Status` / `Historical Gap vs Current Gap`
3. DB 风险任务若 `mandatory_evidence` 未被 `Actual Evidence` 覆盖，测试阶段直接 `FAIL_FAST(TEST_DB_CHAIN_INCOMPLETE)`

## 5. 测试案例执行顺序（推荐）

1. **门禁阶段**: 执行 `L0`（环境、配置、DB、LLM）确保可测。
2. **基础稳定性阶段**: 执行 `L1` + `L2`，确认认证/会话/待办主链路可用。
3. **数据与安全阶段**: 执行 `L3`，重点关注 SQL 安全与权限边界。
4. **治理能力阶段**: 执行 `L4`，验证管理后台配置闭环。
5. **智能体鲁棒性阶段**: 执行 `L5`，验证技能召回、上下文预算、回退策略。
6. **前端体验回归**: 在上述链路通过后执行 Playwright 全量；若 `auth.setup` 失败，停止后续 UI 用例并先修复认证前置。
