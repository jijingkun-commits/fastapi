## 0.9 最近补充回归（2026-03-08）

- 复合查询下 `external.lookup + data.query` 最终答复不得重复标签链或 Markdown 噪声。
- 单行 `sql_result` 正文只允许简明摘要，详细明细交由结构化表格卡片呈现。
- SQL 结果卡片在聊天流内应与正文同层左对齐，不再使用居中窄卡样式。
- `data.query` 运行态合同只认 `pending_handoff.frame.query_text`；`task_description` 不再作为 data 子任务上下文恢复来源。
- `frame.query_text` 必须是自然语言子任务描述，禁止直接填写 SQL；若命中 SQL-like handoff，Router 必须阻断并回流 Supervisor。
- `external.lookup` 用户可见正文只认 `payload.display_markdown`；在复合问题中若 Supervisor 已先回答可直答子问题，必须优先保留该段用户可见 Markdown，禁止再从天气/站点特化解析里“猜”最终正文；raw tool 文本只允许作为兜底证据，不得把 handoff 痕迹或原始站点导航噪声拼进最终答复；internal handoff HumanMessage 不得落库为用户历史消息。
- 天气/实时信息段允许保留换行与 Markdown 强调；`summary` 只用于覆盖率与匹配，用户可见正文应走富文本展示字段。
- `coverage_report` 必须同时保留 `goal_results` 与 `goal_attempts`；未完成 goal 若已有失败证据，最终答复必须直接展示失败原因，不得统一退化成“缺少可用结果”。
- `data.query` handoff 已完整时，`data_graph` 不得再次依赖意图分析模型；若模型不可用且没有 handoff contract，可输出稳定失败文案，但不得伪装成 `free_query` 继续生成 SQL。
