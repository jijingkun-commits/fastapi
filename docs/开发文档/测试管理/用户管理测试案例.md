## 1. TC-USER-01: 用户列表查看

### 1.1 分页查询

**前置条件**: 管理员已登录

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 访问 `/admin/users` | 页面显示用户列表 |
| 2 | 验证列表字段 | 显示 ID、用户名、手机号、系统角色（role）、数据角色（data_role）、机构、部门、状态、创建时间 |
| 3 | 检查分页 | 列表支持分页，每页默认显示数据 |

### 1.2 搜索功能

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 输入用户名关键词搜索 | 列表筛选显示匹配用户 |
| 2 | 清空搜索框 | 恢复显示全部用户 |

### 1.3 权限验证

| 属性 | 值 |
|------|------|
| **关联需求** | [用户管理需求](../../产品文档/用户管理需求.md) 中的管理员权限与用户列表访问控制 |
| **关联设计** | `docs/开发文档/架构设计/后端架构.md` 中的鉴权与后台接口分层 |
| **风险标签** | `authz`, `ui-api-consistency`, `isolation`, `error-contract` |
| **风险等级** | P0 |
| **输入 / 触发** | 1. 无 Token 访问 `/api/v1/users`<br>2. 普通用户 Token 访问<br>3. 管理员 Token 访问 |
| **主结果断言** | 1. 未登录返回 401<br>2. 普通用户返回 403<br>3. 管理员返回用户列表 |
| **失败语义断言** | 不允许出现“页面拦截了但 API 还能拿数据”或“API 拦了但页面仍展示缓存用户列表”的不一致情况 |
| **状态 / 副作用断言** | 被拒绝请求不应暴露用户列表字段、总量统计或调试信息；若系统记录审计，应保留拒绝轨迹 |
| **自动化建议** | `tests/api/test_auth.py` + `web/e2e/user-admin.spec.cjs` 联动验证 |
| **退化信号** | 普通用户能看到 `/admin/users` 列表、搜索结果或用户详情 |

### 1.4 TC-USER-01-STATE: 页面状态反馈一致性（2026-02 新增）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 首次进入 `/admin/users` | 显示统一 loading 状态组件 |
| 2 | 模拟接口返回空列表 | 展示 empty 状态，含“创建用户”动作按钮 |
| 3 | 模拟接口返回 403 | 展示 forbidden 状态，提示无访问权限 |
| 4 | 模拟接口异常（500/断网） | 展示 error 状态，点击“重新加载”可再次请求 |

## 4. TC-USER-04: 用户登出

### 4.1 正常登出

**前置条件**: 用户已登录

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 点击头像下拉菜单 | 显示「退出登录」选项 |
| 2 | 点击「退出登录」 | 页面跳转到登录页 |
| 3 | 使用旧 Token 调用 API | 返回 401 无效令牌 |

### 4.2 Token 黑名单

| 属性 | 值 |
|------|------|
| **关联需求** | [用户管理需求](../../产品文档/用户管理需求.md) 中的登录态失效与安全退出 |
| **风险标签** | `session`, `token-blacklist`, `security`, `error-contract` |
| **风险等级** | P0 |
| **输入 / 触发** | 1. 执行登出<br>2. 登出后检查数据库或黑名单存储<br>3. 使用旧 Token 调用受保护接口 |
| **主结果断言** | Token JTI 已加入黑名单表，旧 Token 调用受保护接口返回 401/403 |
| **失败语义断言** | 不允许出现“退出成功提示已返回，但后端仍接受旧 Token”的假登出 |
| **状态 / 副作用断言** | 旧 token 不再通过鉴权；重新登录后新 token 正常可用 |
| **自动化建议** | 新增 api 回归，覆盖 logout -> old token denied -> new token accepted |
| **退化信号** | 登出后仍可访问用户信息、用户列表或批量删除接口 |

## 6. API 测试用例

### 6.1 用户列表 API

```bash
# 正常请求
GET /api/v1/users?page=1&page_size=10
Authorization: Bearer {admin_token}
# 预期: 200, 返回分页用户列表

# 无权限请求
GET /api/v1/users
# 预期: 401
```

### 6.2 创建用户 API

```bash
POST /api/v1/users
Authorization: Bearer {admin_token}
Content-Type: application/json
{
  "username": "newuser",
  "password": "password123",
  "role": "user",
  "data_role": "staff",
  "org_code": "ORG001",
  "dept_code": "D001"
}
# 预期: 201, 返回新用户信息（含 role/data_role）
```

### 6.3 禁用/启用用户 API

```bash
PATCH /api/v1/users/{id}/status
Authorization: Bearer {admin_token}
Content-Type: application/json
{"is_active": false}
# 预期: 200, 返回更新后的用户信息
```

### 6.4 登出 API

```bash
POST /api/v1/logout
Authorization: Bearer {user_token}
# 预期: 200, {"message": "登出成功"}
```

### 6.5 批量删除对话 API

```bash
DELETE /api/v1/chat/threads/batch
Authorization: Bearer {user_token}
Content-Type: application/json
{"thread_ids": ["id1", "id2"]}
# 预期: 200
```

### 6.6 双角色权限属性 API

```bash
# 查询用户列表（关注 role/data_role 字段）
GET /api/v1/users?page=1&page_size=10
Authorization: Bearer {admin_token}
# 预期: 200, items[] 包含 role/data_role/org_code/dept_code

# 创建用户（不传 data_role，验证默认值）
POST /api/v1/users
Authorization: Bearer {admin_token}
Content-Type: application/json
{
  "username": "staff_auto",
  "password": "password123",
  "role": "user"
}
# 预期: 201, data_role 默认 staff
```
