## 2. 测试环境

### 服务地址

| 服务 | 地址 | 说明 |
|------|------|------|
| 后端 API | `http://127.0.0.1:${TEST_BACKEND_PORT}` | FastAPI（主分支默认 8000） |
| 前端 | `http://127.0.0.1:${TEST_FRONTEND_PORT}` | Next.js（主分支默认 3000） |
| PostgreSQL | `localhost:5432` | 数据库 chat_db |
| MinIO | `localhost:19000` | 对象存储 |
| RAGFlow | `localhost:9380` | 知识库服务 |

> **注意**: 主分支（`main`/`master`）固定使用 `3000/8000`；子任务 worktree 可使用 `scripts/vk_ports.sh` 自动分配端口。

### Vibe Kanban 多 worktree 端口约定

- 主分支：`TEST_FRONTEND_PORT=3000`、`TEST_BACKEND_PORT=8000`
- 子任务 worktree：
  - 先执行 `bash scripts/vk_setup.sh` 生成 `.env.vk.local` / `web/.env.vk.local`
  - 执行测试前建议 `eval "$(bash scripts/vk_ports.sh --export)"`，确保端口变量与当前 worktree 一致
  - 执行 `bash scripts/vk_dev.sh up` 启动本机服务
  - 若本地 `venv` 不可用（如仅有 `Scripts/`），`vk_setup.sh` 会自动准备 `.vibe/venv`
  - 测试工具读取以下变量：
    - `TEST_BACKEND_PORT` / `TEST_FRONTEND_PORT`
    - `E2E_API_BASE` / `LIVE_API_BASE`
    - `PLAYWRIGHT_BASE_URL`
    - `VK_RUNTIME_VENV`（存在时优先作为 Python 运行环境）

## 3. 运行测试

### 后端测试

```bash
# 安装测试依赖（建议在选定 venv 内执行）
pip install -e ".[dev]"

# 推荐：统一先解析仓库测试解释器
PYTHON_BIN="$(bash scripts/repo_python.sh)"

# 解释器优先级：VK_RUNTIME_VENV -> venv -> .venv -> .vibe/venv -> python3/python

# 开发期定向红绿验证（默认 no-cov，避免全局 coverage 噪音）
bash scripts/pytest_targeted.sh app/tests/test_todo_graph_integration.py -q

# 最终收口验证（可保留 coverage / 默认门禁语义）
"${PYTHON_BIN}" -m pytest -q

# 或按关键字筛选相关测试
"${PYTHON_BIN}" -m pytest -q app/tests -k todo

# 显示详细输出
"${PYTHON_BIN}" -m pytest -v
```

### 前端 E2E 测试 (Playwright)

```bash
cd web

# 推荐：先注入当前 worktree 端口，避免回落到 3000/8000
eval "$(bash ../scripts/vk_ports.sh --export)"
export TEST_BACKEND_PORT="${VK_BACKEND_PORT:-${TEST_BACKEND_PORT:-8000}}"
export TEST_FRONTEND_PORT="${VK_FRONTEND_PORT:-${TEST_FRONTEND_PORT:-3000}}"
export PLAYWRIGHT_FRONTEND_PORT="${PLAYWRIGHT_FRONTEND_PORT:-$TEST_FRONTEND_PORT}"
export PLAYWRIGHT_BASE_URL="${PLAYWRIGHT_BASE_URL:-http://127.0.0.1:${TEST_FRONTEND_PORT}}"

# 执行全部测试
npm test

# 可视化界面（推荐调试时使用）
npm run test:ui

# 执行单个测试文件
npx playwright test todo.spec.cjs

# 执行特定测试文件（有界面）
npx playwright test todo.spec.cjs --headed

# 生成 HTML 报告
npx playwright show-report

# 调试模式（带 Inspector）
npx playwright test --debug

# 查看测试 trace
npx playwright show-trace test-results/*/trace.zip
```

**测试文件列表**:

| 文件 | 用途 | 对应用例 |
|------|------|---------|
| `todo.spec.cjs` | 待办基础 CRUD | TC-CRUD-01~03 |
| `todo-component.spec.cjs` | UI 组件测试 | TC-UI-* |
| `todo-multi-turn.spec.cjs` | 多轮对话 | TC-MULTI-* |
| `todo_agent_stress_test.spec.cjs` | 复杂场景压力测试 | TC-STRESS-01 |
| `chat.spec.cjs` | 聊天基础功能 | - |
| `chat_sync.spec.cjs` | 对话同步 | - |

### AI 对话测试

```bash
# API 模式测试（待办 API）
"${PY_VENV}/bin/python" -m pytest -q tests/api/test_todo_api.py

# 意图分析测试（无需数据库）
"${PY_VENV}/bin/python" -m pytest -q app/tests/test_todo_multiround.py -k test_intent_analysis

# Playwright E2E 压力测试
cd web && npx playwright test e2e/todo_agent_stress_test.spec.cjs --headed
```

## 3.1 工程流证据输出规范（`/jjk-test` 对齐）

### 必填报告字段

1. `Required Evidence`：来自 `implementation_plan.mandatory_evidence` 的必需证据集合。
2. `Actual Evidence`：本轮实际执行结果（以 `acceptance_results` 与脚本输出为准）。
3. `Scripted Flow Status`：脚本链路是否执行、是否命中必需断言、失败原因。
4. `Historical Gap vs Current Gap`：区分历史遗留缺口与本轮新增缺口，避免把旧问题伪装为本轮通过。

### DB 风险任务 fail-fast 规则

- 命中 `risk_tags=chat_db` 但缺 `chat_db` 类证据：`TEST_DB_CHAIN_INCOMPLETE`
- 命中 `risk_tags=data_db` 但缺 `data_db` 类证据：`TEST_DB_CHAIN_INCOMPLETE`
- `mandatory_evidence` 包含 `scripted_flow` 但脚本未执行或无断言证据：`TEST_DB_CHAIN_INCOMPLETE`

### 推荐定向验证命令

```bash
bash scripts/repo_python.sh
bash scripts/pytest_targeted.sh tests/unit/test_coder4_wtimp_dispatch_bridge.py tests/unit/test_coder4_wt_flow_verified_state.py -q
```

> 开发期定向回归禁止混入 coverage；coverage 仅用于最终收口阶段。

## 5. 启动命令

### 推荐：Vibe Kanban 多 worktree 本机脚本

```bash
# 初始化当前 worktree（复制本地配置 + 生成端口变量）
bash scripts/vk_setup.sh

# 启动 backend + web
bash scripts/vk_dev.sh up

# 查看状态
bash scripts/vk_dev.sh status

# 清理当前 worktree 启动进程
bash scripts/vk_cleanup.sh
```

### 手工启动（备用）

```bash
# 后端（主分支建议固定 8000）
PY_VENV="${VK_RUNTIME_VENV:-venv}"
if [ ! -x "${PY_VENV}/bin/uvicorn" ] && [ -x ".vibe/venv/bin/uvicorn" ]; then
  PY_VENV=".vibe/venv"
fi
ENV=dev API_PUBLIC_URL=http://127.0.0.1:${TEST_BACKEND_PORT:-8000}/public \
"${PY_VENV}/bin/uvicorn" app.main:app --reload --host 127.0.0.1 --port ${TEST_BACKEND_PORT:-8000}

# 前端（主分支建议固定 3000）
cd web
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:${TEST_BACKEND_PORT:-8000} npm run dev -- -p ${TEST_FRONTEND_PORT:-3000}
```

## 7. 常见问题与修复

### 7.1 环境配置问题

| 问题 | 症状 | 修复方案 |
|------|------|---------|
| 前后端端口不匹配 | 前端发送请求失败 | 修改 `web/.env.local`（或 worktree 的 `web/.env.vk.local`）中的 `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:${TEST_BACKEND_PORT:-8000}` |
| Pydantic V2 迁移 | `ImportError: cannot import BaseSettings` | 改为 `from pydantic_settings import BaseSettings` |
| 模块导入冲突 | `module has no attribute 'STREAMING'` | 在 `__init__.py` 中重新导出常量 |

### 7.2 路由问题排查

当待办请求未被正确路由时：

1. **检查后端日志**
   ```bash
   tail -f logs/assistant.log | grep -E "(supervisor|todo_expert)"
   ```

2. **检查 Supervisor Prompt**
   - 文件: `app/ai/prompts/agent_prompts.py`
   - 确认决策树中"待办事项管理"节点存在

3. **恢复原始代码**
   ```bash
   git checkout app/ai/prompts/agent_prompts.py
   git checkout app/ai/workflow/multi_agent_graph.py
   ```

### 7.3 调试原则

> **先检查配置和 Prompt，再考虑修改代码架构。**

| 顺序 | 检查项 | 说明 |
|------|--------|------|
| 1 | 服务状态 | `curl http://127.0.0.1:${TEST_BACKEND_PORT:-8000}/health` |
| 2 | 端口配置 | `web/.env.local`（或 `web/.env.vk.local`）与后端端口一致 |
| 3 | Prompt 文件 | 核心决策树未被修改 |
| 4 | 代码逻辑 | 最后考虑修改架构 |
