|-----|---|

## 3. SQL 生成测试

### TC-AD-02: 基础 SQL 生成

| 属性 | 值 |
|-----|---|
| **前置条件** | Schema 已同步，贷款相关表可用 |
| **输入** | "查询贷款余额" |
| **步骤** | 1. 在聊天界面输入"查询贷款余额"<br>2. 系统识别为数据查询意图，路由到数据专家<br>3. 观察返回结果 |
| **预期行为** | 1. 生成的 SQL 包含聚合函数（如 `SUM`）<br>2. 查询目标表为贷款相关表<br>3. SQL 语法正确，可执行<br>4. 返回贷款余额数值结果 |
| **验证方法** | 检查生成的 SQL 语句和执行结果是否合理 |

### TC-AD-03: 多维分析（GROUP BY）

| 属性 | 值 |
|-----|---|
| **前置条件** | 存款表包含分行字段 |
| **输入** | "按分行统计存款余额" |
| **步骤** | 1. 输入查询<br>2. 等待 SQL 生成和执行 |
| **预期行为** | 1. 生成带 `GROUP BY` 的 SQL<br>2. 分组字段为分行（branch）<br>3. 结果以表格或列表形式展示，每行对应一个分行<br>4. 数据按分行维度聚合 |
| **验证方法** | 手动执行生成的 SQL，与系统返回结果对比 |

### TC-AD-04: 意图解析与澄清（银行业务场景）

| 属性 | 值 |
|-----|---|
| **输入** | "查询贷款余额" |
| **步骤** | 1. 输入模糊查询（未指定时间范围）<br>2. 观察系统是否主动澄清 |
| **预期行为** | 1. 识别为业务数据查询（intent 含 `free_query`）<br>2. 指标识别为"贷款余额"<br>3. 路由到数据专家（`assign_to_data_expert`）<br>4. 若未指定时间范围，返回澄清提示（如"请指定时间范围"） |
| **业务口径** | 贷款余额为对公/零售核心指标，需时间区间与可选维度（分行、产品线等） |
| **数据库验证** | 检查 LLM 生成的 SQL 中是否自动添加了合理的时间过滤条件 |

### TC-AD-14: 元数据问句澄清护栏（库表统计）

| 属性 | 值 |
|-----|---|
| **输入** | "查询我数据库中一共有几张表" |
| **步骤** | 1. 发送库表元数据问句<br>2. 观察意图分析阶段返回字段 |
| **预期行为** | 1. 识别为元数据查询并进入 `free_query -> schema` 路由<br>2. 不应返回“请补充指标和时间范围”类澄清<br>3. `query_context.is_schema_metadata_query=true` 便于排障观测 |
| **自动化入口** | `tests/unit/test_data_graph_clarify_guard.py::test_schema_metadata_query_should_not_require_metric_and_time` |

### TC-AD-07: 同指标多轮追问（总量→TopN）

| 属性 | 值 |
|-----|---|
| **前置条件** | 指标 `贷款余额` 已配置模板（`SUM(prin_bal)`），客户维度映射为 `ecif_cust_no` |
| **步骤** | 1. 输入"查询2025年6月30日的贷款余额"<br>2. 在同线程继续输入"查询2025年6月30日贷款余额前10名的客户" |
| **预期行为** | 1. 第一轮返回总量值（单行聚合）<br>2. 第二轮仍命中"贷款余额"指标<br>3. 第二轮 SQL 在同一过滤条件下自动增加 `GROUP BY ecif_cust_no`、`ORDER BY`、`LIMIT 10`<br>4. 第二轮结果不应与第一轮总量答案完全相同 |
| **验证方法** | 检查执行 SQL 与返回行数（<=10）；确认 `data_dt='20250630'` 与币种条件继承 |

### TC-AD-08: 结果列名中文化展示

| 属性 | 值 |
|-----|---|
| **前置条件** | `t_meta_columns` 中已配置部分字段 `display_name`（如 `data_dt`、`loan_bal_amt`） |
| **步骤** | 1. 输入明细查询（包含 `data_dt`、`ecif_cust_no`、`loan_bal_amt`）<br>2. 观察返回表头与 SQL 折叠区 |
| **预期行为** | 1. 表头优先显示中文（如“数据日期”“贷款余额”）<br>2. 无映射字段回退原字段名<br>3. 折叠区优先展示 `display_sql` |
| **验证方法** | 核对 `additional_kwargs.data.column_display_names` 与前端展示一致；确认单元格取值仍按原字段 key |

### TC-AD-09: 展示 SQL 回退与别名稳定性

| 属性 | 值 |
|-----|---|
| **前置条件** | 构造一个包含已有英文别名的 SQL（如 `SUM(prin_bal) AS loan_balance`） |
| **步骤** | 1. 触发 SQL 查询并展开折叠区<br>2. 检查展示 SQL 的别名行为 |
| **预期行为** | 1. 未起别名直出列可补中文别名<br>2. 已有英文别名保持不变<br>3. 若展示 SQL 生成失败，回退原 `sql` |
| **验证方法** | 对比 `sql` 与 `display_sql`；验证报错场景下页面仍可正常显示 SQL 区块 |

### TC-AD-10: 图表补充回合（Top10 客户贷款余额）

| 属性 | 值 |
|-----|---|
| **前置条件** | `2025-06-30` 存在贷款余额数据；查询结果包含客户维度与数值列 |
| **步骤** | 1. 在同一线程输入“查询2025-06-30贷款余额前10名客户”<br>2. 待首轮返回表格后补充“以柱状图方式展示” |
| **预期行为** | 1. 系统识别为补充型图表诉求（`SUPPLEMENT`）并继承上一轮指标与时间条件<br>2. 同一条 AI 回复同时展示交互柱状图与 SQL 结果表<br>3. SSE 仍通过 `data_type='sql_result'` 返回，不新增事件类型 |
| **业务口径** | 贷款余额 Top10 客户用于授信集中度观察，图形与明细需可同时核对 |
| **自动化脚本** | `web/e2e/data-agent.spec.cjs` |

### TC-AD-11: 图表维度冲突唯一化（空客户名不丢图元）

| 属性 | 值 |
|-----|---|
| **前置条件** | TopN 结果中存在至少 2 条客户名称为空（或相同客户名称），且客户编号不同 |
| **步骤** | 1. 执行 TopN 客户查询并生成柱状图<br>2. 对比图表图元数量与表格行数<br>3. 悬浮查看冲突类目 tooltip |
| **预期行为** | 1. 图表图元数量与表格行数一致，不因“未知/同名”类目塌缩<br>2. 冲突类目展示唯一化后缀（优先客户编号）<br>3. SSE 协议不变，仍通过 `data_type='sql_result'` 返回 |
| **验证方法** | 对比 `chart.data.length` 与 `rows.length`；检查重复类目是否被唯一化 |

### TC-AD-12: 日期字段不应进入图表 Y 轴（数值日期防误判）

| 属性 | 值 |
|-----|---|
| **前置条件** | 查询结果同时包含日期列（如 `业务日期=20250630`）和金额列（如 `年日均余额`） |
| **步骤** | 1. 发起“固定单日 + 机构分布”的图表查询<br>2. 观察图表 `X/Y` 轴说明和柱状分布 |
| **预期行为** | 1. Y 轴应为金额类指标，不得为日期列<br>2. 若日期只有单值，X 轴优先使用机构/客户等非日期维度<br>3. 多日期点趋势场景可使用日期作为 X 轴 |
| **验证方法** | 核对 `chart.y_key != 业务日期`；固定单日下 `chart.x_key` 不应优先选日期 |

### TC-AD-13: 图表字段语义契约输出（field_meta）

| 属性 | 值 |
|-----|---|
| **前置条件** | 触发图表补充回合，返回 `sql_result.chart` |
| **步骤** | 1. 发起“按机构看余额”的柱状图查询<br>2. 展开返回数据中的 `chart.field_meta` |
| **预期行为** | 1. 每个字段都包含 `role/semantic_type/axis_hint/agg`<br>2. 日期字段 `semantic_type=temporal`，不得标注为 `axis_hint=y`<br>3. 度量字段应标注 `role=measure` 且 `axis_hint=y` |
| **验证方法** | 核对 `chart.field_meta` 中 `业务日期/年日均余额` 的语义标签与轴位一致 |

## 5. 银行业务场景测试

### TC-AD-BIZ-01: 存款业务多维查询

| 属性 | 值 |
|-----|---|
| **角色** | 分行经理 |
| **步骤** | 1. 输入"查询上月各支行的存款余额"<br>2. 追问"与上上月相比增长了多少？" |
| **预期行为** | 1. 第一个查询生成带时间过滤（上月）和分行分组的 SQL<br>2. 追问能理解"上上月"为前一个月份<br>3. 结果以对比表格形式展示 |
| **业务口径** | 存款余额包含对公存款和零售存款，时间以月末时点值为准 |

### TC-AD-BIZ-02: 贷款业务分析

| 属性 | 值 |
|-----|---|
| **角色** | 风控人员 |
| **输入** | "按产品线统计不良贷款率" |
| **预期行为** | 1. 识别"不良贷款率"为计算指标（不良贷款余额/贷款总余额）<br>2. 生成包含 `CASE WHEN` 或子查询的 SQL<br>3. 结果按产品线分组展示 |
| **边界情况** | 若数据库无"不良"标识字段，应返回澄清而非错误 SQL |

### TC-AD-BIZ-03: 权限与数据脱敏

| 属性 | 值 |
|-----|---|
| **角色** | 普通客户经理（非管理员） |
| **步骤** | 1. 输入"查询客户明细信息"<br>2. 观察返回结果中的敏感字段 |
| **预期行为** | 1. 无权限时返回拒绝提示或仅展示汇总数据<br>2. 有权限时，敏感字段（身份证号、手机号）应脱敏显示<br>3. 不应返回其他分行/部门的客户数据 |
