## 2. 访问控制测试

### TC-ADMIN-01: 白名单/黑名单展示与 SQL 测试

| 属性 | 值 |
|-----|---|
| **前置条件** | 管理员登录成功，进入"访问控制"页面 |
| **步骤** | 1. 查看白名单列表，确认表名/SQL 数量<br>2. 查看黑名单列表，确认拦截规则<br>3. 在"SQL 测试"区域输入一条白名单中的 SQL，点击执行<br>4. 输入一条黑名单中的 SQL，点击执行 |
| **预期行为** | 1. 白名单/黑名单列表正确加载，无空白<br>2. 白名单 SQL 执行成功，返回结果<br>3. 黑名单 SQL 被拦截，显示拒绝提示<br>4. 列表支持分页或滚动加载（如数据量大） |
| **验证方法** | 对比管理后台展示的规则与数据库 `t_sql_whitelist`/`t_sql_blacklist` 表内容 |

## 3. LLM 配置测试

### TC-ADMIN-02: 提供商与模型列表

| 属性 | 值 |
|-----|---|
| **前置条件** | 管理员登录成功 |
| **步骤** | 1. 进入"LLM 配置"页面<br>2. 查看提供商列表（如 OpenAI、Kimi 等）<br>3. 展开某提供商，查看模型列表<br>4. 观察 API Key 显示方式 |
| **预期行为** | 1. 提供商列表完整，与 `t_llm_provider` 表一致<br>2. 模型列表按类型分类（chat/embedding/vision）<br>3. API Key 脱敏显示（仅显示前 4 位和后 4 位，中间用 `****` 替代）<br>4. 启用/禁用状态正确显示 |
| **验证方法** | `SELECT name, is_enabled FROM t_llm_provider` 与页面展示对比 |

### TC-ADMIN-02b: 模型配置编辑

| 属性 | 值 |
|-----|---|
| **步骤** | 1. 选择一个模型，点击编辑<br>2. 修改 `temperature` 参数<br>3. 保存修改<br>4. 刷新页面查看是否生效 |
| **预期行为** | 1. 编辑表单预填当前配置值<br>2. 保存后显示成功提示<br>3. 刷新后修改值仍保留<br>4. 修改后发送聊天消息，新参数生效 |
| **数据库验证** | `SELECT config FROM t_llm_model WHERE id = ?` — 确认参数已更新 |

## 5. 系统配置测试

### TC-ADMIN-04: 配置列表与编辑

| 属性 | 值 |
|-----|---|
| **前置条件** | 管理员登录成功 |
| **步骤** | 1. 进入"系统配置"页面<br>2. 使用分类筛选（如"AI 配置"/"系统配置"）<br>3. 找到一个可编辑的配置项，修改其值<br>4. 点击保存<br>5. 刷新页面确认修改已持久化 |
| **预期行为** | 1. 配置项按分类正确分组显示<br>2. 筛选功能可快速定位目标配置<br>3. 修改后显示保存成功提示<br>4. 刷新后新值保留<br>5. 修改的配置在业务功能中即时生效 |

## 6. 权限与安全测试

### TC-ADMIN-05: 非管理员访问拦截

| 属性 | 值 |
|-----|---|
| **前置条件** | 使用普通用户账号登录 |
| **步骤** | 1. 登录普通用户账号<br>2. 直接在浏览器地址栏输入 `/admin` 页面 URL<br>3. 尝试通过 API 直接调用管理接口 |
| **预期行为** | 1. 页面访问被拒绝（跳转到首页或显示"无权限"提示）<br>2. API 调用返回 403 Forbidden<br>3. 不暴露后台页面的任何内容或数据 |
| **验证方法** | `curl -H "Authorization: Bearer {user_token}" /api/v1/admin/config` — 应返回 403 |

| **预期行为** | 1. 关键操作（配置修改、模型启停）被记录<br>2. 日志包含操作人、时间、操作内容 |

## 7. 银行业务场景测试

### TC-ADMIN-BIZ-01: 权限分级管理（银行场景）

| 属性 | 值 |
|-----|---|
| **角色** | 系统管理员（总行科技部） |
| **业务背景** | 银行需要按分行/部门分配不同的数据访问权限 |
| **步骤** | 1. 在用户管理中创建分行 A 用户和分行 B 用户<br>2. 分别配置其数据访问权限（分行 A 只能查看 A 行数据）<br>3. 用分行 A 用户登录，尝试查询分行 B 的数据 |
| **预期行为** | 1. 分行 A 用户只能看到本行数据<br>2. 查询分行 B 数据时返回"无权限"或空结果<br>3. 权限配置变更即时生效 |
| **合规要求** | 符合银行信息隔离要求 |

### TC-ADMIN-BIZ-02: LLM 配置切换（银行场景）

| 属性 | 值 |
|-----|---|
| **角色** | 运维人员 |
| **业务背景** | 银行因合规要求需要切换 LLM 提供商（如从外部模型切换到内部部署模型） |
| **步骤** | 1. 在 LLM 配置中禁用当前主力模型<br>2. 启用备用模型<br>3. 发送聊天消息验证切换是否生效 |
| **预期行为** | 1. 模型切换后聊天功能正常<br>2. 新模型的回复能力符合预期<br>3. 切换过程对在线用户影响最小 |

## 8. 异常处理测试

### TC-ADMIN-ERR-01: 并发配置修改

| 属性 | 值 |
|-----|---|
| **步骤** | 1. 两个管理员同时修改同一配置项<br>2. 分别保存 |
| **预期行为** | 1. 不出现数据覆盖丢失<br>2. 后保存的操作有冲突提示，或最后写入生效 |

### TC-ADMIN-ERR-02: 禁用所有 LLM 模型

| 属性 | 值 |
|-----|---|
| **步骤** | 1. 在 LLM 配置中禁用所有可用模型<br>2. 尝试发送聊天消息 |
| **预期行为** | 1. 聊天界面显示明确提示（如"当前无可用模型"）<br>2. 不出现白屏或 500 错误<br>3. 管理员能重新启用模型恢复服务 |

### TC-ADMIN-ERR-03: 网络异常时保存配置

| 属性 | 值 |
|-----|---|
| **步骤** | 1. 修改配置项<br>2. 在点击保存时断开网络 |
| **预期行为** | 1. 显示保存失败提示<br>2. 用户输入的修改内容不丢失（仍在表单中）<br>3. 恢复网络后可重新保存 |
