## 日志查看

### 后端日志

```bash
# 实时查看日志
tail -f logs/assistant.log

# 按级别过滤
grep "ERROR" logs/assistant.log

# 查看 LangGraph 相关日志
grep -E "(supervisor|todo_expert|data_expert)" logs/assistant.log
```

### 日志级别

开发环境默认 DEBUG，可在 `.env.dev` 修改：

```bash
LOG_LEVEL=DEBUG
```

## 多智能体路由调试

### 路由问题排查顺序

当用户请求未被正确路由到目标 Agent 时，按以下顺序排查：

| 顺序 | 检查项 | 文件/命令 |
|------|--------|----------|
| 1 | 后端服务状态 | `curl http://localhost:8089/health` |
| 2 | Supervisor Prompt | `app/ai/prompts/agent_prompts.py` |
| 3 | 多智能体图结构 | `app/ai/workflow/multi_agent_graph.py` |
| 4 | Handoff 工具注册 | 检查 `assign_to_*` 工具 |

### 关键原则

> **先检查配置和 Prompt，再考虑修改代码架构。**

原有架构经过验证，路由问题通常是：
- Prompt 决策树被意外修改
- 配置文件错误
- 端口不匹配

### 快速恢复

如果修改代码后导致问题，使用 Git 回滚：

```bash
# 恢复单个文件
git checkout app/ai/prompts/agent_prompts.py

# 恢复多个文件
git checkout app/ai/workflow/multi_agent_graph.py app/ai/prompts/agent_prompts.py

# 查看修改内容
git diff <file>
```

## 常见问题

### Token 过期

重新登录获取新 Token。

### 数据库连接失败

```bash
# 检查服务状态
docker compose ps

# 查看日志
docker compose logs postgres
```

### LLM 调用失败

检查 API Key 和网络连接：

```bash
curl https://dashscope.aliyuncs.com/api/v1/services \
  -H "Authorization: Bearer $MODEL_API_KEY"
```

### 模块导入冲突

当出现 `module 'xxx' has no attribute 'YYY'` 错误时：

1. 检查是否有同名目录覆盖了模块文件
2. 在 `__init__.py` 中显式导出需要的属性

**案例**：`app/ai/config/` 目录覆盖了 `app/ai/config.py`

```python
# app/ai/config/__init__.py
# 需要重新导出原 config.py 的常量
from app.core.config import STREAMING, MODEL_PROVIDER, ...
```

### Pydantic V2 迁移问题

Pydantic V2 中 `BaseSettings` 已移至独立包：

```python
# 旧写法（Pydantic V1）
from pydantic import BaseSettings

# 新写法（Pydantic V2）
from pydantic_settings import BaseSettings
```

Config 内部类也需更新：

```python
# 旧写法
class Config:
    env_prefix = "TODO_"

# 新写法
model_config = {"env_prefix": "TODO_"}
```

### 前后端端口不匹配

检查 `web/.env` 中的 API 地址：

```bash
# 确保端口与后端一致
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8089
```

## 调试经验总结

### 黄金法则

1. **日志优先**：先看日志，再改代码
2. **最小改动**：优先修复配置，而非重构架构
3. **Git 保底**：改动前确认可回滚
4. **验证闭环**：每次修改后立即验证

### 调试流程图

```
发现问题 → 检查日志 → 定位错误源
    ↓
是配置问题？→ 是 → 修复配置 → 验证
    ↓ 否
是 Prompt 问题？→ 是 → 调整 Prompt → 验证
    ↓ 否
检查代码逻辑 → 修复 → 验证
    ↓ 失败
回滚并重新分析
```
