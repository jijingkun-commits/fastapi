# 生产部署手册

本文档提供生产环境部署的完整指南，包括环境准备、部署步骤、检查清单和回滚方案。

---

## 一、环境要求

### 硬件配置

#### 主应用服务器

| 组件 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 2 核 | 4 核+ |
| 内存 | 4 GB | 8 GB+ |
| 磁盘 | 20 GB SSD | 100 GB+ SSD |

#### RAGFlow 服务器（可选，知识库功能）

| 组件 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 4 核 | 8 核+ |
| 内存 | 16 GB | 32 GB+ |
| 磁盘 | 50 GB SSD | 200 GB+ SSD |
| GPU | 无 | NVIDIA GPU（加速 Embedding） |

> RAGFlow 包含 Elasticsearch、MinIO、MySQL 等组件，资源消耗较大。建议独立部署。

### 软件依赖

| 组件 | 版本要求 | 用途 |
|------|----------|------|
| Python | ≥ 3.11 | 后端运行时 |
| PostgreSQL | ≥ 16 + pgvector | 主数据库 |
| MinIO | 最新版 | 对象存储 |
| RAGFlow | ≥ 0.14 | 知识库检索（可选） |
| Node.js | ≥ 18 | 前端构建（可选） |

## 三、部署步骤

### Step 1: 环境准备

```bash
# 1. 克隆代码
git clone <repo-url> /opt/app
cd /opt/app

# 2. 创建生产环境配置
cp .env.example .env.prod

# 3. 编辑配置（重要！）
vim .env.prod
```

**必须修改的配置项：**

```bash
# 数据库连接（改为生产库地址）
DATABASE_URL=postgresql+psycopg://user:password@prod-db:5432/chat_db
ANALYTICS_DATABASE_URL=postgresql+psycopg://user:password@prod-db:5432/data_db

# 安全配置
JWT_SECRET=<生成64位随机字符串>
CORS_ALLOW_ORIGINS=https://your-domain.com

# MinIO
MINIO_ENDPOINT=http://minio.prod:9000
MINIO_ACCESS_KEY=<生产密钥>
MINIO_SECRET_KEY=<生产密钥>

# LLM API Keys
ZHIPUAI_API_KEY=<生产密钥>
OPENAI_API_KEY=<生产密钥>

# RAGFlow（可选，用于知识库检索）
RAGFLOW_BASE_URL=http://ragflow.prod:9380
RAGFLOW_API_URL=http://ragflow.prod:9380/api/v1
RAGFLOW_API_KEY=<生产密钥>
RAGFLOW_DATASET_IDS=<知识库ID列表，逗号分隔>
RAGFLOW_SIMILARITY_THRESHOLD=0.2
RAGFLOW_TOP_K=5
RAGFLOW_VECTOR_WEIGHT=0.6

# 日志
LOG_LEVEL=INFO
```

### Step 2: 安装依赖

```bash
# Python 依赖
pip install -r requirements.txt

# 或使用 pyproject.toml
pip install -e .
```

### Step 3: 初始化

```bash
# 一键初始化（数据库 + MinIO + 技能）
./deploy.sh prod init
```

### Step 4: 启动服务

```bash
# 后台启动
./deploy.sh prod start

# 查看状态
./deploy.sh prod status

# 查看日志
./deploy.sh prod logs
```

### Step 5: 验证部署

```bash
# 健康检查
curl http://localhost:8000/api/v1/health

# 预期响应
{"status": "healthy", "version": "x.x.x"}
```

## 五、回滚方案

### 服务回滚

```bash
# 1. 停止当前服务
./deploy.sh prod stop

# 2. 切换到上一版本
git checkout <previous-tag>

# 3. 重新安装依赖
pip install -r requirements.txt

# 4. 启动服务
./deploy.sh prod start
```

### 数据库回滚

#### 回滚权限控制表

```sql
-- 删除权限相关表
DROP TABLE IF EXISTS t_data_permission_column CASCADE;
DROP TABLE IF EXISTS t_data_permission_row CASCADE;
DROP TABLE IF EXISTS t_data_permission_table CASCADE;

-- 回滚用户表字段
ALTER TABLE t_user DROP COLUMN IF EXISTS role;
ALTER TABLE t_user DROP COLUMN IF EXISTS org_code;
ALTER TABLE t_user DROP COLUMN IF EXISTS org_name;
ALTER TABLE t_user DROP COLUMN IF EXISTS dept_code;
ALTER TABLE t_user DROP COLUMN IF EXISTS dept_name;
```

#### 回滚指标扩展

```sql
-- 删除扩展的指标
DELETE FROM t_metric_definition 
WHERE metric_id IN (
    'DEP_003', 'DEP_004', 'DEP_005', 'DEP_006', 'DEP_007', 'DEP_008',
    'LOAN_003', 'LOAN_004', 'LOAN_005', 'LOAN_006', 'LOAN_007', 
    'LOAN_008', 'LOAN_009', 'LOAN_010', 'COMP_001'
);
```

## 六、RAGFlow 部署

RAGFlow 是可选的知识库检索服务，用于企业文档的语义搜索。

### 6.1 Docker 部署（推荐）

```bash
# 1. 克隆 RAGFlow
git clone https://github.com/infiniflow/ragflow.git
cd ragflow

# 2. 启动服务
docker compose -f docker-compose.yml up -d

# 3. 等待初始化（首次需要 10-15 分钟）
docker logs -f ragflow-server
```

**默认端口**:

| 服务 | 端口 | 说明 |
|------|------|------|
| RAGFlow Web | 9380 | 管理界面和 API |
| Elasticsearch | 9200 | 向量搜索后端 |
| MinIO | 9001 | 文档存储 |
| MySQL | 3306 | 元数据存储 |

### 6.2 配置知识库

1. **访问管理界面**: `http://ragflow-server:9380`

2. **创建 API Key**:
   - 进入 `设置` > `API 密钥`
   - 点击 `创建密钥`，复制生成的 Key

3. **创建知识库**:
   - 进入 `知识库` > `新建`
   - 配置名称、描述、Embedding 模型
   - 上传文档并等待解析完成

4. **获取知识库 ID**:
   - 在知识库列表中，点击知识库进入详情
   - URL 中的 ID 即为 `RAGFLOW_DATASET_IDS`
   - 多个知识库用逗号分隔

### 6.3 集成配置

在 `.env.prod` 中配置：

```bash
# RAGFlow 服务地址
RAGFLOW_BASE_URL=http://ragflow.prod:9380
RAGFLOW_API_URL=http://ragflow.prod:9380/api/v1

# API 密钥
RAGFLOW_API_KEY=ragflow-xxxxxxxxxxxxxxxx

# 知识库 ID（逗号分隔多个）
RAGFLOW_DATASET_IDS=7c112617e91411f08852712b5dc403b8

# 检索参数
RAGFLOW_SIMILARITY_THRESHOLD=0.2  # 相似度阈值（0-1）
RAGFLOW_TOP_K=5                   # 返回结果数量
RAGFLOW_VECTOR_WEIGHT=0.6         # 向量权重（混合检索）
```

### 6.4 验证集成

```bash
# 测试 RAGFlow API 连通性
curl -X POST "$RAGFLOW_API_URL/retrieval" \
  -H "Authorization: Bearer $RAGFLOW_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset_ids": ["'$RAGFLOW_DATASET_IDS'"],
    "question": "测试查询",
    "top_n": 3
  }'

# 预期返回：包含检索结果的 JSON
```

### 6.5 图片代理说明

RAGFlow 知识库中的图片通过本系统代理访问：

| 原始路径 | 代理路径 |
|----------|----------|
| RAGFlow 内部图片 ID | `/api/v1/assets/proxy/ragflow/{image_id}` |

代理由后端自动处理，前端无需关心 RAGFlow 的直接访问。

### 6.6 常见问题

**RAGFlow 连接超时**:

```bash
# 检查服务状态
docker ps | grep ragflow

# 检查网络连通性
curl -v $RAGFLOW_BASE_URL/api/v1/health
```

**检索结果为空**:

1. 确认知识库中有已解析的文档
2. 检查 `RAGFLOW_DATASET_IDS` 是否正确
3. 降低 `RAGFLOW_SIMILARITY_THRESHOLD` 阈值

**图片无法显示**:

1. 确认图片代理端点正常：`curl localhost:8000/api/v1/assets/proxy/ragflow/{image_id}`
2. 检查 `RAGFLOW_BASE_URL` 配置是否正确

## 七、常见问题

### 数据库连接失败

```bash
# 检查 PostgreSQL 状态
pg_isready -h <host> -p 5432

# 检查连接字符串
python3 -c "from app.core.config import DATABASE_URL; print(DATABASE_URL)"
```

### MinIO 初始化失败

```bash
# 手动创建 Bucket
mc alias set local http://localhost:9000 admin password
mc mb local/chat-assets
```

### 服务启动但无法访问

```bash
# 检查端口占用
lsof -i :8000

# 检查防火墙
iptables -L -n
```
