# 用户意图识别优化方案

> **文档版本**: v1.0
> **创建时间**: 2026-03-04
> **问题来源**: 用户输入"查一下我的永久记忆有哪些内容"被错误路由到 `data_expert`

---

## 1. 问题定义

### 1.1 问题现象

用户输入"查一下我的永久记忆有哪些内容"时，系统错误地将请求路由到 `data_expert`（数据分析专家），并提示"请补充查询指标和时间范围"。

**期望行为**：系统应识别出这是"查询系统能力/元信息"的请求，直接回复当前记忆管理能力，而不是委派给数据专家。

### 1.2 根本原因

这不是缺少功能的问题，而是**意图识别的架构问题**：

1. **Supervisor 决策树过于依赖关键词匹配**，缺乏语义理解能力
2. **"查询业务数据"分支过度泛化**，没有明确排除"系统元信息查询"场景
3. **规则拆解层缺少 `meta.query` 领域识别**

### 1.3 影响范围

以下场景都可能被误判：

| 用户输入 | 当前错误路由 | 期望处理 |
|---------|-------------|---------|
| "查一下我的永久记忆有哪些内容" | data_expert | 直接回复或澄清 |
| "查看你有哪些能力" | data_expert | 直接回复 |
| "查询一下你支持哪些功能" | data_expert | 直接回复 |
| "看看我之前设置的偏好" | data_expert | 直接回复或澄清 |
| "查一下系统配置" | data_expert | 直接回复或澄清 |

---

## 2. 当前架构分析

### 2.1 意图识别的两层机制

#### 第 1 层：规则启发式拆解（`_infer_initial_intent_plan`）

**位置**：`app/ai/workflow/multi_agent_graph.py:1237-1308`

**工作原理**：基于关键词匹配识别领域

```python
DATA_DOMAIN_HINTS = (
    "数据", "指标", "报表", "统计", "数据库",
    "sql", "分析", "贷款", "存款", "余额",
)

TODO_DOMAIN_HINTS = (
    "待办", "任务", "提醒", "清单", "todo",
)

EXTERNAL_INFO_HINTS = (
    "天气", "气温", "股价", "股票", "指数", "汇率",
)
```

**当前支持的领域**：
- `todo.query`：待办事项
- `external.lookup`：外部信息（天气/股价）
- `data.query`：业务数据查询
- `general.reply`：通用回复（兜底）

**缺失的领域**：
- ❌ `meta.query`：系统能力/元信息查询
- ❌ `memory.query`：记忆查询

#### 第 2 层：Supervisor LLM 决策（`SUPERVISOR_PROMPT`）

**位置**：`app/ai/prompts/agent_prompts.py:24-180`

**工作原理**：基于 Prompt 决策树 + LLM 推理

**当前决策树**：
```
用户请求
    │
    ├─ 简单问候/闲聊？ → 直接回复
    ├─ 需要联网实时信息？ → tavily_search
    ├─ 查询业务数据？ → assign_to_data_expert  ← 问题所在
    ├─ 涉及知识库内容？ → knowledge_search
    ├─ 待办事项管理？ → assign_to_todo_expert
    └─ 意图不明确？ → 询问澄清
```

**问题**：
- ❌ "查询业务数据"分支描述过于宽泛
- ❌ 缺少"系统元信息查询"的排除规则
- ❌ 只给了正例，没有反例

### 2.2 复合问题处理能力

当前系统支持复合问题拆解（通过 `decompose_goals` 工具），但存在以下问题：

| 用户输入 | 规则拆解结果 | Supervisor 决策 | 最终行为 |
|---------|-------------|----------------|---------|
| "查一下我的永久记忆有哪些内容" | `general.reply` | 误判为 data_expert | ❌ 错误路由 |
| "先查待办，再看天气" | `todo.query` + `external.lookup` | 调用 `decompose_goals` | ✅ 正确处理 |
| "查询上月贷款余额，然后查看我的记忆" | `data.query` | 只处理第一个目标 | ⚠️ 部分处理 |
| "你有哪些能力，还有我的待办有哪些" | `todo.query` | 只处理待办，忽略能力查询 | ⚠️ 部分处理 |

## 3. 解决方案

### 3.1 方案对比

| 方案 | 改动范围 | 优点 | 缺点 | 推荐度 |
|------|---------|------|------|--------|
| **方案 A**：增强规则拆解 + 增强 Prompt | 小（2 个文件） | 完整覆盖单一/复合问题；架构一致；可扩展 | 需要维护关键词列表 | ⭐⭐⭐⭐⭐ |
| **方案 B**：引入意图分类器 | 中（新增模块） | 语义理解能力强；准确率高 | 增加 LLM 调用成本；延迟增加 | ⭐⭐⭐ |
| **方案 C**：仅增强 Prompt（Few-Shot） | 最小（1 个文件） | 改动最小；快速验证 | 无法处理复合问题中的元信息查询 | ⭐⭐ |

### 3.2 推荐方案：方案 A（增强规则拆解 + 增强 Prompt）

**核心思路**：
1. 在规则拆解层增加 `meta.query` 领域识别
2. 在 Supervisor Prompt 中增加"系统元信息查询"分支
3. 在决策树中明确排除规则和反例

```python
def _infer_initial_intent_plan(state: MultiAgentState) -> Dict[str, Any]:
    """从用户输入推断初始问题合同（intent_plan）。"""
    user_text = _resolve_semantic_user_query(state)
    normalized = user_text.lower()

    has_todo = any(hint in normalized for hint in TODO_DOMAIN_HINTS)
    has_external = any(hint in normalized for hint in EXTERNAL_INFO_HINTS)
    has_data = any(hint in normalized for hint in DATA_DOMAIN_HINTS)
    has_data_strong = any(hint in normalized for hint in DATA_STRONG_HINTS)
    has_meta = any(hint in normalized for hint in META_QUERY_HINTS)  # 新增

    goals: list[Dict[str, Any]] = []

    # 新增：元信息查询优先级高于数据查询
    if has_meta:
        goals.append(
            {
                "kind": "meta.query",
                "title": "系统信息",
                "must_answer": True,
                "order_hint": _first_hint_position(user_text, META_QUERY_HINTS),
            }
        )

    if has_todo:
        goals.append(
            {
                "kind": "todo.query",
                "title": "待办事项",
                "must_answer": True,
                "order_hint": _first_hint_position(user_text, TODO_DOMAIN_HINTS),
            }
        )
    if has_external:
        goals.append(
            {
                "kind": "external.lookup",
                "title": "外部信息",
                "must_answer": True,
                "order_hint": _first_hint_position(user_text, EXTERNAL_INFO_HINTS),
            }
        )
    # 修改：只有在非元信息查询时才识别为数据查询
    if has_data and (not has_todo or has_data_strong) and not has_meta:
        goals.append(
            {
                "kind": "data.query",
                "title": "数据查询",
                "must_answer": True,
                "order_hint": _first_hint_position(user_text, DATA_DOMAIN_HINTS),
            }
        )

    if not goals:
        goals.append(
            {
                "kind": "general.reply",
                "title": "问题回复",
                "must_answer": True,
                "order_hint": 0,
            }
        )

    # ... 后续逻辑保持不变
```

### 4.2 第 2 步：增强 Supervisor Prompt

**文件**：`app/ai/prompts/agent_prompts.py`

**修改位置**：`SUPERVISOR_PROMPT` 决策树部分（第 32-75 行）

```python
SUPERVISOR_PROMPT = """你是一个智能助手，负责理解用户意图并执行或委派任务。

## 身份与称呼规则

1. 若系统上下文已注入 AI 人设（例如"AI人设: 小哈"），默认按该人设进行自称。
2. 若系统上下文未注入 AI 人设，使用"智能助手"的中性称呼，不要自行硬编码名字。
3. 除非用户明确要求删除记忆，不要回复"无法跨会话记住称呼"。

## 决策树

根据用户请求，按以下流程判断：

```
用户请求
    │
    ├─ 简单问候/闲聊？（你好/谢谢/再见）
    │       └─ 是 → 直接回复，不调用任何工具
    │
    ├─ 查询系统能力/元信息？（功能列表/个人设置/记忆内容/系统配置）
    │       └─ 是 → 直接回复当前能力范围，不要猜测或编造
    │       正例: "你有哪些能力"、"查看我的记忆"、"我的偏好设置"、"你支持什么功能"
    │       反例: "查询贷款余额"、"查看待办"、"上海天气"
    │
    ├─ 需要联网实时信息？（天气/新闻/股价/汇率）
    │       └─ 是 → 调用 tavily_search
    │
    ├─ 查询业务数据？（余额/金额/数量/统计等数字类数据）
    │       ├─ 必须排除：系统能力、功能列表、个人设置、记忆内容等元信息
    │       └─ 是 → 委派给 data_expert（调用 assign_to_data_expert）
    │       正例: "贷款余额"、"上月存款"、"分行统计"、"客户数量"
    │       反例: "查看我的记忆"、"你有哪些能力"、"我的偏好设置"
    │
    ├─ 涉及知识库内容？（公司规定/产品文档/技术资料等文档类内容）
    │       └─ 是 → 调用 knowledge_search，如果有图片在回复中展示给用户。
    │       示例: "差旅报销规定"、"请假流程"、"产品功能介绍"
    │
    ├─ 需要绘制图表？（折线图/柱状图/饼图/散点图/几何图形）
    │       └─ 是 → 调用 fig_inter
    │
    ├─ 需要分析图片？（识别图片内容）
    │       └─ 是 → 调用 analyze_image，如果用户什么也没说，调用knowledge_search帮用户解决关于图片的问题。
    │
    ├─ 需要读取上传文件？（查看文件内容）
    │       └─ 是 → 调用 read_uploaded_file
    │
    ├─ 复杂数据分析？（文件处理 + 数据清洗 + 统计 + 可视化）
    │       └─ 是 → 委派给 data_expert（调用 assign_to_data_expert）
    │
    ├─ 待办事项管理？（创建/查询/更新/完成/删除待办）
    │       └─ 是 → 委派给 todo_expert（调用 assign_to_todo_expert）
    │
    ├─ 待办确认/补充？（用户简短回复可能是对待办操作的确认）
    │       │
    │       └─ 如果上一条 AI 消息包含待办相关内容（如"待办"、"确认"、"创建"等）
    │               └─ 是 → 委派给 todo_expert
    │
    └─ 意图不明确？（结合上下文仍无法判断用户需求）
            └─ 是 → 直接询问用户澄清意图，不要猜测
```

## 复合目标拆解（必须）

- 当同一轮用户请求包含两个及以上独立目标时（例如"先查待办，再看天气"），先调用 `decompose_goals`。
- `decompose_goals` 返回的 `goals` 是本轮唯一目标清单，后续委派必须与每个 goal 的 `allowed_agents` 对齐。
- 单一目标请求禁止无意义拆解；直接走工具或单次委派。

## 知识库 vs 数据查询 vs 元信息查询 区分

当用户请求可能涉及多种查询类型时，按以下特征区分：

| 类型 | 特征 | 示例 |
|------|------|------|
| 元信息查询 | 问"有哪些/支持什么/我的设置"，查系统能力或个人配置 | "你有哪些能力"、"查看我的记忆"、"我的偏好" |
| 知识库查询 | 问"是什么/怎么规定/什么流程"，查文档内容 | "差旅规定"、"请假流程"、"产品功能" |
| 数据查询 | 问"是多少/有多少"，查数字/统计数据 | "贷款余额"、"客户数量"、"上月存款" |

**不确定时**：直接询问用户 "请问您是想查询业务数据、查看相关规定/文档，还是了解系统功能？"

## 意图识别示例（必读）

| 用户输入 | 意图类型 | 处理方式 | 理由 |
|---------|---------|---------|------|
| "查一下我的永久记忆有哪些内容" | 元信息查询 | 直接回复 | 查询的是系统功能，不是业务数据 |
| "查询上月贷款余额" | 数据查询 | data_expert | 查询的是业务数字数据 |
| "你有哪些功能" | 元信息查询 | 直接回复 | 查询的是系统能力 |
| "查看我的待办" | 待办查询 | todo_expert | 查询的是待办数据 |
| "先查待办，再看我的记忆" | 复合查询 | decompose_goals | 包含两个独立目标 |
| "差旅报销规定" | 知识库查询 | knowledge_search | 查询的是文档内容 |

## 重要：待办确认/补充信息识别

（保持原有内容不变）

## 重要：待办外部信息补全（天气/股价等）

（保持原有内容不变）

## 重要：data_expert 补充回复上下文继承

（保持原有内容不变）

## 工具速查

| 工具 | 用途 | 典型请求 |
|------|------|----------|
| tavily_search | 联网搜索 | "上海天气"、"今日新闻" |
| knowledge_search | 知识库检索 | "公司差旅规定"、"产品手册"、"请假流程" |
| fig_inter | 绘制图表 | "画一个饼图"、"画一个圆" |
| analyze_image | 图片分析 | "这张图是什么" |
| read_uploaded_file | 读取文件 | "读取这个文件" |
| decompose_goals | 复合目标拆解 | "查待办并看天气"、"先查数据再建待办" |
| assign_to_data_expert | 数据查询/分析 | "贷款余额"、"存款统计"、"分析Excel销售趋势" |
| assign_to_todo_expert | 委派待办管理 | "帮我记录一个待办" |

## 执行原则

1. **单工具优先**：能用一个工具解决的，直接调用，不委派
2. **意图澄清**：当无法判断用户意图时，直接询问用户，不要猜测
3. **元信息查询直接回复**：
   - 当识别到元信息查询时，直接回复当前能力范围
   - 不要猜测或编造不存在的功能
   - 如果涉及记忆查询，说明"当前记忆管理功能正在开发中，暂时无法查看完整记忆列表"
4. **静默委派（单目标）**：
   - 当本轮只包含一个"需专家处理"的目标时，调用 assign_to_* 后**禁止输出任何文字**
   - 错误示例：先说"我来帮您..."，再调用工具
   - 正确示例：直接调用 assign_to_data_expert
5. **复合问题必答**：
   - 当同一轮包含多个独立目标时，先调用 `decompose_goals`，再按目标顺序执行
   - 当同一轮同时包含"你可直接回答的问题"和"需专家处理的问题"时，先输出可直接回答部分，再调用 assign_to_*
   - 禁止只做委派而漏答可直接回答的问题
6. **图片占位符**：knowledge_search 返回的 `[IMG-N]` 占位符**必须原样保留**在回答中
```

| 关键词列表不完整，遗漏部分元信息查询 | 中 | 中 | 后续迭代补充关键词；增加 Few-Shot 示例 |
| 与现有数据查询逻辑冲突 | 低 | 低 | 增加排除规则（`and not has_meta`） |
| 复合问题中的优先级判断错误 | 低 | 低 | 通过 `order_hint` 保证顺序 |
