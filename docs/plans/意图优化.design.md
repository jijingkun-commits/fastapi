# 用户意图路由收敛设计（最终方案）

> 文档版本：v4.0  
> 更新时间：2026-03-04  
> 设计状态：`approved`

## 1. 需求澄清结论

- 目标:
  - 保留**必要** `intent_plan`（仅限 `decompose_goals` 的规划内部链路），避免一次性硬删导致链路回归。
  - 将运行时路由与门禁统一收敛到 `decomposed_goals + target_agent`，消除双轨路由语义。
  - 兜底主体固定为 `supervisor`，专家节点只处理合法委派任务。
- 范围:
  - `app/ai/workflow/multi_agent_graph.py`：保留 planner 旧策略链路，移除运行时对 `state.intent_plan` 的依赖。
  - `app/ai/prompts/agent_prompts.py`：强化“元信息/记忆优先于数据查询”的判定口径。
  - `tests/unit/**`、`tests/integration/**`：改造断言口径，区分“规划阶段允许 `intent_plan`”与“运行阶段禁用 `intent_plan`”。
  - `docs/开发文档/架构设计/AI模块设计.md`：同步“规划保留、运行剥离”的边界。
- 边界:
  - 本轮不删除 `_build_planner_intent_plan`、`model_primary/heuristic_only/shadow_metrics` 相关链路。
  - 本轮不在专家节点增加兜底分支，避免职责下沉。
  - 本轮不引入新的专家节点或新路由角色。
- 成功标准:
  - `decompose_goals` 保持模型优先+规则兜底能力，行为不退化。
  - 路由执行关键路径（`_resolve_active_goals`、`_apply_router_contract_guard`、`_dispatch_values_mode_chunk`）不再依赖 `state.intent_plan`。
  - 记忆/元信息请求误路由到 `data_expert` 的比例下降并可观测。

### 1.1 现状证据、失败样例、不可做项

- 现状证据:
  - `decompose_goals` 当前通过 `_build_planner_intent_plan` 产出 `intent_plan`，再转 `goals`，属于核心产出链路。
  - `_resolve_active_goals`、`_apply_router_contract_guard`、`_dispatch_values_mode_chunk` 仍存在 `state.intent_plan` 读取。
  - `tests/unit/test_intent_plan_model_primary.py`、`tests/integration/test_intent_shadow_metrics.py` 等测试对 planner 旧链路有覆盖依赖。
- 失败样例:
  - “查一下我的永久记忆有哪些内容”被“查询”动作词误吸附，出现 `data.query` 误委派。
  - handoff 缺少 `target_agent` 时，若未统一回流 `supervisor`，容易出现空执行或空答复。
- 不可做项:
  - 不允许“专家兜底”替代“supervisor 兜底”。
  - 不允许在运行时继续将 `intent_plan` 作为路由主输入。
  - 不允许一次性删除 planner 旧链路后再靠临时补丁救火。
- 依赖约束:
  - 依赖 `decompose_goals` 工具稳定输出 `goals`。
  - 依赖 `ENABLE_ROUTER_CONTRACT_GUARD`、`ENABLE_COVERAGE_GATE_ENFORCED` 默认开启。
  - 依赖 `intent_mode` 配置可在 `model_primary/heuristic_only` 间回退。

## 2. 详细设计冻结清单（DoD）

### 2.1 模块边界与职责归属

- `app/ai/workflow/multi_agent_graph.py`
  - 负责：规划产出（保留 `intent_plan` 内部链路）、目标归一、Router Gate、Supervisor 兜底编排。
  - 不负责：专家语义纠偏。
- `app/ai/prompts/agent_prompts.py`
  - 负责：Supervisor 判定策略与反例样本。
  - 不负责：运行时门禁状态校验。
- `app/ai/contracts/*`
  - 负责：活动目标与交付覆盖合同。
  - 不负责：把运行时路由回退到 `intent_plan`。
- `data_expert` / `todo_expert`
  - 负责：执行合法委派任务。
  - 不负责：兜底、补齐、重路由决策。

### 2.2 端到端数据流（输入 -> 处理 -> 输出）

1. 用户输入进入 Supervisor。
2. 复合目标场景先调用 `decompose_goals`。
3. `decompose_goals` 内部：
   - 优先：`_build_planner_intent_plan`（`model_primary`）。
   - 降级：`heuristic_only` 或模型异常 fallback。
4. 将 `intent_plan.goals` 归一为 `decomposed_goals`。
5. 路由执行阶段仅消费 `decomposed_goals`，生成 handoff（`target_agent`）。
6. Router Gate 基于 `allowed_agents` 放行/阻塞。
7. 阻塞、缺口、异常统一回流 `supervisor` 兜底。
8. Coverage Gate 复核 `must_answer`，Final Composer 输出最终答复。

### 2.3 状态机与生命周期

- `S0_INPUT`：接收用户输入。
- `S1_PLAN`：`decompose_goals` 规划阶段（允许内部 `intent_plan`）。
- `S2_GOALS_ACTIVE`：`decomposed_goals` 完成归一并成为活动目标源。
- `S3_ROUTE`：生成/校验 handoff。
- `S4_EXEC`：专家执行。
- `S5_SUPERVISOR_FALLBACK`：阻塞或异常统一兜底。
- `S6_COVERAGE`：覆盖率复核与补齐。
- `S7_FINAL`：最终收口输出。

生命周期约束：
- `intent_plan` 生命周期限制在 `S1_PLAN` 内部，不作为运行态共享状态源。
- `decomposed_goals` 是 `S2` 及后续阶段唯一目标源。
- 任意失败路径必须进入 `S5_SUPERVISOR_FALLBACK`，不得切到专家兜底。
- 幂等重放以 `turn_id + goal_id` 去重。

### 2.4 字段级输入/输出契约

#### 输入合同 A：规划内部 `intent_plan`（必要保留）

| 字段 | 必填 | 默认值 | 错误语义 |
|---|---|---|---|
| `version` | 否 | `1` | 非法值置 `1` |
| `source` | 是 | `heuristic_only` | 缺失则按 fallback source 补齐 |
| `user_query` | 是 | `""` | 空值触发规则兜底 |
| `goals[]` | 是 | `[]` | 空 goals 触发规则兜底并写 fallback_meta |

#### 输入合同 B：运行时 `decomposed_goals[*]`

| 字段 | 必填 | 默认值 | 错误语义 |
|---|---|---|---|
| `goal_id` | 是 | `GOAL-XX` | 缺失补齐并记 warning |
| `order` | 是 | 顺序重排 | 非法值重排 |
| `kind` | 是 | `general.reply` | 未识别降级为 `general.reply` |
| `must_answer` | 否 | `true` | 非 bool 强转 |
| `allowed_agents` | 否 | 按 kind 补齐 | 非法值过滤 |

#### 输入合同 C：`handoff`

| 字段 | 必填 | 默认值 | 错误语义 |
|---|---|---|---|
| `target_agent` | 是 | 无 | 缺失触发 `invalid_target_agent` -> Supervisor 兜底 |
| `task_description` | 是 | 无 | 为空触发 `invalid_task_description` -> Supervisor 兜底 |
| `frame` | 否 | `{}` | 非 dict 时清空并记 warning |

#### 输出合同 A：`route_decisions[*]`

| 字段 | 必填 | 默认值 | 语义 |
|---|---|---|---|
| `goal_id` | 是 | 无 | 对齐活动目标 |
| `target_agent` | 是 | 无 | 放行目标 |
| `dispatch_reason` | 是 | `goal_allowed_agents` | 放行原因 |
| `priority` | 否 | `order` | 优先级 |
| `blocked_by` | 否 | `[]` | 阻塞依赖 |

#### 输出合同 B：`delivery_meta.router_contract_blocked[*]`

| 字段 | 必填 | 默认值 | 语义 |
|---|---|---|---|
| `reason` | 是 | 无 | `invalid_target_agent/invalid_task_description/no_pending_goal/target_not_in_allowed_agents` |
| `goal_id` | 否 | `""` | 关联目标 |
| `target_agent` | 否 | `unknown` | 被阻塞目标 |
| `allowed_agents` | 否 | `[]` | 目标允许集合 |

### 2.5 异常语义与降级策略

- `planner_model_failed`
  - 条件：模型规划异常。
  - 处理：回退 `heuristic_fallback`，继续生成 `decomposed_goals`。
- `invalid_target_agent`
  - 条件：handoff 缺失 `target_agent`。
  - 处理：阻塞并回流 `supervisor`。
- `invalid_task_description`
  - 条件：handoff 缺失任务描述。
  - 处理：阻塞并回流 `supervisor`。
- `target_not_in_allowed_agents`
  - 条件：目标不在 `allowed_agents`。
  - 处理：阻塞并回流 `supervisor` 重新路由或直接答复。
- 降级原则:
  - 允许规划降级（model -> heuristic），不允许兜底主体降级（supervisor 必须保留）。
  - 回退策略不改变合同主语义（运行态仍以 `decomposed_goals` 为准）。

### 2.6 NFR 数字阈值

- 路由门禁新增耗时：`P50 <= 30ms`，`P95 <= 150ms`。
- `planner_model_failed` 比率：`<= 5%`（超阈值触发配置回退）。
- 记忆/元信息误路由到 `data_expert`：`<= 0.5%`。
- 路由异常恢复时长（进入 Supervisor 兜底）：`TTR <= 1` 回合。
- 运行配置回退生效时长：`<= 5min`。

### 2.9 回退锚点（默认开启）

- `ENABLE_ROUTER_CONTRACT_GUARD=true`
  - 回退：置 `false` 放宽门禁。
- `ENABLE_COVERAGE_GATE_ENFORCED=true`
  - 回退：置 `false` 放宽强覆盖。
- `ENABLE_SUPERVISOR_FALLBACK_ONLY=true`
  - 回退：仅允许切到“更保守的 Supervisor 直接答复”，不允许切换专家兜底。
- `intent_mode=model_primary`（配置项）
  - 回退：切 `heuristic_only`（保持 `decompose_goals` 可用，降低模型不稳定影响）。

### 2.10 风险与反例（>=3）

1. 反例：删除 `state.intent_plan` 读取后，多目标检测被误判为单目标。
   - 风险：复合问题漏答。
   - 规避：以 `decomposed_goals.must_answer` 做唯一依据，并补多目标回归测试。
2. 反例：模型规划失败频繁触发 fallback。
   - 风险：目标拆解质量下降。
   - 规避：保留 `intent_mode` 快速回退与 fallback 指标监控。
3. 反例：Router Gate 过拦截导致响应延迟和空答复。
   - 风险：体验退化。
   - 规避：阻塞即进入 `supervisor_fallback_activated`，并保持覆盖率补齐。
4. 反例：兜底职责被误改到专家节点。
   - 风险：职责耦合扩散，后续不可维护。
   - 规避：测试断言“异常路径只到 supervisor”。

## 3. 最终方案

- 方案描述:
  - 保留 `intent_plan` 仅作为 `decompose_goals` 的规划阶段中间契约，保障现有模型策略链路稳定。
  - 运行阶段彻底以 `decomposed_goals` 作为目标状态源，剥离 `state.intent_plan` 路由依赖。
  - 异常与补齐统一走 `supervisor`，确保职责单点收敛。
- 关键决策:
  - 不做“一次性全删 intent_plan”。
  - 不做“长期双轨并行”。
  - 采用“规划保留、运行剥离”的中风险方案。

## 4. 决策权衡

- 放弃路径:
  - 一次性删除 `intent_plan` 与 planner 旧策略链路。
  - 保持现状双轨不动，仅靠 prompt 修补误路由。
- 放弃原因:
  - 全删风险过高，会直接影响 `decompose_goals` 主产出链路。
  - 仅靠 prompt 无法保证运行时门禁一致性，问题会复发。

## 5. 设计概要

- 架构:
  - 规划层（保留 `intent_plan`）-> 运行层（`decomposed_goals`）-> 兜底层（`supervisor`）三段分层。
- 组件:
  - Planner Strategy、Goal Normalizer、Router Guard、Coverage Gate、Supervisor Fallback。
- 数据流:
  - `user_query -> planner(intent_plan) -> normalized_goals(decomposed_goals) -> routing(target_agent) -> expert/supervisor -> final_answer`。
- 异常与测试:
  - 通过规划链保留回归 + 运行链剥离回归 + 失败注入回归三层验证。
