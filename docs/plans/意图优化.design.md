## 1. 目标与边界

### 1.1 目标

统一意图状态与路由门禁，收敛为：

1. 运行时仅以 `decomposed_goals` 作为目标状态源
2. Router Gate 按目标合同稳定拦截误委派
3. 解决“记忆/元信息请求误路由到 `data_expert`”问题

### 1.2 本轮不展开项

按当前评审约束，本轮**不展开**以下议题的影响面分析：

- 删除 `_infer_initial_intent_plan` / `_build_planner_intent_plan` 的全链路影响

---

## 2. 根因归纳

问题根因不在 `data_expert`，而在意图层与门禁层：

1. **状态双轨导致语义漂移**：`decomposed_goals` 与 `intent_plan` 并存，路由口径不一致。
2. **门禁输入不稳定**：Router Gate 仍兼容 `intent_plan` 读取，导致合同边界不清。
3. **目标分类不充分**：元信息/记忆请求缺少明确识别规则，被“查询”动作词误吸附到 `data.query`。

---

## 3. 最终架构决策

### 3.1 单一真理源

`MultiAgentState.decomposed_goals` 为唯一目标状态源：

- 路由门禁、覆盖率、最终收口统一读取 `decomposed_goals`
- 运行时不再读取 `state.get("intent_plan")`

### 3.2 目标类型与允许委派

`decomposed_goals[*].kind` 支持：

- `general.reply`
- `meta.query`
- `memory.query`
- `todo.query`
- `todo.create`
- `external.lookup`
- `data.query`

`allowed_agents` 与当前实现约束对齐（仅允许现有专家节点）：

| kind | 默认 `allowed_agents` | 处理方式 |
|------|------------------------|----------|
| `general.reply` | `[]` | Supervisor 直接回答 |
| `meta.query` | `[]` | Supervisor 直接回答 |
| `memory.query` | `[]` | Supervisor 直接回答 |
| `external.lookup` | `[]` | Supervisor 直接工具链（如 `tavily_search`） |
| `todo.query` / `todo.create` | `["todo_expert"]` | 委派 `todo_expert` |
| `data.query` | `["data_expert"]` | 委派 `data_expert` |

> 说明：当前系统无 `external_info_expert` 专家节点，不引入虚构路由目标。

### 3.3 Router Gate 合同

Router Gate 使用真实函数 `_apply_router_contract_guard`，并按当前 handoff 协议执行：

- handoff 目标字段统一为 `target_agent`（非 `agent`）
- 仅按 `decomposed_goals`（含运行时归一后的 active goals）做 `allowed_agents` 校验
- 不在允许集内的 handoff 记录阻塞原因并拦截

---

## 4. 端到端流程（最终形态）

1. **目标生成**
   - 单目标：按当前流程直接决策
   - 多目标：先调用 `decompose_goals`，产出 `decomposed_goals`

2. **路由决策**
   - Supervisor 依据当前 active goal 进行工具调用或委派
   - 若委派，handoff 必须写 `target_agent`

3. **Router Gate 校验**
   - `_apply_router_contract_guard` 基于 `allowed_agents` 做强校验
   - 拦截后写入 `router_contract_blocked` 元数据并触发补齐提示

4. **覆盖率与收口**
   - Coverage Gate 按 `must_answer` 验证目标覆盖
   - Final Composer 仅汇总与 goals 对齐的可验证结果

### 5.2 关键代码修正 1：Router Gate 函数名与字段口径对齐

**文件**：`app/ai/workflow/multi_agent_graph.py`  
**函数**：`_apply_router_contract_guard`

```python
def _apply_router_contract_guard(
    handoffs: Sequence[Dict[str, Any]],
    *,
    state: MultiAgentState,
) -> Tuple[list[Dict[str, Any]], list[Dict[str, Any]], list[Dict[str, Any]]]:
    normalized_handoffs = [dict(item) for item in handoffs if isinstance(item, dict)]
    if not normalized_handoffs:
        return [], [], []

    active_goals = _resolve_active_goals(state)
    dispatch_queue = _build_router_dispatch_goal_queue(active_goals)
    if not dispatch_queue:
        return normalized_handoffs, [], []

    accepted, blocked = [], []
    pending_goals = [dict(goal) for goal in dispatch_queue]

    for handoff in normalized_handoffs:
        target_agent = str(handoff.get("target_agent") or "").strip()
        if not target_agent:
            blocked.append(_build_router_blocked_entry(handoff=handoff, reason="invalid_target_agent"))
            continue

        if not pending_goals:
            blocked.append(_build_router_blocked_entry(handoff=handoff, reason="no_pending_goal"))
            continue

        current_goal = pending_goals[0]
        allowed_agents = list(current_goal.get("allowed_agents") or [])
        if target_agent not in allowed_agents:
            blocked.append(
                _build_router_blocked_entry(
                    handoff=handoff,
                    reason="target_not_in_allowed_agents",
                    goal=current_goal,
                )
            )
            continue

        enriched = dict(handoff)
        enriched["goal_id"] = str(current_goal.get("goal_id") or "")
        enriched["route_decision"] = {
            "goal_id": str(current_goal.get("goal_id") or ""),
            "target_agent": target_agent,
            "dispatch_reason": "goal_allowed_agents",
            "priority": int(current_goal.get("order") or 0),
            "blocked_by": [],
        }
        accepted.append(enriched)
        pending_goals.pop(0)

    return accepted, blocked, pending_goals
```

### 5.3 关键代码修正 2：移除运行时 `intent_plan` 读取

**文件**：`app/ai/workflow/multi_agent_graph.py`  
**位置**：`_dispatch_values_mode_chunk`（supervisor 分支）

- 删除 `raw_intent_plan = ...` 与 `has_explicit_router_contract` 中的 `intent_plan` 分支
- `has_explicit_router_contract` 仅基于：
  1) `extracted_goals`  
  2) `runtime_goals`（`decomposed_goals`）

**示例代码（按真实函数口径）**：

```python
# before
raw_intent_plan = final_state.get("intent_plan")
if not isinstance(raw_intent_plan, dict):
    raw_intent_plan = ctx.state.get("intent_plan")

has_explicit_router_contract = bool(
    extracted_goals
    or (isinstance(raw_runtime_goals, list) and raw_runtime_goals)
    or (
        isinstance(raw_intent_plan, dict)
        and isinstance(raw_intent_plan.get("goals"), list)
        and raw_intent_plan.get("goals")
    )
)

# after
has_explicit_router_contract = bool(
    extracted_goals
    or (isinstance(raw_runtime_goals, list) and raw_runtime_goals)
)
```

### 5.4 关键代码修正 3：Prompt 决策树补齐元信息/记忆分支

**提示词插入示例（局部增量，不替换整段）**：

```text
├─ 查询系统能力/元信息/记忆内容？（能力列表/偏好设置/记忆内容）
```

## 6. 约束与可观测性

### 6.1 约束

1. 新增逻辑不得新增 `state.get("intent_plan")` 运行时依赖。
2. handoff 协议统一字段名：`target_agent`。
3. `allowed_agents` 仅允许出现在 `WORKFLOW_AGENT_NODE_BY_TYPE` 有定义的专家节点中。
4. 新增控制开关默认开启（`true`），回退路径统一为“关闭开关或触发降级策略”。

### 6.2 可观测事件

至少保留：

- `goals_decomposed`：`goal_count`、`kinds`、`source`
- `router_handoff_blocked`：`goal_id`、`target_agent`、`reason`
- `coverage_result`：`must_answer_count`、`answered_count`、`missing_goals`

## 9. 验收标准

### 9.1 功能验收

1. “查一下我的永久记忆有哪些内容”不路由 `data_expert`
2. “你有哪些能力”由 Supervisor 直接回答
3. “查询上月贷款余额”可路由 `data_expert`
4. “先看待办，再查天气”可拆解并完整回答

### 9.2 结构验收

1. Router Gate 核心路径不读取 `state.get("intent_plan")`
2. handoff 协议统一使用 `target_agent`
3. `allowed_agents` 不出现不存在的专家节点（如 `external_info_expert`）
4. `decompose_goals` 工具位置与文档一致

### 9.3 回归验收

1. `todo.query` / `data.query` / `external.lookup` 行为不退化
2. coverage gate 对 `must_answer` 目标校验保持有效
3. 现有相关测试全部通过
