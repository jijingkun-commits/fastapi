## 🔍 代码审查发现的关键问题

### 问题 1: 请求内重复创建数据库引擎 ⭐⭐⭐⭐⭐

**严重程度**: 🔴 高（每次请求 3-6 次 create_engine）

**问题描述**:
多处代码在请求处理过程中重复调用 `create_engine()`，每次创建新的连接池，导致：
- TCP 连接建立开销（50-200ms/次）
- 连接池初始化开销
- 内存泄漏风险（连接池未正确关闭）

**代码证据**:

1. **vanna_client.py** (4处)
```python
# Line 106: DDL 检索
with create_engine(self.metadata_db_url).connect() as conn:
    tables = conn.execute(table_sql, {...})

# Line 208: 关键词降级
with create_engine(self.metadata_db_url).connect() as conn:
    tables = conn.execute(fallback_sql, params)

# Line 315: 指标匹配
with create_engine(self.metadata_db_url).connect() as conn:
    rows = conn.execute(sql, {"embedding": embedding_str})

# Line 367: 训练集检索
with create_engine(self.metadata_db_url).connect() as conn:
    result = conn.execute(sql, {"embedding": embedding_str})
```

2. **data_graph.py** (3处)
```python
# Line 2250: 指标名称匹配
with create_engine(DATABASE_URL).connect() as conn:
    rows = conn.execute(sql, {"name": metric_name})

# Line 2297: 指标向量检索
with create_engine(DATABASE_URL).connect() as conn:
    rows = conn.execute(sql, {"embedding": embedding_str, "top_k": top_k})

# Line 2504: 训练集向量检索
with create_engine(DATABASE_URL).connect() as conn:
    rows = conn.execute(sql, {"embedding": embedding_str, "top_k": top_k})
```

**影响范围**: 问数助手场景每次请求 **3-6 次额外连接开销**

**理论耗时估算**:
- 本地连接: 50-100ms × 6 = **300-600ms**
- 远程连接: 100-200ms × 6 = **600-1200ms**

**修复方案**:
```python
# 使用已有的全局引擎
from app.db.session import engine  # 主库
from app.db.session import analytics_engine  # 分析库

# vanna_client.py 修改
class VannaPGVector:
    def __init__(self, config=None):
        # 使用全局引擎，不要 self.metadata_db_url
        from app.db.session import engine
        self._engine = engine

    def get_related_ddl(self, question: str, schema: str):
        # 直接使用 self._engine
        with self._engine.connect() as conn:
            tables = conn.execute(table_sql, {...})
```

### 问题 2: Checkpointer 连接池独立但配置保守

**澄清**: 之前报告错误声称"与主库共享连接池"，实际上：

```python
# app/db/postgres_checkpoint.py:52
_connection_pool = AsyncConnectionPool(
    conninfo=PG_CHECKPOINTER_URI,  # 独立连接串
    min_size=2,   # 🔴 太小
    max_size=10,  # 🔴 太小
    timeout=30,
)
```

**问题**: 配置过于保守，高并发时会排队

**修复方案**:
```python
min_size=5,   # 2 → 5
max_size=20,  # 10 → 20
timeout=10,   # 30 → 10（快速失败）
```

**澄清**: 之前报告建议"创建独立连接池"，实际上已存在：

analytics_engine = create_engine(
