# BOJX AI 智能助手 - 项目文档

> 基于 LangGraph 多智能体架构的 AI 助手系统，支持智能对话、待办管理、数据问答等场景。

---

## 关于本仓库

本仓库同时包含后端、前端与文档；`docs/` 是**稳定文档主入口**，用来回答“当前到底以什么为准”。

如果你只想快速了解项目，直接从本页和 `SUMMARY.md` 开始就够了，不用先通读代码。

> **声明**：文档中出现的企业名称、Logo 及品牌元素均为虚构或借用于网络，仅用于学习演示目的，不代表与任何真实企业存在关联。如有侵权，请联系删除。

## 关于本项目

本项目是一个从零开始、一点一滴完善的 AI 应用，主要目的是**学习 AI 应用开发**。除知识库部分集成了开源的 [RAGFlow](https://github.com/infiniflow/ragflow) 外，其余模块都借助 Vibe Coding 方式逐步搭建完成。

项目还没有正式上线，所以当前最重要的不是“兼容旧口径”，而是把文档和工程结构整理清楚，尽量做到：

- 读者一眼知道当前真理源在哪里
- 过程文档不污染主阅读路径
- 自动化产物不混进稳定文档目录

---

## 文档分层约定

目前文档按下面三层理解：

| 层级 | 作用 | 你什么时候看它 |
|---|---|---|
| **稳定文档** | 当前有效、给人读的真理源 | 你想知道“现在到底怎么设计/怎么开发/怎么调用” |
| **过程文档** | 需求、方案、任务拆解、评审、验收材料 | 你要追过程、看历史推导、做实施管理 |
| **运行态产物** | 自动执行状态、锁文件、生成结果 | 只有脚本和维护者会关心 |

当前主导航**只覆盖稳定文档**。

新的过程层根目录冻结为 `workdocs/`。

历史过程文档当前仍暂时保留在下面这些旧路径里：

- `docs/plans/`
- `docs/内部参考/迭代需求/`

也就是说：

- `workdocs/` 是**新的 canonical 过程层根目录**
- `docs/plans/` 与 `docs/内部参考/迭代需求/` 仍是**迁移过渡期的旧入口**
- `task_split` 已在 `Phase 2` 收口到 `workdocs/任务拆解/`，`docs/内部参考/任务拆解/` 只保留说明页。

后续若继续治理流程产物路径，再单独收口 `docs/plans/`。

## 稳定阅读路径

```text
docs/
├── 项目上下文.md        ← 新对话快速入口
├── README.md           ← 本阅读指南
├── SUMMARY.md          ← 稳定文档完整目录
│
├── 产品文档/            ← 功能需求与产品说明（单一真理源）
├── 开发文档/            ← 开发指南、架构设计、测试与工作流
├── API文档/             ← 给人读的接口说明
├── api/                ← OpenAPI / AsyncAPI 契约文件
└── 内部参考/            ← 长期有效的内部知识（决策 / 技能 / 资料）
```

> `workdocs/` 是新的过程层根目录；其中 `workdocs/任务拆解/` 已成为 task_split 的 canonical 根目录。`docs/plans/` 与 `docs/内部参考/迭代需求/` 仍属于迁移期旧路径。

## 文档维护规则

代码修改时，优先同步更新对应的**稳定真理源**：

| 修改范围 | 更新文档 |
|---|---|
| 新增功能 | `产品文档/系统需求.md` |
| API 变更 | `API文档/接口文档.md` |
| AI 模块 | `开发文档/架构设计/AI模块设计.md` |
| 数据库 | `开发文档/架构设计/数据库设计.md` |
| 配置项 | `开发文档/快速入门/配置说明.md` |

补充约定：

- 过程文档不能替代稳定真理源。
- 稳定文档默认原位修改，不在文末堆“增量需求 / 实现进展 / 日期补充”。
- 运行态文件、锁文件、生成结果不应进入主导航。

详见 `.cursor/rules/doc_sync.mdc`。
