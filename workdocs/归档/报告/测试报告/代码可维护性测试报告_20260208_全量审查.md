### F-P0-001 前端类型桥接失配（阻断 `tsc`）

- 位置：
  - `web/src/hooks/useSSEStream.ts:105`
  - `web/src/hooks/useSSEStream.ts:231`
  - `web/src/hooks/useSSEStream.ts:416`
  - `web/src/types/message.ts:72`
- 触发证据：`npx tsc --noEmit` 报 `TS2322`（`feedback_score` 不属于 `@langchain/langgraph-sdk` 的 `Message` 类型）。
- 维护性影响：消息对象存在“SDK 类型 + 本地扩展字段”双轨，后续任何字段演进都易再次触发类型断裂。
- 建议方案：引入统一转换层（`UnifiedMessage -> SDKMessage`），禁止在 `Message` 上直接挂扩展字段。
- 预估工作量：M

### F-P0-002 确认卡类型断言不安全（阻断 `tsc`）

- 位置：
  - `web/src/components/todo/ConfirmationCard.tsx:43`
  - `web/src/components/todo/ConfirmationCard.tsx:67`
  - `web/src/components/todo/ConfirmationCard.tsx:79`
- 触发证据：`npx tsc --noEmit` 报 `TS2352`、`TS2345`（`Record<string, unknown>` 与 `TodoItem` 互转不安全）。
- 维护性影响：卡片编辑流基于宽类型对象，字段约束缺失，后续表单扩展易引入运行时数据污染。
- 建议方案：将 `ConfirmationData.data` 改为判别联合（按 action 分型）或增加显式 runtime 校验后再收敛为 `TodoItem`。
- 预估工作量：S

### F-P0-003 数据访问白名单契约漂移（3 个失败用例）

- 位置：
  - `app/ai/semantic/data_access_control.py:22`
  - `app/ai/semantic/data_access_control.py:156`
  - `app/ai/semantic/data_access_control.py:209`
  - `app/tests/test_data_agent.py:135`
  - `tests/api/test_data_chat.py:211`
- 触发证据：`pytest` 失败显示 `t_orders` 被判定为“不在白名单”，且日志命中 `data_access.table_whitelist` 查询。
- 维护性影响：测试期望（`t_orders`/`t_products` 可访问）与运行时白名单来源（DB 配置 + 默认 f_mid_*）脱节，导致权限回归难以稳定验证。
- 建议方案：明确“测试白名单基线”机制（fixture 注入或独立 test config key），并把白名单来源策略文档化。
- 预估工作量：M

### F-P0-004 LLM 配置加载与测试桩不一致（1 个失败用例）

- 位置：
  - `app/services/llm_config_service.py:57`
  - `app/tests/test_llm_config.py:14`
- 触发证据：`LLMModelConfig` 在 `model_type` 字段抛 `ValidationError`；测试使用 `MagicMock` 且未显式提供字符串类型。
- 维护性影响：配置服务升级到严格类型后，旧测试夹具仍按弱类型写法，容易掩盖真实配置质量问题。
- 建议方案：统一测试工厂对象（强类型 fixture），避免 `MagicMock` 直接充当领域模型。
- 预估工作量：S

### F-P0-005 模型路由行为与测试 seam 漂移（3 个失败用例）
