## 一、多任务并行能力分析

### 1.1 会话隔离机制（已实现）

你的 cardrun 通过 **session_id** 实现了完整的会话隔离：

```
任务 A: .worktrees/2026-03-01_用户记忆/C01/session-1
任务 B: .worktrees/2026-02-28_聊天优化/C01/session-2
```

**关键特性**：
- 每个任务有独立的 `task_key`（来自 `_active_task.json`）
- 每个卡片有独立的 `card_id`
- 每个会话有独立的 `session_id`（自动生成或手动指定）
- 分支命名：`feature/<task_key>/<card_id>/<session_id>`
- worktree 路径：`.worktrees/<task_key>/<card_id>/<session_id>`

### 1.2 状态管理隔离

每个任务的状态文件独立存储：

```
.artifacts/states/task_splits/<task_split_dir>/<task_key>/sessions/<session_id>/wt-flow-state.json
workdocs/任务拆解/<task_split_dir>/contracts/_active_task.json
.artifacts/states/task_splits/<task_split_dir>/<task_key>/task-runner-state.json
```

**结论**：✅ **多个大任务可以同时执行，互不干扰**

## 二、冲突处理机制分析

### 2.1 Merge 策略（当前实现）

从 `scripts/coder4/wt-flow.sh` 第 881 行可见：

```bash
git merge --no-ff "${branch}" -m "merge: ${branch} into ${base_branch}"
```

**关键点**：
1. 使用 `--no-ff`（非快进合并），保留完整分支历史
2. **不使用 rebase**（除非 worktree 内手动 rebase）
3. 冲突时自动 abort：`git merge --abort`

### 2.2 冲突检测时机

**三个检测点**：

#### 检测点 1：merge 前的 rebase（可选）
```bash
# wt-flow.sh 第 860 行
if ! git -C "$wt_path" rebase "${base_branch}"; then
  git -C "$wt_path" rebase --abort
  exit 1
fi
```

#### 检测点 2：主仓库 dirty 检查
```bash
# wt-flow.sh 第 871-878 行
disallowed="$(_collect_disallowed_dirty_lines "$whitelist_csv")"
if [[ -n "$disallowed" ]]; then
  _die "主仓库存在非白名单变更，请先提交或清理后再执行 merge"
fi
```

#### 检测点 3：merge 冲突检测
```bash
# wt-flow.sh 第 881-886 行
if ! git merge --no-ff "${branch}"; then
  git merge --abort
  _err "请手动解决冲突后重新执行 merge"
  exit 1
fi
```

### 2.3 冲突场景分析

#### 场景 A：两个任务修改不同文件
```
任务 A: 修改 app/services/chat_service.py
任务 B: 修改 app/services/todo_service.py
```
**结果**：✅ **无冲突，自动合并成功**

#### 场景 B：两个任务修改同一文件不同区域
```
任务 A: 修改 app/services/chat_service.py 第 10-20 行
任务 B: 修改 app/services/chat_service.py 第 100-110 行
```
**结果**：✅ **Git 自动合并成功（大概率）**

#### 场景 C：两个任务修改同一文件相同区域
```
任务 A: 修改 app/services/chat_service.py 第 50-60 行
任务 B: 修改 app/services/chat_service.py 第 55-65 行（重叠）
```
**结果**：⚠️ **冲突，需要人工介入**

### 2.4 冲突处理流程

当任务 B 尝试 merge 时遇到冲突：

```
1. cardrun 执行 wt-flow.sh merge
2. Git 检测到冲突
3. wt-flow.sh 自动 abort merge
4. 输出错误：CARDRUN_MERGE_FAILED
5. 保留 worktree 和分支
6. 等待人工介入
```

**人工介入步骤**：
```bash
# 1. 进入 worktree
cd .worktrees/2026-02-28_聊天优化/C01/session-2

# 2. 手动 rebase 到最新 master
git fetch origin master
git rebase origin/master

# 3. 解决冲突
# 编辑冲突文件
git add <resolved-files>
git rebase --continue

# 4. 回到主仓库重新执行 merge
cd /Users/jijingkun/bojxAI/fastapi
bash scripts/coder4/wt-flow.sh merge
```

## 四、潜在风险与缓解措施

### 4.1 风险清单

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| **多任务修改同一文件** | 中 | 高 | 人工介入解决冲突 |
| **merge 顺序不当导致重复冲突** | 低 | 中 | 优先合并小改动任务 |
| **worktree 清理不及时占用磁盘** | 低 | 低 | 定期执行 `git worktree prune` |
| **session_id 冲突** | 极低 | 低 | 自动生成时间戳 + 随机后缀 |
| **主仓库 dirty 阻塞 merge** | 中 | 中 | 白名单机制已覆盖 docs/ 等目录 |

### 4.2 最佳实践建议

#### 建议 1：任务拆分时避免文件重叠
在 `/jjk-plan` 阶段就规划好：
```yaml
任务 A (用户记忆):
  - app/services/user_preference_memory_service.py
  - app/services/document_memory_service.py

任务 B (聊天优化):
  - app/services/chat_service.py
  - app/ai/workflow/chat_graph.py
```

#### 建议 2：优先合并小改动任务
```
任务 A: 3 个文件，50 行改动 → 优先合并
任务 B: 10 个文件，300 行改动 → 后合并
```

#### 建议 3：定期同步 master
```bash
# 在 worktree 内定期执行
git fetch origin master
git rebase origin/master
```

#### 建议 4：使用 `--state-dir` 隔离状态
```bash
# 任务 A
export WT_FLOW_SESSION_ID="session-a"
/jjk-cardrun 2026-03-01_用户记忆 loop

# 任务 B（另一个终端）
export WT_FLOW_SESSION_ID="session-b"
/jjk-cardrun 2026-02-28_聊天优化 loop
```

## 五、改进建议（可选）

### 5.1 自动冲突预检测

在 `wt-flow.sh merge` 前增加预检测：

```bash
# 检测是否有其他任务正在 merge
if [[ -f ".artifacts/states/task_splits/<task_split_dir>/<task_key>/global_merge_lock" ]]; then
  _warn "检测到其他任务正在 merge，建议等待完成后再执行"
  read -p "是否继续？(y/N) " confirm
  [[ "$confirm" != "y" ]] && exit 1
fi

# 创建全局 merge 锁
touch ".artifacts/states/task_splits/<task_split_dir>/<task_key>/global_merge_lock"
trap "rm -f .artifacts/states/task_splits/<task_split_dir>/<task_key>/global_merge_lock" EXIT
```

### 5.2 冲突文件预警

在 `cardrun` 选卡时检测潜在冲突：

```bash
# 读取当前任务的文件清单
current_files=$(jq -r '.cards[] | .file_scope[]' vk_cards.json)

# 检测其他活跃任务的文件清单
for other_task in $(ls workdocs/任务拆解/*/contracts/vk_cards.json); do
  other_files=$(jq -r '.cards[] | .file_scope[]' "$other_task")
  overlap=$(comm -12 <(echo "$current_files" | sort) <(echo "$other_files" | sort))
  if [[ -n "$overlap" ]]; then
    _warn "检测到与任务 $(basename $(dirname $other_task)) 存在文件重叠："
    echo "$overlap"
  fi
done
```

### 5.3 Merge 队列机制

引入全局 merge 队列，避免并发 merge：

```bash
# .artifacts/states/task_splits/<task_split_dir>/<task_key>/merge_queue.json
{
  "queue": [
    {"task_key": "2026-03-01_用户记忆", "card_id": "C01", "requested_at": "2026-03-05T10:00:00Z"},
    {"task_key": "2026-02-28_聊天优化", "card_id": "C02", "requested_at": "2026-03-05T10:05:00Z"}
  ],
  "current_merge": null
}
```
