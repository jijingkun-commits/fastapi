# 自动化大型任务开发全量打钩板清单（主机方案）

> 适用文档：`workdocs/归档/正文/设计/自动化大型任务开发设计方案.md`
> 适用范围：OpenClaw + Codex + 项目代码 + 本地依赖服务均在同一主机
> 使用原则：每完成一项即打钩；任一 `Go/No-Go` 安全门禁未通过时，禁止进入下一阶段

---

## 0. 使用说明

- 状态标记：`[ ]` 未完成，`[x]` 已完成，`[-]` 阻塞/待决
- 责任归属：每项必须填写 owner（人名或角色）
- 证据要求：每项必须有证据路径（日志、截图、命令输出、报告链接）
- 进入条件：Phase N 的 Exit Gate 全部通过后，才能进入 Phase N+1

### 0.1 全局进度总览

| 阶段 | 目标 | 进入条件 | 退出条件 | 当前状态 |
|------|------|---------|---------|---------|
| P0 | 触发器切换与安全基线 | 主机基线确认 | hooks/鉴权/互斥/watchdog 全绿 | [ ] |
| P1 | 核心本地化改造 | P0 Exit Gate 全绿 | kernel/scope/wt-flow/state 可闭环运行 | [ ] |
| P2 | 仓外规则清理与约束迁移 | P1 Exit Gate 全绿 | WORKFLOW/PROMPTS/SKILL 迁移完成 | [ ] |

## 6. 超大任务拆分执行板（多会话必用）

> 目标：把“一个大任务做不完”的风险降到可控范围。
> 建议采用“`vkplan` 拆分 -> 每会话 1-2 张卡片 -> 会话级验收”的节奏。

### 6.1 拆分层级

| 层级 | 粒度建议 | 产物 | 完成定义 |
|------|---------|------|---------|
| Epic | 1 个大目标（2-4 周） | 主设计文档 + 总清单 | 业务目标达成 + 验收通过 |
| Wave | 3-7 天可交付 | 波次计划（card_order） | 波次 Exit Gate 全绿 |
| Card | 1 个会话可完成（2-6 小时） | 代码/文档变更 + 证据 | done_gate 通过 |

### 6.2 会话工作包模板（每次开工必填）

- [ ] S-01 本会话目标卡片（最多 2 张）：__________
- [ ] S-02 前置依赖已满足（hard_depends_on 全 done）
- [ ] S-03 执行路径已确认（serial/parallel）
- [ ] S-04 验收标准已写清（tests/lint/evidence）
- [ ] S-05 会话输出物路径已确定（PR/日志/报告）
- [ ] S-06 结束时已更新 `task-runner-state.json` + ledger

### 6.3 会话节奏建议

| 节奏 | 内容 | 时间盒 |
|------|------|-------|
| 开场 10 分钟 | 读状态 + 锁定目标卡片 | 10m |
| 实施 90-180 分钟 | 只做目标卡片，不跨卡片扩散 | 1.5h-3h |
| 收口 20 分钟 | 验收、证据、状态更新、下一会话 handoff | 20m |
