# 文档治理 Vibe Kanban 计划（2026-02）

## 1. 目标

- 用看板方式推进 `docs/` 的结构治理，先统一导航与索引，再逐步做内容深改。
- 保持“文档可导航、可追踪、可验收”，让新成员可以按入口快速定位信息。
- 在不打乱当前研发节奏的前提下，分批完成文档质量提升。

## 2. 范围与边界

### 本轮纳入

- `docs/README.md`、`docs/SUMMARY.md` 等导航入口。
- `docs/开发文档/架构设计/`、`docs/产品文档/`、`docs/API文档/`、`docs/开发文档/快速入门/`。
- 与上述目录强关联的交叉引用、命名一致性和阅读路径。

### 本轮不纳入

- `workdocs/任务拆解/**`（并行拆解正文/契约/报告）；`docs/内部参考/任务拆解/` 仅保留说明页。
- `workdocs/归档/测试报告/` 下历史归档正文（仅维护索引，不重写归档内容）。

## 3. 看板规则

- 列状态：`Backlog -> Doing -> Review -> Gate -> Done`
- WIP 限制：`Doing` 同时最多 2 个 WS。
- DoR（进入 Doing）：范围清晰、Owner 明确、涉及目录明确。
- DoD（进入 Done）：结构更新完成，`python3 scripts/docs_guard.py --strict` 通过。

## 4. 工作包（WS）

| WS | 名称 | 目标 | 产出 |
|---|---|---|---|
| WS-00 | 文档基线盘点 | 建立问题清单与优先级 | 问题清单、执行顺序 |
| WS-01 | 信息架构治理 | 统一入口与目录导航 | 更新 `README/SUMMARY` |
| WS-02 | 架构文档对齐 | 统一术语与引用路径 | 架构文档交叉引用修订 |
| WS-03 | 产品/API 对齐 | 需求与接口映射一致 | 产品文档/API 文档修订 |
| WS-04 | 快速入门链路 | 新手路径闭环 | 快速入门文档修订 |
| WS-G1 | 一致性门禁 | 链接、命名、覆盖率校验 | 门禁记录 |
| WS-G2 | 终稿门禁 | 发布前总检查 | 版本化整理结果 |

## 5. 执行顺序

1. 先做结构治理：`WS-00 -> WS-01 -> WS-02`
2. 再做内容治理：`WS-03 -> WS-04`
3. 最后门禁收口：`WS-G1 -> WS-G2`

## 6. 验收标准

- 入口文档（`README/SUMMARY`）可覆盖本轮纳入目录。
- 跨文档链接无断链，且入口路径与实际目录一致。
- 同一概念在不同文档中的命名保持一致（模块名、接口名、角色名）。
- `python3 scripts/docs_guard.py --strict` 结果为通过。
