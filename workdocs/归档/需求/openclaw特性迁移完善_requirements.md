## 1. 背景与问题定义

当前仓库已具备部分 OpenClaw 迁移代码骨架（run 生命周期、工具治理、Skill 三层模型、用户记忆能力、复合任务队列汇总），但业务侧感知仍偏弱，主要问题为：

1. 能力默认关闭或未灰度启用（开关未统一落地）。
2. 新模型表存在但未完成数据迁移与主路径切流。
3. 部分能力停留在“代码可用”，未形成“可运营、可观测、可回滚”的上线闭环。

本轮需求目标：让“已实现能力”转化为“真实可用能力”。

---

## 2. 用户故事

### US-01（平台管理员）

作为平台管理员，我希望可以通过配置中心调整工具可用策略（按 agent/场景），以便在不改代码的情况下动态控制风险。

### US-02（多用户业务场景）

作为不同业务用户，我希望同一个 Skill 能有不同版本绑定（或默认版本），以便个性化能力不会互相污染。

### US-03（终端用户）

作为终端用户，我希望系统能记住我的长期偏好（语言、结构、回复风格）并在后续会话继续生效，以减少重复指令输入。

### US-04（复杂问答用户）

作为发起复合问题的用户，我希望系统可以按队列执行多个子任务并给出统一汇总回复，避免遗漏与碎片化回答。

### US-05（运维与发布负责人）

作为运维负责人，我希望上述能力具备明确观测指标与回滚开关，以便在灰度异常时快速止损。

---

## 3. 范围与边界

### 3.1 本轮范围（In Scope）

1. 开关与配置中心统一：run/tool/skill/memory 相关开关可通过 DB/ENV 生效。
2. Skill 三层治理上线：`t_agent_skills` 到 `definition/version/binding` 的迁移与切流。
3. 用户偏好记忆上线：recall + flush 可灰度启用，具备最小质量保护。
4. 复合任务队列汇总能力验收：确保“单次请求内多意图串行 + 汇总”稳定可用。
5. 自动化验收与发布门禁：形成可重复执行的验证脚本与回滚手册。

### 3.2 暂不纳入（Out of Scope）

1. OpenClaw 插件生态完整复刻（保留后续专题）。
2. 跨请求的“长期未回复消息池”智能聚合（可在后续专题补齐）。
3. 前端大规模交互重构（仅做最小适配与兼容）。

## 4. 功能验收标准

### AC-01 运行态与取消语义

1. `/api/v1/chat/runs/{run_id}/cancel` 返回幂等结果。
2. 取消后流式输出停止，终态收口一致（`stopped`/`done` 兼容语义可配置）。
3. 多用户取消互不影响。

### AC-02 工具可配置治理

1. 支持全局策略 + agent 策略合并，`deny` 优先于 `allow`。
2. 支持失效模式（`compat/allow/deny/minimal`）配置。
3. 策略变更无需发版即可生效。

### AC-03 Skill 多用户版本治理

1. Skill 版本可发布、回滚、查询。
2. 用户可绑定 Skill 版本并生效到检索链路。
3. 未绑定时走可解释的默认版本策略。
4. 完成老表到新三层的迁移与回退方案。

### AC-04 用户个性化永久记忆

1. `recall` 可按用户和作用域注入上下文。
2. `flush` 可在命中显式偏好时持久化到 `t_user_memory`。
3. 关闭 flush 时不写入；关闭 recall 时不注入。
4. 记忆读取和写入都具备用户隔离。

### AC-05 提问队列与合并回复

1. 单次复合请求内多个 handoff 可串行执行。
2. 队列清空后进入统一汇总节点返回聚合结果。
3. 汇总结果可覆盖 direct tool 结果 + 专家结果。

### AC-06 发布与运维闭环

1. 提供灰度开关矩阵与回滚剧本。
2. 关键路径具备自动化测试与证据输出。
3. 文档索引与配置说明同步更新。

---

## 5. 非功能需求

1. **一致性**：所有多用户能力必须以 `user_id` 为隔离主键。
2. **可观测性**：关键事件需记录 run_id/thread_id/user_id 维度日志。
3. **稳定性**：取消与队列执行不应导致线程阻塞或死循环。
4. **可回滚性**：每个功能模块必须具备独立开关回退路径。
5. **安全性**：工具治理默认应支持保守模式（`deny/minimal`）。

## 7. 发布完成定义（DoD）

满足以下条件方可判定本专题完成：

1. AC-01 ~ AC-06 全部通过自动化验证或有明确人工确认记录。
2. 新三层 Skill 表与记忆表存在有效业务数据（非空样本）。
3. 默认开关策略与灰度策略已落地并文档化。
4. 发布回滚演练至少执行一轮并有证据。
5. `/jjk-verify` 自动判定模式可输出 PASS/WARN/FAIL 结论。
