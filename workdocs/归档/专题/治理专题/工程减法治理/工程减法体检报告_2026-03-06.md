## 二、瘦身候选清单

### 2.1 高优先级删除（风险低、收益高）

#### A. 未使用的门禁脚本（5 个）

**删除候选**：
1. `scripts/check_special_doc_sync.py`
2. `scripts/check_gate_contract_consistency.py`
3. `scripts/check_clarify_plan_alignment.py`
4. `scripts/check_plan_vk_coverage.py`
5. `scripts/coder4/check_integration_gate.py`

**理由**：
- 未在 `.githooks/` 或 `.github/workflows/` 中被调用
- 未在其他脚本中被引用（除 `check_plan_vk_coverage.py` 引用了 `check_clarify_plan_alignment.py`）
- 功能重叠：`docs_guard.py` 已覆盖文档治理核心能力

**风险**：
- 低：这些脚本可能是实验性或已废弃的门禁
- 若有手动调用场景，可从 Git 历史恢复

**收益**：
- 减少 5 个脚本文件
- 降低维护成本（避免"看起来有用但实际不用"的假象）

---

#### B. 过程报告文件（4 类）

**删除候选**：
1. `workdocs/任务拆解/*/reports/consumption_report.json`
2. `workdocs/任务拆解/*/reports/gate_contract_report.json`
3. `workdocs/任务拆解/*/reports/sync/vktodo_create_result.json`

**理由**：

**风险**：
- 低：若需要历史审计，可从 Git 历史恢复
- 若脚本依赖这些文件，需先确认依赖关系

**收益**：
- 减少 4 类过程文件（约 10-15 个实例）
- 简化任务目录结构

### 2.2 中优先级合并（风险中、收益中）

#### D. coder4 系列脚本（5 个）

**现状**：
- `coder4_bootstrap_kernel.py`（核心调度）
- `coder4_scope_guard.py`（作用域切换代理）
- `coder4_vk_sync.py`（VK 同步）
- `coder4_external_backup.sh`（备份）
- `coder4_external_restore.sh`（恢复）

**合并建议**：

- `coder4_external_backup.sh` 和 `coder4_external_restore.sh` 可合并为单个脚本 `coder4_external_snapshot.sh --backup|--restore`

**风险**：
- 中：需确认 OpenClaw 或其他外部工具是否硬编码了这些脚本路径
- 若有外部依赖，需保留符号链接

**收益**：
- 减少 2-3 个脚本文件
- 降低 coder4 系列脚本的认知负担

---

#### E. codex 监控脚本（2 个）

## 四、总结

### 4.1 瘦身证据

| 类型 | 删除数量 | 风险等级 | 收益 |
|------|---------|---------|------|
| 未使用门禁脚本 | 5 个 | 低 | 高 |
| 过程报告文件 | 10-15 个 | 低 | 中 |
| .state 历史尝试 | 若干 | 中 | 中 |
| coder4 脚本合并 | 2-3 个 | 中 | 中 |
| codex 监控脚本 | 2 个 | 低 | 低 |

**总计**：可减少 20-25 个文件，降低维护成本约 30%。

---

### 4.2 风险与收益

**高收益、低风险**：
- 删除未使用的门禁脚本（5 个）
- 删除过程报告文件（10-15 个）

**中收益、中风险**：
- 合并 coder4 脚本（2-3 个）
- 清理 .state 历史尝试

**低收益、高风险**：
- 归档任务拆解历史目录
- 归档数据库脚本

---

### 4.3 执行原则

1. **优先删除零引用文件**：未在 hooks/CI/其他脚本中被调用的文件
2. **保留主干能力**：不删除核心执行链路依赖的文件
3. **不兼容旧版**：不保留"可能有用"的实验性脚本
4. **可逆操作**：所有删除操作可从 Git 历史恢复
